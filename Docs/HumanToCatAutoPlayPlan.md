## 実装済みの初版

以下は基礎営業（`basic`）の仕様。安定経営（`clear`）・積極経営（`fast`）との差は後述する。

```bash
python3 -m cat_cafe_sim.cafe_autoplay --days 60
python3 -m cat_cafe_sim.cafe_autoplay --days 10 --detailed --interval 1
python3 -m cat_cafe_sim.cafe_autoplay --resume reports/autoplay/20261001163000/cafe.json --days 10
```

通常は `reports/autoplay/開始日時/` に独立した人気モードのテストゲームを作り、`cafe.json`・`relationships.json`・日本語の `autoplay.log` を保存する。`--directory` で保存先を変えられる。`--resume` は指定したセーブと参照先の関係データを更新し、操作ログを同じフォルダへ追記する。旧セーブは既存の読み込み処理を使い、指定した検証対象がないゲームには目標を後付けせず進行不能として終了する。既定は人気で、集計のみのゲームは `--objective bond|patron` と対応する保存済み目標が必要。

| 項目 | 初版の方針 |
| --- | --- |
| 出勤 | 健康・在店で疲労とストレスがどちらも60未満の猫。該当しない猫を休ませ、出勤可能な猫がゼロなら休業 |
| 接客 | 既存の自動割り当て・自動交流を使用 |
| 人気目標 | 第1・第2段階の達成後は次段階へ進み、最終達成か期限切れで終了 |
| 成長 | 接客の得意分野を選ぶ。分類・個別行動の熟練は選択可能な候補の設定順 |
| 加入・譲渡・予約 | 受け入れ依頼、常連・派遣紹介、譲渡、特別予約を見送り |
| 店舗 | 設備トラブルは修理して席数を維持、支援依頼は見送り |
| 出発済み派遣 | 選択イベントは正の疲労・ストレス増加の合計が最小の候補。同点はID順。家出トラブルは帰還を待つ。帰還結果を確認 |
| その他 | 行方不明の猫の帰還、他の目標結果、進行中のプレイヤー交流を確認。信頼回復は見送り |
| 範囲 | 購入・新規派遣・新規加入・新たなプレイヤー交流は自動で開始しない |

60は自動プレイヤーの暫定判断基準で、ゲームの疲労・ストレス係数を変更するものではない。現在値で判断する簡単な方針のため、営業中に負担が上昇して病気や家出が起きることもある。必勝を要件にしない。

通常ログには操作と理由、日次の資金・人気・目標状態、猫ごとの疲労・ストレス・健康を表示する。`--detailed` では各刻みの操作記録とイベントをJSONで併記し、猫・客ID、交流コマンドと結果を調査できる。記録内の識別子はゲーム内部の英語IDを維持する。`--interval` は日次結果後の待機秒数（0〜60、既定0）。

終了理由は最終目標達成、期限切れ、ゲームオーバー、日数上限、操作上限、進行不能、中断を区別する。既定上限は実行開始から30営業日・10,000操作。休業も1日、再開時の上限はその実行から数える。通常営業は閉店時、休業は日次精算時に日数を数える。目標達成・期限切れ・ゲームオーバーは同時に日数上限へ到達しても優先する。

`AutoPlayer.step()` は通常操作を一つ呼び出し、`cancel()` の要求を次の操作前に確認する。CLIのCtrl+Cも同じ中断要求として扱い、処理中の操作を終えてから止める。各操作後と終了時に通常の営業セーブを保存する。進行不能は終了コード1、ほかのゲーム結果・上限・中断は0。ゲームの資金・人気・猫状態を書き換えて進めず、保存形式も変更しない。

## 基礎営業・安定経営・積極経営

ユーザーの希望に沿い、単純な基礎営業を比較の基準として残し、通常の操作で人気3段階のクリアを目指す方針を追加した。ゲーム開始時の人気・有力者・好感度などの目標モードとは別の、自動プレイヤーの判断方針である。

```bash
python3 -m cat_cafe_sim.cafe_autoplay --mode basic --days 60
python3 -m cat_cafe_sim.cafe_autoplay --mode clear --days 60
python3 -m cat_cafe_sim.cafe_autoplay --mode fast --days 60
python3 -m cat_cafe_sim.cafe_autoplay --resume reports/autoplay/20261001163000/cafe.json --mode clear --days 10
```

| モード | 方針 |
| --- | --- |
| `basic`：基礎営業（既定） | 初版の出勤・休養・回答を維持。投資や予約の受諾は行わず、失敗も比較結果として残す |
| `clear`：安定経営 | 全来店客の接客量から1匹への集中上限を見込み、予測疲労・ストレス60以下を優先。休養と予備資金を重視して期限内達成を目指す |
| `fast`：積極経営 | 予測疲労65・ストレス60以下まで出勤候補に含め、設備・予約を使って早期達成を目指す |

指定を省略すると既存と同じ `basic` で実行する。営業セーブには自動プレイ方針を追加保存せず、再開時も `clear` を使う場合は明示して指定する。意図的に方針を切り替えることもできる。同じ方針を指定した保存・再開では、判断とゲーム結果の一致を維持する。Pythonでは `AutoPlayer(session, mode='clear')` または `mode='fast'` で選ぶ。既存の `clear` 指定は安定経営として引き継ぐ。

### 安定経営・積極経営の判断

- 投資後に最低300、または1席増えた場合の運営費2日分のうち大きい方を残す。営業準備中に、通常の購入条件を満たすものだけ購入する。
- 優先順は休養スペース、解放済みの席増設、休養スペース強化、設備のない席へのおもちゃセット、防音改修。1操作ごとに条件を再確認する。席数は通常の解放条件に従い最大8席までで、最終達成時には停止するため、通常の通しプレイで増設するのは5席まで。
- 当日を含め目標期限まで残り1日のときは、席・休養設備への投資を見送る。即日の接客へ効果があるおもちゃセットは条件を満たせば購入する。既に設置された設備は入れ替えない。
- 今日の来店予定・交流時間・既存席数から負担と必要人数を見積もる。最低20行動を見込み、疲労・ストレスが小さい健康な在店猫から、安定経営は予測が両方60以下、積極経営は疲労65・ストレス60以下の候補を必要人数まで出勤させる。安定経営は全来店客の接客量と営業時間の小さい方（最低20行動）を1匹への集中上限とし、人数や席数で割らない。積極経営は分担の目安・前日の実績・好み一致の接客量の最大を使う従来の予測を維持する。安定経営は出勤候補または同時接客の見込みが既存席数以下なら増設を見送る。積極経営は来店人数と健康で担当可能な猫の総数が既存席数を上回れば、交代要員・待機客・増設で増える客を見込んで先行増設する。[集中負担の改善と比較](HumanToCatAutoPlaySafeLoad.md)を参照。
- 出勤候補がいない日は休業する。ただし受諾済み予約の来店日は休業できないため、健康な在店猫の中で現在の疲労とストレスの合計が最小の1匹を出勤させる。同点はID順。健康な猫がいない場合も営業を進め、接客できなかった結果を記録する。
- 特別予約は、健康または療養残り1日以内の長毛猫が在店し、翌日の来店が現在の段階の期限内なら受諾する。満足・予約成功を保証する判断ではなく、通常の割り当て・接客処理で結果を確認する。
- 成長、帰還、加入・譲渡・支援依頼の見送りなど、それ以外の回答は基礎営業と共通。新規派遣・加入・プレイヤー交流は自動で開始しない。

日本語ログに方針名、購入理由と予備資金、猫ごとの予測、予約回答理由を表示する。終了時には不足した人気も記録する。判断は保存済みの営業状態から決め、隠れた進行カウンターで購入や出勤を選ばない。通常の操作と共通の保存・再開・中断処理を使い、将来のGUIでも同じ方針を利用できる。

予測は目安であり、当日の担当回数や接客時間で実際の負担は変わる。初版の単純な方針は維持し、追加方針でも全条件での必勝を保証しない。ゲームの係数・資金・人気・猫の状態・期限を直接変更して達成させることはない。

## 目的と最初の対象案

個別機能のテストに加え、機能を組み合わせてゲームを最後まで進められるか確認する。通常の[自動接客](HumanToCatAutomaticCafe.md)や[100日評価](HumanToCatLongTermEvaluation.md)とは役割を分ける。

初回対象は人気３段階への挑戦。必勝を要件にせず、一定日数内で結果へ到達すること、進行不能を検出すること、終了理由を説明できることを優先する。

- 出勤・休養を選び、営業を進める。
- 目標結果・成長・帰還・イベントの回答待ちを処理する。
- 達成・期限切れ・ゲームオーバー・日数上限・進行不能を区別して報告する。
- 途中保存・再開を挟んでも、同じ条件で同じゲーム結果になるか確認する。

初版はゲームの既存の操作処理を通して進める。回答方針は上記の実装仕様を参照。以後、有力者・猫６匹の好感度・購入・派遣・猫の加入へ対象を広げる候補を保持する。

## 実行内容を見られるログ

ユーザーの「何をやっているか見たい」という希望に対し、日本語で操作と結果を実行中に表示する案を提示した。

| 表示・出力 | 提案内容 |
| --- | --- |
| 通常表示 | 日ごとの操作、選んだ理由、営業結果 |
| 詳細表示 | 接客ごとの猫・客・行動・結果も表示 |
| ログ保存 | 終了後に読み返せるファイルを出力 |
| 速度指定 | 待ち時間なし、または日ごとに間隔を空けて表示 |
| 最終報告 | 終了理由、実行日数、目標の達成状況をまとめる |

表示例（架空の値。判断基準や購入自動化の採用を意味しない）：

## GUI「10日間おまかせ」

通常ゲームの「営業」タブで、猫の詳細・相性ボタンと並ぶ「10日間おまかせ…」を開く。専用画面で導入済みの「人気」「好感度」「有力者」目標と「基礎営業」「安定経営」「積極経営」を選び、開始する。任せる操作はCLIの各方針と共通で、安定経営・積極経営では購入・予約も自動判断する。

保存済みの人気・好感度・有力者目標に挑戦中のゲームが対象。旧ゲームへ目標を後付けせず、人気集計のみのゲームでも好感度・有力者が挑戦中なら開始できる。目標未導入・結果確認待ち・ゲームオーバー・交流結果の保存待ちでは開始できない。対象別の表示と検証は[GUIのおまかせ](HumanToCatAutoPlayObjectiveGui.md)を参照。営業準備中、営業の途中、閉店後から実行できる。開始時に通常の営業タイマーを止め、専用画面を閉じるまで他画面への入力を止める。

- 実行開始から最大10営業日を進める。休業も1日、営業途中から開始した当日の閉店も1日として数える。
- 経過日数と日本語の操作・判断ログを表示し、20ミリ秒ごとに最大1操作を実行する。操作の間にGUIの入力や描画を処理する。
- 「判断一覧」「操作ログ」のタブを切り替えられる。判断一覧は日・対象・判断・理由・実行結果を表示し、行を選ぶと下欄で理由の全文を読める。
- 出勤・休養・療養・不在を猫ごとに表示する。基礎営業は現在の疲労・ストレスと60未満の条件、クリア方針は出勤時の予測値と60以下の条件を使う。予約当日の休業回避で配置する場合は、その理由も表示する。
- 購入は費用・購入後の資金・運営予備資金、特別予約は長毛猫の在店／回復予定と来店日が期限内かを表示する。対象は実際に選んだ購入や予約回答で、全商品の比較や購入しない全理由を列挙する画面ではない。
- 操作に成功した判断は「実行済み」、失敗は理由付きの「失敗」とする。中止前に実行した判断は残す。同日・同対象の出勤を再判断した場合は最新の行へ更新し、同名の猫は個体IDで区別する。新たなおまかせ開始時に判断一覧をリセットする。
- 判断一覧は今回のおまかせの表示用で、閉じた後の再開やセーブには保存しない。従来の日本語ログとその書き出しは維持する。
- 各人気段階の達成、期限切れ、ゲームオーバー、進行不能、操作上限でも停止する。併用中の有力者・好感度目標の結果が出た場合も停止する。
- 中止・画面を閉じる・通常操作へ戻る場合は、操作の境界で止め、予約済みのGUIタイマーを取り消す。セーブの切り替えや親画面の終了でも停止する。
- 終了後に資金・人気、猫ごとの疲労・ストレス・健康・活動状態の開始前後を表示する。
- 保存先があるゲームは終了・中止時に現在の営業セーブへ保存する。未設定ならメイン画面の「保存…」を利用する。保存失敗は終了画面に表示し、ゲーム状態を保持して通常画面で保存し直せるようにする。
- 「操作ログを保存…」で日本語テキストを書き出せる。実行中に押すと先に中止する。営業セーブや関係データと同じファイルへは書き込めない。操作ログは画面内に保持するため、必要なら閉じる前に書き出す。
- 「通常操作へ戻る」で専用画面を閉じる。目標達成時は通常の目標結果画面で次段階・継続営業を選ぶ。10日上限や中止の後は、手動操作や新たな10日間のおまかせを選べる。

CLIの既定は3段階を通して進む動作を維持する。共通処理の `AutoPlayer(..., stop_on_goal=True, on_decision=...)` をGUIで指定し、各段階の結果を未確認のまま保存して停止する。再開するゲームでも方針は専用画面で選び、営業セーブの形式は変更しない。

GUI追加後、追加7件を含む全1,085件成功（310.294秒）。

GUIテストでは10日上限と画面の応答、方針選択、各段階・期限切れ・ゲームオーバーでの停止、購入後の中止と保存再開、タイマー取り消し、通常操作への復帰、保存失敗とログ書き出しを確認する。共通処理では3段階の各結果を未確認のまま止め、ユーザーの通常操作で次へ進めることを確認する。

## バランス調整の希望

人気3段階のクリアが短いという相談を受け、必要人気と各段階の期限を一緒に増やす評価条件を追加した。[人気目標・期限の比較](HumanToCatPopularityDurationEvaluation.md)に結果と通常設定への反映方針を整理した。評価CLIの `--goal-preset medium` / `long` と `--days 60` で再実行できる。ユーザーは長めの案（人気250→450→650、期限20→20→25日、上限650）の採用を決定した。通常の新規ゲームへの反映まで実装した。新しい他モードからの途中挑戦も長めの設定で、旧上限300のゲームは従来の挑戦を開始する。開始済みの目標は保存済み設定を維持する。

調整前の旧設定・シード0で、基礎営業・クリア方針・増設なし・休養設備なし・接客設備なしを比較した。[予備評価](HumanToCatAutoPlayBalanceEvaluation.md)に達成日、収支、負担、設備の効果、期限の余裕と調整候補を記録し、[日次結果と集計JSON](Results/AutoPlayBalanceEvaluation.json)を保存した。旧条件の再実行は `python3 -m cat_cafe_sim.autoplay_evaluation --goal-preset legacy --customer-preset legacy --days 30`。通常クリア16日に対して増設なし14日だったため、まず出勤猫数に応じた増設判断の比較を優先する案。1シードの予備評価。後続の相談で人気目標・期限の長めの案を採用決定したが、料金変更や出勤猫数に応じた増設判断は未採用。

ユーザーは、自動プレイの導入に加えてバランス調整も行ってほしいと希望している。従来の「細かな調整は後回し」という方針に対し、自動プレイで進行を確認しながら調整する後続作業として記録する。初版の実装ではゲームの数値変更は行わない。

自動プレイの実行結果から、資金・人気の推移、目標達成までの日数、疲労・ストレスと休養頻度、設備や派遣・加入の費用と報酬を確認する案。複数の開始条件・プレイ方針で比較し、難しすぎる箇所や選択肢の偏りを見つけ、変更前後の結果を説明できる形で調整する。

目標の日数制限の意味も検討対象とする。ただし、望ましい難易度・達成日数・対象モード・調整順序は未確定であり、一つの自動プレイ方針が必勝になることを基準にしない。席数は当面８席まで、旧セーブの固定設定を維持する既存方針も尊重する。

## 検証方針の案

同じ開始条件での再現、回答待ちの解消、正常終了と進行不能の区別、途中保存・再開による結果一致を確認する。GUI追加時は画面の応答、途中中止、10日未満での結果停止、終了後の通常操作を確認する。

操作は既存の保存・二重処理防止・旧セーブ互換を維持する。実装とテストの完了後に関連仕様・引き継ぎを更新し、コミットは別途依頼を受けて行う。

## 評価CLIのシード指定

評価CLIに `--seed`（既定0）と `--seeds`（重複なしの0以上の整数列）を追加した。単一評価は従来の詳細JSON、複数評価はシード別集計と達成率を保存する。[10シード比較と集計仕様](HumanToCatAutoPlaySeedEvaluation.md)を参照。ゲームの数値と方針は変更しない。

店舗イベントへの回答は未保存結果の保存・プレイヤー交流の終了の後、依頼・紹介等より先に行う。同時に回答待ちとなる場合の進行不能を修正した。[修正内容と再評価](HumanToCatAutoPlaySeedEvaluation.md#回答順の修正内容)を参照。
