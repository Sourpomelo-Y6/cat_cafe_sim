# テスト用自動プレイと将来のGUI連携

更新日：2026-10-01 / 状態：会話の整理・未実装。実装の依頼と詳細仕様の確定は別途行う。

## 今回の相談

ユーザーは、通常進行の機能が揃ってきたため、テスト用自動プレイの導入を検討したいと提案した。また、GUIを使わなくても何をしているか見たいこと、将来的にはGUI上で10日分程度をまとめて自動プレイしたいことを希望した。

以下はその希望に対して提示した設計案であり、各判断基準・操作範囲・数値をすべて採用済みとするものではない。今回の依頼は資料化であり、自動プレイの実装は行わない。

直前に提案した「派遣先比較へ帰還後の疲労・ストレス見込みを追加」は未着手。自動プレイを次の作業候補にするため、この表示改善はいったん置く案を提示した。

## 目的と最初の対象案

個別機能のテストに加え、機能を組み合わせてゲームを最後まで進められるか確認する。通常の[自動接客](HumanToCatAutomaticCafe.md)や[100日評価](HumanToCatLongTermEvaluation.md)とは役割を分ける。

初回対象は人気３段階への挑戦を推奨。必勝を要件にせず、一定日数内で結果へ到達すること、進行不能を検出すること、終了理由を説明できることを優先する。

- 出勤・休養を選び、営業を進める。
- 目標結果・成長・帰還・イベントの回答待ちを処理する。
- 達成・期限切れ・ゲームオーバー・日数上限・進行不能を区別して報告する。
- 途中保存・再開を挟んでも、同じ条件で同じゲーム結果になるか確認する。

ゲームの既存の操作処理を通して進め、テストのために資金・人気・猫の状態を直接書き換える方式は避ける案。必要な回答の選び方は実装前に定める。以後、有力者・猫６匹の好感度・購入・派遣・猫の加入へ対象を広げる候補を保持する。

## 実行内容を見られるログ

ユーザーの「何をやっているか見たい」という希望に対し、日本語で操作と結果を実行中に表示する案を提示した。

| 表示・出力 | 提案内容 |
| --- | --- |
| 通常表示 | 日ごとの操作、選んだ理由、営業結果 |
| 詳細表示 | 接客ごとの猫・客・行動・結果も表示 |
| ログ保存 | 終了後に読み返せるファイルを出力 |
| 速度指定 | 待ち時間なし、または日ごとに間隔を空けて表示 |
| 最終報告 | 終了理由、実行日数、目標の達成状況をまとめる |

表示例（架空の値。判断基準や購入自動化の採用を意味しない）：

```text
【12日目・準備】
出勤：ミケ、ソラ、シオン
休養：タマ（疲労72のため）
休養スペースを購入：資金1,800 → 1,400

【12日目・営業終了】
売上：320／費用：90／残金：1,630
人気：145 → 153
目標：第２段階に挑戦中
```

購入の行は将来の操作範囲を含む表示例。初回から購入することは決めていない。単なる結果一覧だけでなく、自動プレイの判断理由を追えることを重視する。

## 将来のGUI「10日間おまかせ」案

ユーザーは、後からGUIで10日分程度をまとめて自動プレイする機能を希望した。まず共通の自動プレイ処理を作り、テスト用実行とGUIの両方で判断・イベント回答を利用する構成を提案した。

- 開始前に任せる操作範囲を選ぶ。出勤・休養だけか、将来は購入・派遣・加入も含めるかを区別する。
- 実行中に「何日目／10日」と操作ログを表示する。
- 中止時は処理中の操作を終えたところで安全に止める。
- 目標達成・期限切れ・ゲームオーバーでは、10日未満でも停止する。
- 終了後に資金・人気・猫の状態の変化をまとめて表示する。

画面を固めず、処理を小さく区切って進める案。初回の操作範囲は出勤・休養・営業と進行に必要な回答を推奨し、購入などを任せる範囲は後から広げる。GUIは将来の機能で、テスト用自動プレイと同時に実装することは決めていない。

テスト用の人気３段階通しプレイは第１・第２段階の結果を処理して次へ進む一方、GUI案は目標達成で停止する。停止条件を用途に合わせて選べる構成を検討する。

## 実装前に詰める事項

- 出勤・休養の判断基準、担当可能な猫が不足した日の扱い。
- 成長・目標継続・帰還・予約・譲渡・家出などの回答方針と、初回に扱う範囲。
- 実行日数上限、１日・１操作の数え方、進行不能の判定。
- ログファイルの形式・保存先・詳細度・待ち時間の指定方法。
- 保存・再開を含む比較で、ゲーム結果と表示ログのどこまで一致を求めるか。
- GUIの開始・中止可能な状態、停止後の保存と通常操作への戻り方。

購入・派遣・加入を初回から自動化することや、ストレスによる休養判断の具体値は未確定。以前保留した休養提案機能を、この相談だけで実装済み・採用済みと扱わない。

## バランス調整の希望

ユーザーは、自動プレイの導入に加えてバランス調整も行ってほしいと希望している。従来の「細かな調整は後回し」という方針に対し、自動プレイで進行を確認しながら調整する後続作業として記録する。今回は希望の資料化であり、数値変更は行わない。

自動プレイの実行結果から、資金・人気の推移、目標達成までの日数、疲労・ストレスと休養頻度、設備や派遣・加入の費用と報酬を確認する案。複数の開始条件・プレイ方針で比較し、難しすぎる箇所や選択肢の偏りを見つけ、変更前後の結果を説明できる形で調整する。

目標の日数制限の意味も検討対象とする。ただし、望ましい難易度・達成日数・対象モード・調整順序は未確定であり、一つの自動プレイ方針が必勝になることを基準にしない。席数は当面８席まで、旧セーブの固定設定を維持する既存方針も尊重する。

## 検証方針の案

同じ開始条件での再現、回答待ちの解消、正常終了と進行不能の区別、途中保存・再開による結果一致を確認する。GUI追加時は画面の応答、途中中止、10日未満での結果停止、終了後の通常操作を確認する。

操作は既存の保存・二重処理防止・旧セーブ互換を維持する。実装とテストの完了後に関連仕様・引き継ぎを更新し、コミットは別途依頼を受けて行う。
