# Phase 2 猫方策の離散化・Q学習

更新日：2026-09-05

本書はQ学習の初期実装の記録。続く[学習済み猫の営業接続](Phase2_LearnedCafePolicy.md)で
営業CLIから保存済みモデルを選べるようになった。

今回、離散化、疎なQ表による学習、推論モデルの保存・再読み込み、
固定方策との比較コマンドを追加した。接客のゲームルールと料金・報酬係数は変更していない。
シミュレーターは0.2.0のまま、環境契約は`cat-interaction-v2`、
状態変換は`cat-state-v1`、学習方策は`tabular-q-v1`として識別する。

## 実行手順

既存の`requirements-env.txt`以外に依存の追加はない。プロジェクトのルートから実行する。

```bash
# 学習前に状態数とメモリの概算を確認
venv/bin/python -m cat_cafe_sim.training inspect

# 既定設定で3,000接客を学習し、保存・再読み込み・調整用条件の比較を実行
venv/bin/python -m cat_cafe_sim.training train

# 保存済みモデルを固定して、別の評価用条件で比較
venv/bin/python -m cat_cafe_sim.training evaluate \
  --model models/cat_q.json --split test --output reports/cat_q.test.json

# 別の学習seed。既存の成果物を残すため出力先も指定
venv/bin/python -m cat_cafe_sim.training train --seed 43 \
  --model models/cat_q_seed43.json --report-prefix reports/cat_q_seed43

# 全テスト
venv/bin/python -m unittest discover -s tests -v
```

`train`の`--episodes`で接客数を上書きできる。`--config`はゲーム設定、
`--rewards`は猫報酬、`--training`は学習・離散化・実験条件のJSONを指定する。
大きな接客数を指定して評価seed範囲と重なる場合は、学習設定のseed範囲も変更する。

生成物：

| ファイル | 内容 |
|---|---|
| models/cat_q.json | Q表、状態変換、ゲーム・報酬・学習設定、seed、各種バージョン |
| reports/cat_q.training.csv | 接客ごとの報酬8項目、探索率、満足・気力消費・売上、行動数、既知状態数 |
| reports/cat_q.validation.json | 保存前後の一致確認と、調整用条件の方策比較 |
| reports/cat_q.test.json | evaluateで明示的に実行した評価用条件の比較 |

比較JSONには、モデルのSHA-256、実行時のPython/Gymnasium/NumPy版、
客条件・seedごとの行動列と元のゲーム指標も含める。
モデル・生成レポートはGit対象外。モデルは設定・出力先を指定して再生成できる。

## 状態数と情報の取捨選択

Q表のキーは次の5整数のタプル。

| 要素 | 既定の区間数 | 内容 |
|---|---:|---|
| 満足 | 6 | 0、(0,.25]、(.25,.5]、(.5,.75]、(.75,1)、1 |
| 体力 | 6 | 最大値で正規化して同じ区間に分類 |
| 気力 | 6 | 最大値で正規化して同じ区間に分類 |
| 交流履歴 | 11 | 未交流1種＋2交流種類×連続回数1〜5 |
| 残り時間 | 6 | 0、1、2〜5、6〜10、11〜20、21以上 |

最大状態数は6×6×6×11×6＝14,256、7行動のQ値は99,792個。
全要素をfloat64の密な配列にした場合は798,336バイト（約0.76MiB）。
実装は訪れた状態だけを更新・保存する辞書であり、Pythonオブジェクトの管理費用はこの概算に含まない。
既定の`max_states=100000`を超える離散化は、学習を開始する前に拒否する。

履歴の上限は設定から自動計算する。既定では同種5回で飽き倍率が下限に達し、
切り替え資格も成立済みなので、5回以降をまとめられる。
切り替え条件を9回に変えれば上限も9へ増える。営業時間を超える履歴は不要なのでその範囲に制限する。
休むことや速度変更によって交流履歴が失われることはない。

直前速度は現在の接客ルールの次状態計算に影響しないためQキーには含めない。
初来店・初対面フラグも今回の環境では固定なので省略する。
非公開の好み、環境seed、将来イベント、診断infoは入力しない。

**正確なMarkov状態ではない。** 資源・残り時間を区間化するため、
体力消費や気力回復の閾値の前後が同じ状態へ集約される場合がある。
0と最大値、残り1tickは独立させたが、全閾値の正確な保持はしていない。
また好みは非公開で、過去の反応の推定記憶もまだ持たない。
速度や初対面に依存するルールを今後追加する場合は、状態仕様の見直しと版更新が必要。

## 学習と終了の扱い

`config/cat_training.json`の既定値は学習率0.15、割引率0.95、接客数3,000。
探索率は1.0から0.05まで、接客数の約80%で線形に下げ、以後0.05を維持する。
学習中の同率最大Q値はseed付き乱数で選択し、序盤の行動IDへの偏りを抑える。

```text
Q(s,a) ← Q(s,a) + 学習率 × (報酬 + 割引率 × 将来価値 - Q(s,a))
将来価値 = 0                                      （terminated）
         = 次状態の有効行動だけから取った最大Q値    （それ以外）
```

探索時・貪欲選択時・次状態の最大値計算のすべてに行動マスクを適用する。
成功・不満・閉店の最終報酬も必ず更新に含め、外部打ち切りでは将来価値を消さない。
環境に`bootstrap_action_mask`を追加した。外部打ち切り後の`action_mask`は従来どおり0だが、
学習用マスクは打ち切り直前の非終端状態で有効だった行動を示す。
今回の標準学習コマンドは途中打ち切りを使わず、接客の本来の終了まで学習する。

[Gymnasiumの行動マスク説明](https://gymnasium.farama.org/tutorials/training_agents/action_masking_taxi/)と
[時間制限の説明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)を参照した。

## 保存と推論

モデルはJSONで保存する。読み込み時には方策・環境・状態変換の版、
ゲーム設定と状態変換の整合、状態番号の範囲、Q値7個の有限性、行の重複を検証する。
未対応版や不正なQ表は拒否する。

推論は探索なし、同率の場合は最小の有効行動IDを選ぶ。
未知状態では全Q値0として同じ規則を使い、比較結果に未知状態率を記録する。
推論によってQ表、更新回数、探索乱数を変えない。

```python
from cat_cafe_sim.training.model import CatModel
from cat_cafe_sim.envs import CatInteractionEnv

model = CatModel.load("models/cat_q.json")
env = CatInteractionEnv(model.config, model.rewards)
observation, info = env.reset(seed=30000, options={"preferences": (0.9, 0.9)})
while True:
    state = model.agent.encoder.encode(observation)
    action = model.agent.act(state, info["action_mask"])
    observation, reward, terminated, truncated, info = env.step(action)
    if terminated or truncated:
        break
env.close()
```

保存物は推論用モデルであり、学習途中から完全に同じ経路で再開するチェックポイントではない。
学習乱数の途中状態・シナリオ生成乱数は保存せず、再学習は同じ設定とseedで最初から行う。
営業CLIで学習済み猫を直接選ぶアダプターはまだ追加していない。

## 条件分離と比較結果

学習・調整・評価の好みと環境seedを別々に設定し、重複を検証する。
学習は5種類の好みから独立したシナリオ乱数で選び、非公開の値は方策へ渡さない。
`train`の終了後は調整用条件だけを使用し、評価用条件は`evaluate --split test`で明示して実行する。
今回、モデル選別やハイパーパラメーターの自動調整は行っていない。

比較対象はRandom、既存の交互固定方策、学習済み方策。全方策に同じ客条件・初期設定を使う。
Q方策は学習も探索も停止する。Randomの行動乱数は環境乱数と分離する。

学習seed 42・43・44で各3,000接客を学習し、すべてで保存前後の調整用行動列・結果が一致した。
評価条件は好み(1.75,.25)、(.25,1.75)、(.9,.9)×5seedの各15接客。

| 方策 | 学習seed | 記録状態数 | 満足退店率 | 平均報酬 | 平均接客tick | 平均気力消費 | 平均売上 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Random | — | — | 100% | 117.31 | 8.27 | 0 | 182.67 |
| 固定 | — | — | 100% | 118.67 | 6.33 | 0 | 163.33 |
| Q学習 | 42 | 224 | 100% | 123.07 | 4.67 | 0 | 180.00 |
| Q学習 | 43 | 221 | 100% | 119.37 | 5.67 | 0 | 156.67 |
| Q学習 | 44 | 229 | 100% | 117.60 | 6.00 | 0 | 160.00 |

seed 42の学習中平均報酬は最初100接客117.04、最後100接客121.96。
CSVには全接客の系列を保存した。ただし探索率と客条件が変わるため、
この値だけを学習済み方策の性能改善と解釈しない。

**固定方策への安定した優位性は未確認。** seed 44は平均報酬で固定方策を下回り、
今回の易しい条件ではRandomも含め満足率が飽和している。
環境の反応は決定的なので、固定・学習済み方策の5seed反復は同じ好みでは同じ結果になる。
15接客を15個の独立した客条件とみなしてはいけない。独立した好みは3種類。
未知状態率はいずれのQモデルも今回の評価で0だったが、状態集約後の一致であって客条件既知を意味しない。

売上には時間課金と特別成功ボーナスが含まれ、接客時間短縮だけで必ず増えるものではない。
以前確認した「休み続けると時間課金が増える」問題はゲームルール側の課題として残す。

## テストと次の作業

既存36件に21件を追加し、57件すべて成功。
離散化の境界、履歴上限、状態数制限、マスク付きQ更新、終了と打ち切り、
乱数の再現、評価時の無更新、保存前後の行動一致、破損モデル拒否、条件分離を検証した。

次の候補は難しい客条件・低リソース条件への評価拡張、反応から好みを推定する状態の検討、
学習済み猫の営業CLIへの接続。未使用条件を増やしてから設定・離散化の比較を行う。
グラフ化、学習途中の厳密な再開、GUI、複数日経営、店長学習は今回の実装に含めていない。
