# 派遣先からの猫紹介

更新日：2026-10-01 / 状態：商店街の紹介と撮影スタジオの初回限定紹介を実装済み。

## 発生と回答

商店街の交流会は既存の解放条件と2日間の期間を維持する。新しい派遣の出発時に紹介候補を固定し、帰還報酬の受け取り後、営業準備中に紹介する。閉店時に報酬を受け取った場合は翌日の準備へ送る。派遣中の選択イベントとは独立している。

案内欄の「確認する」、または派遣・帰還画面の「猫の紹介…」から、名前、個性、特徴、特性の効果、好み、飼育枠、費用、支払い後の資金を確認できる。迎える／見送るを回答するまで営業を進められない。未処理の帰還や目標確認は先に済ませる。通常の受け入れ依頼や複数の紹介が重なっても、各回答を順に処理できる。

## 初回の候補と費用

| 項目 | 内容 |
| --- | --- |
| 名前 | セナ（派遣紹介N） |
| 個性 | 遊び好きで繊細な猫 |
| 特徴 | 白毛・長毛 |
| 特性 | 接客好き |
| 受け入れ費用 | 200 |

対象の派遣ごとに別の猫IDを予約する。初回は同じ組み合わせを使い、名前の紹介番号で区別する。候補の種類・価格・頻度の調整は後続。設定元は `config/cafe_dispatch_introduction.json`。

迎えるには飼育枠の空きと、支払い後に残る資金が必要。加入時は休養予定で、関係・健康・成長など通常加入と共通の初期状態を持つ。費用は日次収支の受け入れ費用へ加算し、派遣報酬とは別に記録する。見送りは資金・人気・帰還報酬を変えず、満員や資金不足でも選べる。回答済みの選択は変更できない。

回答待ちでも「飼育スペースを拡張…」から購入できる。拡張後は空き枠・残り資金を再判定し、迎える／見送るを選ぶ。拡張だけでは営業を再開しない。帰還・目標結果など他の確認待ちは先に解決する。[飼育スペース](HumanToCatHousing.md)を参照。

## 履歴と保存互換

帰還結果、猫の基本情報・できごと履歴に紹介と加入元を表示する。派遣画面から回答後の紹介記録も確認できる。関係データの登録成功後に加入を確定し、保存失敗時は状態を保持して再試行できる。

新規開始時の紹介ルールと出発時の候補を保存し、設定ファイルの変更で保存済み候補を変えない。紹介待ち・回答・加入後の状態を保存復元と詳細リプレイに対応させた。紹介設定を持たない旧セーブへは自動追加せず、旧派遣にも候補を後付けしない。

検証：旧セーブ、準備中・閉店時の帰還、加入・見送り、満員・資金不足、複数紹介と通常依頼、関係登録失敗と再試行、保存復元・詳細リプレイ、候補固定、GUI表示を確認。全606件のGUIを含むテストが成功。

## 撮影スタジオの初回限定紹介

新規ゲームの[撮影スタジオ](HumanToCatPhotoDispatch.md)への最初の対象派遣に、別候補の紹介を追加します。最初の出発時に候補と猫IDを予約し、帰還報酬の受領後の準備中に提示します。閉店時に報酬を受け取った場合は翌準備へ送ります。派遣中の追加撮影への回答とは独立し、どちらを選んでも紹介は届きます。

| 項目 | 内容 |
| --- | --- |
| 名前 | ルカ（派遣紹介N） |
| 個性 | 穏やかな甘えん坊 |
| 特徴 | 白毛・短毛 |
| 特性 | 接客好き |
| 受け入れ費用 | 250 |

1ゲームにつき1回だけです。最初の紹介候補を予約した時点から、同時派遣・後続の派遣に重ねて候補を付けません。迎える／見送るのどちらでも再紹介しません。商店街の紹介頻度・候補は維持し、紹介番号と猫IDは既存の全派遣紹介で共用して衝突を避けます。

名前・個性・特徴・費用と空き枠を既存の紹介画面に表示し、迎える／見送るを選びます。迎えるには飼育枠の空きと支払い後の残金が必要です。満員・資金不足でも見送れます。回答画面から飼育スペースを拡張し、条件を再判定できます。加入時は健康・体力全回復・休養予定で、費用250を受け入れ費用へ一度だけ記録します。派遣報酬は変更しません。

[候補設定](../config/cafe_photo_introduction.json)を新規開始時に既存の紹介設定の任意項目 `dispatch_introduction.photo_studio` へ固定し、出発時候補は既存の派遣記録 `introduction` に保存します。設定変更後も保存済みの候補・費用・状態を維持します。専用の紹介済み台帳は追加せず、派遣記録から初回予約を判定します。

旧の商店街だけの紹介設定、紹介設定なし、紹介候補のない出発済み記録はそのまま読み込み、撮影スタジオの紹介を後付けしません。保存形式を維持し、紹介待ち・回答後・加入後の保存再開と詳細リプレイに対応します。関係登録・保存失敗後の再試行で費用や猫登録を二重処理しません。復元時には派遣先と候補、ID、提示日・回答日、撮影スタジオの紹介が複数ないことを検証します。

[追加テスト](../tests/test_cafe_photo_introduction.py)で全モード・1席／複数席、受け入れと見送り、準備中／閉店時の帰還、満員・資金不足・回答待ち拡張、同時派遣・初回限定・商店街との独立、旧設定と旧出発記録、候補固定、登録・保存失敗の再試行、保存復元と詳細リプレイ、不正記録を確認します。GUIでは案内・紹介内容・閉じる・拡張後の再判定・回答と最小サイズを確認します。
