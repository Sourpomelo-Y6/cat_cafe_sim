# 常連のお客さんからの猫紹介

更新日：2026-09-30 / 状態：実装済み

新規ゲームの全モードで、最初に常連になったお客さんから一度だけ猫を紹介される。通常接客を店の発展だけでなく加入の機会へつなげる。旧セーブ・旧ログには自動追加しない。

## 発生と選択

常連度の既存ルールを使い、満足した接客1件につき＋25、100に達すると常連になる。接客評価未導入の設定では、既存の親しみ増加による常連判定を使う。休業・未接客・普通・不満では増えない。紹介のために別の常連度や毎行動の履歴を追加しない。

最も早い常連化日の翌日の営業準備で紹介する。同日に複数のお客さんが常連になった場合は顧客ID順で紹介者を固定し、保存再開・詳細リプレイでも同じ結果にする。常連になった接客の途中や閉店結果には割り込まない。ゲームオーバーでは新たに提示しない。

「準備・お店」→「常連からの猫紹介…」で候補と条件、回答後の記録を確認できる。届いたときは営業画面の案内の「確認する」からも開ける。閲覧・閉じる・確認のキャンセルだけでは状態を変更しない。

| 項目 | 初回の仕様 |
| --- | --- |
| 候補 | 固定1匹のマロン（`regular-rescue-1`） |
| 個性 | 穏やかな甘えん坊 |
| 特徴・特性 | 茶トラ・短毛、のんびり屋（`relaxed`） |
| 初期費用 | 200 |
| 選択 | 迎える／見送る。確認ダイアログ付き |
| 発生回数 | ゲーム全体で一度。見送り後も再発生しない |

迎えるには飼育枠に空きがあり、支払後も資金が残る必要がある。加入時は健康・体力全回復、疲労・ストレス・プレイヤー好感度0で休養予定。出勤への自動追加はしない。加入後は出勤・休養・派遣・成長・プレイヤー交流・好感度目標に使える。猫の詳細に加入経路・紹介者・加入日、できごとに加入を表示する。

見送りでは費用・人気・常連度・関係データを変更しない。同じ回答の再操作は二重登録・二重請求をせず、回答済みの選択は変更できない。

## 確認待ちと他の出来事

紹介への回答待ちは営業開始・休業・配置変更・プレイヤー交流などを止める。満員や資金不足でも見送れる。紹介への回答は準備中に行い、未保存の接客成果・進行中の交流・帰還・店舗イベント・成長・目標結果は先に確認する。

保護猫の固定日依頼や派遣先からの猫紹介と同日に届いた場合は、それぞれをどちらの順でも回答できる。先に迎えた猫が飼育枠を使うため、もう一方を迎える前には再判定する。両方の自動受け入れは行わない。

目標結果は先に確認できる。人気の次段階への挑戦は、常連紹介にも回答してから選ぶ。資金・人気のゲームオーバーを優先し、終了後は迎える・見送るの操作を認めない。

## 保存・会計・互換性

`config/cafe_regular_introduction.json` の候補を新規開始時に固定し、任意項目 `regular_introduction` に設定、未発生／回答待ち／受け入れ／見送り、紹介者ID・常連化日・提示日・回答日を保存する。紹介者は保存済みの常連度と接客成果から照合する。

候補のIDは開始時から予約し、定期受け入れ・ショップ・依頼・派遣紹介との重複を拒否する。加入時には既存の関係ファイルへ名前・個性を登録し、登録済みIDの衝突と改変を拒否する。書込失敗では費用・猫・回答を変更せず、再試行できる。

費用は既存の `recruitment_expenses` に合算し、加入した日の収支へ計上する。チェックポイントは常連化日と提示・回答、所属猫・特徴・特性、関係プロフィール、会計を検証する。詳細リプレイには初期化と回答操作を記録し、提示は翌日移行から再現する。

旧セーブの読込や人気挑戦の追加では導入しない。旧の常連度100・追加来店も変更しない。常連度を持たない旧形式の初期条件では、紹介も導入しない。
