# 店舗ランダムイベント

更新日：2026-09-29 / 状態：選択式の設備トラブルまで実装済み

## 基本ルール

新規ゲームでは各日の準備開始時にイベントの有無と種類を確定する。発生率は暫定40%。日付とゲームのseedから決定し、保存再開や画面の開き直しでは再抽選しない。内容は営業前のログに公開する。

| イベント | 当日の効果 |
| --- | --- |
| 地域のお祭り | tick 3に通常客を1人追加 |
| 雨の日 | その日の通常客を予定末尾から1人減らす |
| 支援物資 | ストレスを20減らすケア用品を1個入手 |
| 設備トラブル | 営業前に修理・応急処置・休業から対応を選ぶ |
| 保護団体からの支援依頼 | 営業前に支援額を選び、資金と人気へ反映する |

イベントなしの日も結果として固定する。祭りと雨は休業時には来客を発生させない。支援物資は準備中から所持品画面で使える。

## 設備トラブルへの対応

設備トラブルが発生した日は、回答するまで営業開始、通常の休業、出勤変更などを止める。

| 選択 | 当日の結果 |
| --- | --- |
| 修理する | 店舗運営費に50を追加し、全席を使用できる |
| 応急処置する | 追加費用なし。当日の最終1席を使用停止する |
| 休業する | 来客なしで在店猫を休ませ、そのまま翌日の準備へ進む |

選択内容は営業ログとセーブへ保存する。保存再開で再回答や費用の二重適用は発生しない。応急処置による席の停止は当日だけで、翌日には全席を使用できる。

## 保護団体からの支援依頼

| 選択 | 支出 | 閉店時の人気 |
| --- | ---: | ---: |
| 支援する | 100 | ＋5 |
| 少額支援する | 50 | ＋2 |
| 見送る | 0 | 変化なし |

回答時に資金を支払い、資金が0以下になれば既存の資金ゲームオーバーを適用する。人気はその日の閉店処理で接客による増加とまとめて確定し、人気目標の進捗へ反映する。支出は日次収支の店舗イベント支出に含める。

## 表示・保存

- 営業ログと閉店結果に当日のイベント名を表示する。
- 複数日の比較画面に店舗イベント列を追加する。
- 修理費用は運営費と日次収支へ含める。
- 保護団体への支援額は独立した店舗イベント支出として日次収支へ含める。
- 支援物資は派遣報酬のケア用品と同じ所持品・使用履歴へ統合する。
- 営業セーブには固定したルール、各日の抽選値、種類を保存する。
- 読み込み時に日付、seed、抽選値、種類、来店予定、費用、所持品との整合性を検証する。

旧セーブにはイベントを後付けしない。選択式になる前の店舗イベントを持つセーブでは、設備トラブルを従来どおり自動課金として扱う。発生率や効果量の調整、ほかの選択式イベントは全体の流れが固まった後に扱う。
