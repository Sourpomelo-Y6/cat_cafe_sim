# 関係一覧からの再会

更新日：2026-09-13 / 版4の画面機能

保存済みの猫とお客の組み合わせを一覧にし、IDを入力し直さず再会できるようにした。

## 操作

1. `python3 -m cat_cafe_sim.human_cat_gui`で画面を開く。
2. 必要に応じて「保存データを選ぶ…」で次回の保存先を選択する。
3. 「関係一覧から再会…」を押す。
4. 猫ID・お客ID・親しみ・関係の目安・直近の保存済み交流の増減を確認する。
5. 行を選んで「選んだ相手と再会」を押す。

一覧は開いた時点の「次回の保存先」を対象とし、画面上部にそのパスを表示する。
猫ID、お客IDの順に並べ、縦スクロールで閲覧できる。「一覧を更新」で同じ保存先を読み直す。
別の保存先を閲覧する場合は一覧を閉じ、メイン画面で次回の保存先を選び直して開く。
保存済みの関係がなければ案内を表示し、未選択時は再会ボタンを無効にする。

再会には登録済みの猫の個性を使う。未登録の場合はメイン画面の次の個性を使い、開始体力は指定値を使う。
[猫の名前・個性の登録](HumanToCatCatProfiles.md)を参照。猫の名前もIDと並べて表示する。
進行中・未保存の交流がある場合は従来の保存・破棄・キャンセル確認を行う。
キャンセルや開始失敗では現在の交流を維持し、次のIDと保存先の選択も元へ戻す。
現在の結果を保存してから再会するときは、保存後の親しみを読み直して引き継ぐ。

## データの扱い

`RelationshipStore.list_relationships()`が、関係と直近の保存済み結果を読み取り専用で返す。
一覧を開く・更新するだけではファイルを作成・更新せず、未保存の交流結果も表示しない。
読み込み失敗時はエラーを表示し、古い一覧からの再会を防ぐため選択を解除する。

保存形式1・2の既存データを使用する。適用済み交流は保存時に末尾へ追加されるため、その順序で組み合わせごとの最後の結果を取得する。
過去の交流の保存再試行では追加順が変わらず、直近結果も変わらない。
「直近」はアプリでの保存順を意味し、日時順ではない。外部ツールでJSONの適用済み交流のキー順を並べ替える運用は想定しない。
対応する結果がない関係は、直近欄を「記録なし」と表示する。

親しみの段階は[再会時の表現](HumanToCatRelationshipPresentation.md)と共通。
交流ルール、行動効果、資金、ログ形式に変更はない。

## 確認

通常テスト178件と実際のTkウィジェットを使う画面専用8件、計186件が成功。
空の保存先、複数の組み合わせ、直近結果、過去結果の再試行、読み取り時の非更新、破損ファイルを確認した。
画面では一覧表示、選択、キャンセル、親しみの引き継ぎ、次回保存先の使用、読み込み失敗後の再読み込みを確認した。
目視によるレイアウト評価は含まない。
