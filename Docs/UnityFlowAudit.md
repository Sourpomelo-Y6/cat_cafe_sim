# Unity：既存フローの通し確認と移植漏れ監査

確認日：2026-10-10。最新のUnityプロジェクトのAssets・Packages・ProjectSettingsを検証専用コピーへ反映し、独立した一時ゲーム・別ポート・保存ディレクトリで確認しました。通常のUnityシーンとユーザーのPythonセーブを試遊用に変更しません。

## 確認範囲

- 人気・有力者・好感度・自由の4目標について、標準開始条件で各3日間。タイトルから新規開始、出勤/休養の変更、営業開始、自動進行、閉店の振り返り、保存、タイトルから再開、翌日へ進む流れ。
- 日次収支の整合と、保存前後の日付・資金・全猫の状態・目標進捗の一致。再開後の自動進行は手動で開始。
- 別の検証条件で受け入れ依頼・5匹の成長選択・店舗イベントを同時に待つ状態。回答待ちの保存/復元、イベント一覧から各画面を開く、選択できる順に連続回答、送信中の重複操作防止、営業再開と閉店保存/タイトル再開。
- 新しいHTTP照合テストで同じPython Session操作を参照として実行。4目標×3日、営業途中と閉店の保存/再開、イベント重複時の拒否・保存・連続回答を比較。
- 既存の全Unity連携テストで、派遣・施設・用品・顧客・目標・旧セーブ・未保存結果・ログ等を回帰確認。

長期目標達成までの全組み合わせやゲームバランスの試遊とは区別します。重複イベントの発生率・成長閾値・依頼日は検証用ゲームだけで変更します。

## 修正した表示の問題

JSONの `null` がUnityで空のイベントクラスとして読み込まれる場合、自由営業のイベント一覧に存在しない予約を「0日目 / 引き受け済み」と表示していました。状態読込時に、状態名のない予約・常連紹介・店先の猫・受け入れ依頼を未設定として扱うよう修正しました。実際に設定されている `untriggered`・`waiting`・`accepted`・`declined` は保持します。イベントの解放条件・回答・報酬は変更していません。

## 修正した検証上の問題

`PythonMultiDayVerification` が、タイトルの状態取得後すぐに「再開」を呼び、保存一覧の取得前に次の検証段階へ進んでいました。状態と保存一覧は別リクエストのため、実際の再開ボタンが有効になるまで待つよう修正しました。ゲーム本体の保存形式や進行ルールは変更していません。

検証サーバーのポートは `CAT_CAFE_FLOW_TEST_PORT` で指定できます。未指定時は従来の8191番を使い、通常プレイ用8190番は禁止します。検証段階をログへ出力し、イベント確認は実UIのイベント一覧と回答ボタンを使用します。`Run` と `RunEvents` は検証コピーのシーンにポートを書き込むため、通常のUnityプロジェクトでは実行しません。

## 残る既存機能

| 項目 | Python側の根拠 | Unityに残る作業 |
| --- | --- | --- |
| 出勤・休養の予測 | `cafe_shift_forecast.shift_forecast` と `CafeShiftWindow` | 前日の接客量に基づく閉店疲労・発症確率・ストレスの予測と説明。記録のない初日は補わない |
| 疲労順の休養案 | `CafeShiftWindow.propose_rest`、`fatigue_rest_schedule` | 健康な在店猫を疲労順に最大2匹休養する案を作成し、手動変更後に確定する操作 |

| 譲渡済み猫の表示切替 | `cafe_cat_visibility.adoption_toggle` | 一覧を「在籍のみ/譲渡済みも表示」に切替。現在のUnity一覧は譲渡済みも表示する |
