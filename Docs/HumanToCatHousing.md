# 飼育スペースと受け入れ上限

更新日：2026-09-30 / 状態：6→9→12匹の2段階拡張と紹介回答待ちの拡張を実装済み

## 初回仕様

新規ゲームでは、接客席数とは別に在籍猫の上限を6匹とする。「準備・お店」→「飼育スペースを拡張する…」から費用500で一度だけ購入し、上限を9匹へ増やせる。購入済みなら追加費用1,000でさらに12匹へ一度拡張できる。人気や目標達成による解放条件は設けない。好感度目標の6匹へは購入なしでも到達できる。

在籍数には在店・派遣中・家出中・療養中の猫を含め、譲渡済みは除く。譲渡済みの猫の記録は削除せず、空いた枠へ別の猫を迎えられる。外部へ引き渡す子猫は従来どおり費用だけで扱い、在籍猫にも飼育枠にも含めない。席数・派遣の参加条件は変更しない。

初期上限6、拡張幅3、購入費500、維持費20は設定ファイル `config/cafe_housing.json` の暫定値。追加拡張の設定は `config/cafe_housing_upgrade.json`（拡張幅3、費用1,000、維持費合計40）。細かなバランス調整、3段階目以降、売却・返金は後続とする。

## 受け入れと満員時の操作

通常候補画面と受け入れ依頼画面に、在籍数・上限・空き枠を表示する。満員では迎える操作を無効にし、処理側でも拒否する。拒否時は猫の登録、在籍状態、資金、回答記録を変えない。候補の閲覧・定期追加は維持する。

固定日の受け入れ依頼・派遣先からの紹介・常連からの紹介への回答待ちでも、各画面の「飼育スペースを拡張…」から購入できる。拡張後は紹介画面の空き枠・所持金・受け入れ可否を再判定する。拡張費と受け入れ費は別々に必要で、拡張後に受け入れ費を払って資金が残らない場合は迎えられない。拡張だけでは回答済みにならず、迎える／見送るまで営業進行・他の準備変更は停止する。複数の紹介が同時に届いても、各段階の拡張は一度ずつ。見送りによる費用・人気の変化はない。

拡張は営業準備中だけ購入でき、支払い後に資金が残る必要がある。上記3種類の紹介以外の未解決イベント、目標結果、成長選択、プレイヤー交流中、接客結果の保存待ち、ゲームオーバー時は購入できない。確認のキャンセルでは何も変更しない。

## 会計・保存・詳細リプレイ

購入当日から上限を増やし、日次の店舗運営費に初回拡張後は維持費20、追加拡張後は合計40を追加する。営業日・休業日の両方に一度だけ精算し、資金0以下なら既存のゲームオーバーを適用する。購入費は日次収支と比較画面の「飼育スペース費用」、維持費は「運営費」に含める。営業ログにも購入結果と運営費の飼育分を表示する。

営業セーブ形式2・チェックポイント1に任意項目 `housing` を追加し、新規開始時のルールと購入日・金額を固定保存する。設定ファイルの後日の変更で上限・費用を変えない。復元時には購入記録、在籍数と上限、日次費用、運営費の内訳、資金の整合性を確認する。詳細リプレイ4では初期化・購入と日次精算を再現する。保存失敗時も購入結果を保持し、再保存で二重請求しない。

旧セーブには上限・購入・維持費を後付けせず、上限なしの従来ルールと既存の加入経路を維持する。既に6匹以上いる猫を削除・強制譲渡しない。旧セーブの画面は「上限なし（従来ルール）」と表示し、拡張購入は不要と案内する。

## 2段階目の追加拡張

初回拡張済みの営業準備中に「2段階目へ拡張」を選び、費用1,000で上限9→12匹へ拡張できる。人気条件は設けず、支払い後に資金が残る場合のみ購入できる。上限・維持費は当日から有効。維持費は飼育分の合計40で、初回の20へさらに40を足さない。猫・接客席数・出勤予定・進行中の派遣は変更しない。

固定日の依頼・派遣先の紹介・常連紹介への回答待ちも購入可能。9匹で満員なら追加拡張後に受け入れ可否を再判定する。拡張だけでは回答待ちを解除せず、複数の紹介がある場合もそれぞれ回答する。他の未解決イベント・目標結果・成長選択・プレイヤー交流・未保存結果・営業中・閉店後・ゲームオーバーでは追加拡張できない。確認取消は費用と状態を変更しない。

初回の `housing.rules` と `housing.purchase` を維持し、任意の `housing.upgrade` に追加拡張の日付と固定設定を保存する。[追加設定](../config/cafe_housing_upgrade.json)の `capacity_bonus` は初回上限からの加算幅、`daily_cost` は拡張後の飼育維持費合計。設定を変更した旧ゲームでも元の上限・初回費用・維持費を保ち、追加維持費が現在より大きい設定を使用する。読み込み・再生では現行設定を読み直さない。

購入費は支払日の「飼育スペース費用」へ加算し、同日なら初回500＋追加1,000＝1,500。維持費は営業日・休業日とも精算する。復元時は過去の各日の上限・購入費・維持費を当時の段階で検証し、過去の日次結果を変更しない。詳細リプレイには `upgrade_housing` 操作と設定を記録する。セーブ・チェックポイント・リプレイのバージョンは維持する。

飼育ルールを持つ旧セーブも明示的な追加拡張から対応し、未操作なら追加記録を後付けしない。飼育ルールのない上限なしの旧セーブは維持し、拡張不要と表示する。保存失敗後も購入結果を保持し、再保存・二重操作で上限や費用を二重適用しない。

[追加テスト](../tests/test_cafe_housing_upgrade.py)で1席・2席、同日／別日の費用と過去の段階、営業・休業精算、9匹満員からの受け入れと12匹上限、3種類の紹介・同時紹介、操作制限・資金境界、保存済み設定・旧セーブ・保存失敗再試行・詳細再生、不正記録を確認する。GUIでは確認取消、追加拡張と履歴、運営費と購入費、営業ログ、最小サイズ、紹介画面の導線・受け入れ再判定・操作復帰を確認する。
