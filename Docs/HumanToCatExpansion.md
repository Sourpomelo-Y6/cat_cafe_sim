# 店の段階的な増設：2席から5席へ

更新日：2026-09-29 / 状態：5席と段階別の追加来客まで実装済み

営業で得た資金を店の拡張に使い、接客・派遣・休養の割り振りにつなげる。
2席から3席、人気目標の第1段階達成後に4席、第2段階達成後に5席へ増設できる。費用は3席が暫定500、4席と5席が暫定1,000。細かな調整は後回しにする。

## 操作・条件

1. 営業準備中に営業画面の「準備・お店」→「席を増やす…」を開く。
2. 現在の席数、次の席数、費用、支払い後の所持金、来客数の変化を確認する。
3. 増設ボタンを押して確認すると、席は即座に追加される。

- 支払い後に資金が残る場合のみ購入可能。資金500以下では購入できない。
- 各段階を一度だけ購入でき、重複購入・6席以上への増設・売却・返金はない。
- 確認のキャンセルや画面の閲覧では、席数・資金を変更しない。
- 準備中だけ購入可能。営業中・閉店後・交流結果の保存待ち・プレイヤー交流中・帰還等のイベント待ち・目標結果待ち・ゲームオーバー中は不可。
- 3席は従来どおり人気目標がない旧セーブでも購入できる。4席は人気目標第1段階、5席は段階式人気目標第2段階を期限内に達成した営業が対象。旧単段階目標では、その人気目標の達成を第1段階相当として扱い、5席は解放しない。
- 新規ゲームは引き続き2席から開始する。既存の2席セーブも準備中に購入可能。
- 1席の検証用営業からの増設は初回範囲に含めない。

設定は [cafe_expansion.json](../config/cafe_expansion.json)。増設画面には段階ごとの購入日と実際の支払額を表示する。
新規ゲームでは、増設前後の[日次運営費](HumanToCatOperatingCosts.md)も表示する。増設した席は購入当日の運営費から席数に含める。

## 接客・派遣・一日の流れ

増設した `seat-3`・`seat-4`・`seat-5` は購入日の営業から使用できる。手動配置の席選択にも、自動配置の空席候補にも加える。
全席の交流は同じ営業時計で進み、同じ猫・お客さんを複数の席へ割り当てることはできない。
接客コマンドは引き続き自動で選ぶ。

3席への増設では来客数・出勤予定・猫の人数を変更しない。4席への増設では購入翌日から通常客1人をtick 0に、5席への増設では別の通常客1人をtick 6に追加する。購入日には追加しない。休業日は来店せず、通常客と高難度客の既存予定は変更しない。
追加客は固定IDで来店し、通常客と同じく好み・来店回数・猫別の親しみを持つ。「お客さんの名簿・来店予定…」では購入日から翌日の予定を確認できる。
派遣は現在の店内席数を基準に判定するため、5席では担当可能な在店猫を5匹残す。初期6匹なら1匹まで派遣できる。
既に派遣中の猫はそのまま派遣を続け、増設によって取り消し・即時帰還しない。
休養・休業・翌日進行でも購入済みの席数を維持する。

## 会計と保存

増設費用は購入日に一度だけ差し引き、接客売上とは別の支出として扱う。
「営業結果を比較…」に、その日の席数と増設費用を表示する。過去の2席営業の日は書き換えない。
休業日に購入した場合も同日の支出。以後の日には費用0を表示する。

営業セーブの任意項目 `expansion` に段階ごとの席数・購入日・支払額を保存する。従来の3席セーブにある単一の購入記録も読み込む。
読み込み時は席数・増設記録・人気目標の解放条件・日次履歴・追加客・所持金の整合性を照合する。3席以上なのに増設記録がないデータは拒否する。
購入直後・4席／5席の交流途中・閉店後・翌日で保存再開でき、再開だけで再課金・追加来店を繰り返さない。
保存失敗時も起動中の増設結果を保持し、保存を再試行する。購入をやり直さない。

詳細リプレイの `expand_seats` 操作を各段階で記録する。チェックポイント起点では購入済み状態から再開する。
旧1席・2席・3席・4席のセーブとログは従来どおり読み込む。5席への対応を旧版プログラムに戻して読むことは保証しない。
