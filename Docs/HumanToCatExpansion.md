# 店の段階的な増設：2席から7席へ

更新日：2026-09-30 / 状態：7席と段階別の追加来客まで実装済み

営業で得た資金を店の拡張に使い、接客・派遣・休養の割り振りにつなげる。
2席から3席、人気目標の第1段階達成後に4席、第2段階達成後に5席、最終段階達成後の継続営業で6席、その購入後に7席へ増設できる。費用は3席が暫定500、4席と5席が暫定1,000、6席が暫定1,500、7席が暫定2,000。細かな調整は後回しにする。

## 操作・条件

1. 営業準備中に営業画面の「準備・お店」→「席を増やす…」を開く。
2. 現在の席数、次の席数、費用、支払い後の所持金、来客数の変化を確認する。
3. 増設ボタンを押して確認すると、席は即座に追加される。

- 支払い後に資金が残る場合のみ購入可能。3席は資金500以下、4・5席は1,000以下、6席は1,500以下、7席は2,000以下では購入できない。
- 各段階を一度だけ購入でき、重複購入・8席以上への増設・売却・返金はない。
- 確認のキャンセルや画面の閲覧では、席数・資金を変更しない。
- 準備中だけ購入可能。営業中・閉店後・交流結果の保存待ち・プレイヤー交流中・帰還等のイベント待ち・目標結果待ち・ゲームオーバー中は不可。
- 3席は従来どおり人気目標がない旧セーブでも購入できる。4席は人気目標第1段階、5席は段階式人気目標第2段階を期限内に達成した営業が対象。旧単段階目標では、その人気目標の達成を第1段階相当として扱い、5・6・7席は解放しない。6・7席は人気3段階の最終段階を期限内に達成し、結果確認後の継続営業の準備中に購入する。7席は6席の購入後が対象。
- 新規ゲームは引き続き2席から開始する。既存の2席セーブも準備中に購入可能。
- 1席の検証用営業からの増設は初回範囲に含めない。

設定は [cafe_expansion.json](../config/cafe_expansion.json)。増設画面には段階ごとの購入日と実際の支払額を表示する。
新規ゲームでは、増設前後の[日次運営費](HumanToCatOperatingCosts.md)も表示する。増設した席は購入当日の運営費から席数に含める。

## 接客・派遣・一日の流れ

増設した `seat-3`・`seat-4`・`seat-5`・`seat-6`・`seat-7` は購入日の営業から使用できる。手動配置の席選択にも、自動配置の空席候補にも加える。
全席の交流は同じ営業時計で進み、同じ猫・お客さんを複数の席へ割り当てることはできない。
接客コマンドは引き続き自動で選ぶ。

3席への増設では来客数・出勤予定・猫の人数を変更しない。4席への増設では購入翌日から通常客1人をtick 0に、5席への増設では別の通常客1人をtick 6に、6席への増設ではさらに別の通常客1人をtick 12に、7席への増設では別の通常客1人をtick 18に追加する。購入日には追加しない。休業日は来店せず、通常客と高難度客の既存予定は変更しない。
追加客は固定IDで来店し、通常客と同じく好み・来店回数・猫別の親しみを持つ。「お客さんの名簿・来店予定…」では購入日から翌日の予定を確認できる。
派遣は現在の店内席数を基準に判定するため、7席では担当可能な在店猫を7匹残す。7匹在籍では派遣に出せず、8匹以上なら残す猫の条件を満たす範囲で派遣できる。猫の人数・出勤予定は増設で自動変更しない。必要なら飼育枠を拡張し、加入経路から猫を迎える。
既に派遣中の猫はそのまま派遣を続け、増設によって取り消し・即時帰還しない。
休養・休業・翌日進行でも購入済みの席数を維持する。

## 会計と保存

増設費用は購入日に一度だけ差し引き、接客売上とは別の支出として扱う。
「営業結果を比較…」に、その日の席数と増設費用を表示する。過去の2席営業の日は書き換えない。
休業日に購入した場合も同日の支出。以後の日には費用0を表示する。

営業セーブの任意項目 `expansion` に段階ごとの席数・購入日・支払額を保存する。従来の3席セーブにある単一の購入記録も読み込む。
読み込み時は席数・増設記録・人気目標の解放条件・日次履歴・追加客・所持金の整合性を照合する。3席以上なのに増設記録がないデータは拒否する。
購入直後・4席／5席／6席／7席の交流途中・閉店後・翌日で保存再開でき、再開だけで再課金・追加来店を繰り返さない。
保存失敗時も起動中の増設結果を保持し、保存を再試行する。購入をやり直さない。

詳細リプレイの `expand_seats` 操作を各段階で記録する。チェックポイント起点では購入済み状態から再開する。
旧1席・2席・3席・4席・5席・6席のセーブとログは従来どおり読み込む。7席への対応を旧版プログラムに戻して読むことは保証しない。

## 6席目と旧ゲームの扱い

購入費用1,500は一度だけ支出し、既存の運営費では当日から1席分の10が増える。追加客 `expanded-guest-3` は購入当日は来店せず、翌日以降の営業のtick 12に来店する。休業日は来店しない。好み・猫別の親しみ・満足評価・常連・不満などは通常客と同じ仕組みを使い、名簿には購入直後から翌日の予定を表示する。

旧セーブの席数や来店を自動変更しない。旧ゲームでも人気3段階の最終達成と準備条件を満たす場合は、新しい購入操作から6席へ増設できる。旧の1〜5席、単一購入記録、3〜5席までの費用設定、詳細リプレイは維持する。最終達成前の購入記録、8席以上、不整合な席数・費用・履歴は読み込み時に拒否する。

[6席テスト](../tests/test_cafe_six_seat_expansion.py)で、解放前後、継続確認、費用境界、追加来店、設備と自動配置、6席同時交流・共有時計、飼育枠と派遣、運営費・日次支出、保存失敗再試行、保存再開・詳細リプレイ、旧ルールと不正データ、購入確認と最小サイズのGUIを確認する。

6席目追加の検証結果：追加9件成功、仮想ディスプレイでGUIを含む全712件成功。

## 7席目と旧ゲームの扱い

人気3段階の最終達成・結果確認後、6席へ増設済みの準備中に費用2,000で購入する。購入時に一度だけ支出し、運営費は既存ルールどおり当日から1席分の10が増える。休養・待合・飼育設備なしなら日次運営費は100から110。猫の人数や出勤予定は自動変更しない。

追加の通常客 `expanded-guest-4` は購入当日は来店せず、翌日以降の営業でtick 18に来店する。休業日は来店せず、既存客の予定を変えない。名簿には購入直後から翌日の予定と固定の好みを表示し、来店後は通常客と同じ親しみ・満足評価・常連度・不満の仕組みを使う。

7席目は購入当日から手動・自動配置に使え、接客設備も設置できる。7席同時交流は共有時計で進み、同じ猫の二重配置を拒否する。新しい派遣は担当可能な在店猫を7匹残す条件で判定し、増設前から派遣中の猫を取り消し・即時帰還させない。

旧セーブの席数や来客は読み込みだけでは変更しない。最終達成と準備条件を満たす旧6席ゲームも、明示的な新しい購入から7席へ増設できる。7席費用を含まない旧設定、単一の3席購入記録、既存の段階別購入、詳細リプレイを引き続き読み込む。7席購入時は同じ `expansion.purchases` 形式に追加し、席数・購入順・日付・最終達成・過去の日次費用・資金の整合性を確認する。

[7席テスト](../tests/test_cafe_seven_seat_expansion.py)で、同日／別日の増設費用、当日利用・翌日追加客・休業、設備・手動と自動配置、7席同時交流・共有時計、飼育枠・8匹目と派遣・派遣中の増設、費用境界、保存失敗再試行、旧6席設定からの購入、保存と詳細リプレイ、不正記録、購入確認・取消・最小サイズのGUIを確認する。

7席目追加の検証結果：追加10件成功、仮想ディスプレイでGUIを含む全830件成功（164.491秒）。ローカルリンク856件と差分チェックも成功。
