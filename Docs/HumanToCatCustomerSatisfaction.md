# 1回ごとの接客評価

更新日：2026-09-28 / 状態：初回実装済み

## 目的と区分

通常営業の接客を「満足・普通・不満」の3段階で評価し、担当猫や席設備を選んだ結果を料金・人気・常連度・累積不満へつなぐ。
これは1回来店したときの評価であり、店への長期的な[常連度](HumanToCatCustomerLoyalty.md)、[累積不満](HumanToCatCustomerDiscontent.md)、猫から客への親しみ、ゲーム全体の人気とは別に扱う。

新規ゲームの全目標モードで導入する。旧セーブには後付けせず、従来の親しみ増加による常連度・人気・不満回復判定を維持する。

## 初回の評価

接客終了時に次の条件を1点ずつ加える。

- 猫からお客さんへの親しみが増えた
- 「心をつかむ」または「心を開く」が1回以上発動した
- 終了時の関心とテンションが両方50以上だった
- お客さんの好みと担当猫の特徴が一致した
- 高難度客の公開条件を達成した場合はさらに＋1、未達なら－1
- 猫が体力切れで終了した場合は－2

合計2点以上を「満足」、0点以下を「不満」、その間を「普通」とする。評価の境界と関心・テンションの基準は `config/cafe_customer_satisfaction.json` に保存する。
同じ結果に複数の理由がある場合も評価は1件であり、名簿と営業ログには判定理由をまとめて表示する。

## 経営結果への接続

| 評価 | 初回の効果 |
| --- | --- |
| 満足 | 接客料金へ＋20。既存の人気獲得1件として数え、常連度＋25、累積不満－25の対象にする |
| 普通 | 評価による追加料金・常連度・累積不満の増減なし |
| 不満 | 累積不満＋25。追加料金・常連度・人気獲得なし |

高難度客は公開条件の追加料金と満足ボーナスを別々に加算する。高難度条件未達による累積不満＋10と接客評価「不満」の＋25が同時に成立した場合は合計＋35とする。
待機列満員・待機時間切れは接客評価を作らず、従来どおり累積不満だけを増やす。休業・未来店・未接客の退店にも接客評価を作らない。

人気は既存の閉店時処理を使う。満足件数に人気目標の `gain_per_success` を掛け、上限・段階目標・ゲームオーバーとの順序は変更しない。

## 画面、保存、互換

営業ログに評価・点数・理由・満足ボーナスを表示する。閉店結果と複数日の比較には、満足・普通・不満の件数を表示する。
顧客名簿でお客さんを選ぶと、その客の直近の接客評価と理由を確認できる。評価の閲覧では状態を変更しない。

設定は新規開始時に営業セーブへ固定し、再開時に設定ファイルを読み直さない。個別の評価履歴を重複保存せず、既存の接客成果から再計算する。日次件数、追加料金、常連度、累積不満、人気との整合性を再開時に照合する。
旧セーブ、旧リプレイ、満足度を明示導入しない試験用営業は従来の判定と表示を維持する。

## 確認

3段階の境界、好み一致・不一致、特別行動、関心・テンション、体力切れ、高難度条件の達成・未達、追加料金、常連度、累積不満、人気、日次比較、途中保存、翌日保存、詳細リプレイ、破損データ、旧セーブ互換を確認する。
