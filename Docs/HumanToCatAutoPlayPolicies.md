# 自動プレイの経営3方針

更新日：2026-10-02。ユーザーの希望に沿い、「基礎営業」「安定経営」「積極経営」の3方針を実装した。ゲーム開始時に選ぶ目標モードとは別の、テスト用自動プレイヤーの判断方針である。

| 表示名 | CLI指定 | 判断 |
| --- | --- | --- |
| 基礎営業 | `basic`（既定） | 従来の単純な出勤・休養・回答を維持。投資・予約を増やさず、失敗も比較結果として残す |
| 安定経営 | `clear` | 猫別の予測疲労・ストレス60以下を優先し、負担を回復しながら期限内の人気3段階達成を目指す |
| 積極経営 | `fast` | 猫別の予測疲労65・ストレス60以下まで出勤候補に含め、健康な猫の稼働機会を増やして早期達成を目指す |

従来の `clear` 指定は安定経営として引き継ぐ。方針をセーブに追加保存しないため、再開時は同じ方針を明示して選ぶ。既存セーブの目標・期限・人気上限・猫や客のIDは維持し、過去の操作と詳細リプレイも変更しない。更新後の判断は以前の `clear` と同じになるとは限らない。

## 負担と投資の判断

安定経営・積極経営とも、今日の来店予定、同時接客の見込み、既存席による接客容量、健康で担当可能な在店猫から必要人数を見積もる。負担を均等に分担する目安だけでは担当が偏るため、猫別に次の最大を見込む。

- 接客量を必要人数で割った行動数（最低20行動）。
- 今日の来店客のうち、その猫の特徴と好みが一致する客の接客行動数の合計。
- 前日のその猫の実際の接客行動数。

好みの一致分と前日の行動数は営業時間を上限とし、特性による疲労・ストレス補正を適用する。未到着の好みは既存の固定設定から読み取り、来店記録や乱数を進めない。健康・在店・体力・担当可能の条件は両方針で共通。積極経営も、家出や長期療養で営業力を失う無理な出勤を避けるため、ストレスの予測上限は60に保つ。

安定経営は今日の出勤候補と同時接客の見込みが既存席数を上回る場合に増設する。積極経営は、来店人数と健康で担当可能な猫の総数が既存席数を上回れば、休養交代・待機客・増設で増える新客に備えて先行増設する。それ以外では安定経営と同じ見送り条件を使う。

休養設備・おもちゃ・防音改修の投資、席の解放条件・費用・運営予備資金、期限内の長毛猫の予約回答は共通。[準備判断](HumanToCatAutoPlayPlan.md#安定経営積極経営の判断)を参照。新規派遣・加入・プレイヤー交流は自動開始しない。ゲームの資金・人気・係数・期限を直接変更しない。

日本語ログとGUIの判断一覧には、選んだ方針名、猫別の接客行動数・予測負担・判断基準、出勤／休養、購入・予約の理由を表示する。GUIでは3方針から選択し、最大10日または各人気段階の達成で停止する。中止・保存・通常操作への復帰は従来どおり。

```bash
python3 -m cat_cafe_sim.cafe_autoplay --mode clear --days 60
python3 -m cat_cafe_sim.cafe_autoplay --mode fast --days 60
python3 -m cat_cafe_sim.cafe_autoplay --resume reports/autoplay/20261002103000/cafe.json --mode fast --days 10
python3 -m cat_cafe_sim.autoplay_evaluation --scenarios basic clear fast --days 60 --output reports/autoplay_policies.json
```

評価CLIは既存の設備除外条件も維持し、省略時は3方針と安定経営の設備除外3条件の計6条件を実行する。

安定経営は前回の43日・発症3回から40日・発症0回となった。積極経営は安定経営より最終達成が1日早い一方、第2段階は2日遅く、投資と取りこぼしも多い。これは1シードでの比較であり、積極経営が各段階で常に速いことを意味しない。

初期の積極経営では、均等分担の予測で疲労75・ストレス77まで許容すると44日・発症6回・家出5回となったため不採用。担当の偏りも考慮し、疲労65・ストレス60までに抑えるだけでは42日だった。最終案はその負担基準に先行増設を加えたもので、中間案は上のJSONに含めない。

予測は目安で、実際の待機・早期終了・担当の偏りを完全には再現しない。安定経営でも無発症を保証せず、積極経営も全初期条件で最短になる保証はしない。追加シードと手動プレイによる評価は後続。
