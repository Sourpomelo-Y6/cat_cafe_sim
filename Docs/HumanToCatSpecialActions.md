# 交流の拡張案：テンション・特別行動・動作種類

更新日：2026-09-07 / 状態：追加アイディアの記録

2026-09-11に特別行動を版2として実装した。[実装記録](HumanToCatSpecialActionsImplementation.md)を参照。
動作種類は[8種類と猫の個性の暫定仕様](HumanToCatInteractionTypes.md)へ具体化し、[版3として実装](HumanToCatInteractionTypesImplementation.md)した。以下は追加案を整理した時点の記録。

特別行動に関する未確定部分は[初回実装用の暫定仕様](HumanToCatSpecialActionsSpecification.md)で具体化した。
本書は追加アイディアと検討経緯の記録。特別行動の実装時は具体化した仕様を参照し、種類拡張は引き続き別途検討する。

[行動原案](HumanToCatActionProposal.md)と[初期設計](HumanToCatInteractionDesign.md)に対する追加仕様をまとめる。
以下の「追加するルール」はユーザーのアイディアを反映したもの。
数値や処理の詳細が提示されていない部分は、未確定事項または設計提案として分ける。

## 1. 追加するルール

お客側に「テンション」を導入する。猫側の「関心」と別のゲージとして扱う。

| 項目 | 心をつかむ | 心を開く |
|---|---|---|
| 主体 | お客（人）側 | 猫側 |
| 使用するゲージ | お客のテンション | 猫の関心 |
| 任意発動できる条件 | テンション80以上 | 関心80以上 |
| 発動時 | テンションを消費する | 関心を消費する |
| 強制発動 | テンション100以上になったら、次回のお客側の行動がこれになる | 関心100以上になったら、次回の猫側の行動がこれになる |
| 報酬 | ボーナス追加 | ボーナス追加 |

両方を同時発動すると、それぞれのボーナスに加えて追加ボーナスが発生し、もらえる資金がより増える。
100に到達した行動中の即時発動ではなく、**次回行動への予約**として区別する。
80以上100未満では発動可能であり、必ず発動するルールではない。

「80以上」は使用資格の閾値。「80を消費する」と決まったわけではないため、消費量は別途決める。
100を超えた分を保持するか、ゲージ上限を100とするかも未確定。
テンションは客満足・客の不満・猫の体力や気力・長期的信頼と別の値として管理する。

## 2. 同時発動とボーナスの整理

同時発動は「同じ交流tickで、お客側の心をつかむと猫側の心を開くが実行されたこと」とする設計案。
両側の選択をそのtickの開始状態から決めると、同時発動を狙うためのゲージ調整を表現できる。
一方の発動がその場で他方を100にし、同じtickで連鎖発動するかは原案では指定されていない。
初期案として、到達は次回予約に回し、同一tick内の連鎖発動は行わないことを提案する。

資金への反映は、次のように通常分・各特別行動分・同時発動分を分ける案とする。

```text
獲得資金 = 通常の獲得分
         + 心をつかむのボーナス
         + 心を開くのボーナス
         + 両方を同時発動した場合の追加ボーナス
```

金額・倍率・支払時点は未確定。式は加算で整理した案で、倍率方式を確定排除するものではない。
既存営業の体力0と満足達成による特別成功とは別イベントにする。
営業接続時には、ボーナスを即時加算するか会計時にまとめるかを決め、同じ発動を二重計上しない。

## 3. 次回行動の処理案

実装に向けて、通常行動と特別行動を以下の順で扱う案を置く。

1. tick開始時に、前回までに成立した両側の強制発動予約を確認する。
2. 予約がある側は特別行動を選ぶ。予約がない側は、ゲージ80以上なら任意発動を選べる。
3. 両側の選択を確定してから、ゲージ消費と行動効果を処理する。
4. 同時発動を判定し、通常の特別行動ボーナスと追加ボーナスをそれぞれ記録する。
5. 更新後のゲージが100以上になった側について、次回の強制発動予約を設定する。
6. 終了条件と、終了時に予約をどう扱うかを適用する。

手順6は特に未確定。現在の「関心100で即成功終了」のままだと、心を開くの次回行動が存在しない。
新ルールでは関心を消費可能なゲージへ変更するため、成功条件をゲージ到達から切り離す必要がある。
例えば特別行動の成立後に成功とする案があるが、現段階では採用しない。
時間切れ・体力切れと100到達が重なった場合の予約、最終ターンの発動可否も合わせて決める。

猫側は現在「反応を固定ルールで出す」実装で、任意行動を選ぶ仕組みがない。
80以上で心を開くか待つかを固定方策で決める案、猫の学習対象にする案などがある。
誰が猫側の任意発動を選ぶかは未確定であり、人が両側を自由操作する仕様とはまだしない。

## 4. 動作の切り替えで選べる種類を増やす

追加要望は、行動の切り替え先を現在の「遊び／なでる」の2種類から増やすこと。
「素直に動かす」「相手に合わせる」などの動かし方と、切り替える対象の種類を分けて整理する。

以下は候補であり、種類の確定リストではない。

| 種類候補 | 交流の例 | 検討点 |
|---|---|---|
| ねこじゃらし | 玩具を追う | 現在のplayに対応 |
| なでる | 穏やかに触れる | 現在のpetに対応。激しく・フェイントの適否を維持検討 |
| ボール遊び | 転がる物を追う | ねこじゃらしとの好み・消耗・効果の違い |
| ブラッシング | 毛並みを整える | なでるとの違い、専用道具の扱い |
| 声をかける | 呼びかけて反応を見る | 動作の強弱をどう表現するか |

おやつなどの資源消費が必要な種類を追加する場合は、在庫・費用を別途設計する。
初期の種類追加と同時に在庫システムまで必須にはしない。

3種類以上では、現在の「switchで2種類を反転」から、**変更先を指定する操作**が必要になる。
種類IDごとに猫の好み、有効な動かし方、基本効果・体力消費の補正を持たせる案とする。
同じ対象の速度や名称を少し変えただけで飽きを解消しないよう、種類と飽きの分類も整理する。
変更先の選択UIとログ項目、同じ種類への変更、往復変更の扱いを実装前に決める。

## 5. 既存資料・実装から変わる点

| 現状 | 拡張後に必要な変更 |
|---|---|
| お客のテンションなし | 上昇・減少・消費・初期値・上限・公開範囲を定義して追加 |
| 関心は100で成功終了 | 消費可能なゲージとし、成功・終了条件を再設計 |
| 心をつかむ／心を開くは未実装 | 80以上の任意発動、100以上の次回強制発動、消費とボーナスを追加 |
| 猫は通常反応を返すだけ | 特別行動の選択と通常反応の関係を定義 |
| 単独交流には資金なし | ボーナスの記録と資金反映先を定義 |
| 遊び／なでるを反転 | 種類リスト・変更先指定・好み・有効行動・履歴を拡張 |
| 現行ログとモデル | ゲージ・予約・双方の行動・消費・ボーナス内訳・対象種類を追加し、版を分ける |

[初期設計](HumanToCatInteractionDesign.md)の「関心100だけで自動発生させない」という旧案は、今回の追加案で置き換える。
初期版の実装記録・比較結果は当時のルールの記録として保存する。
既存コード・設定・GUIは今回変更しない。現在の画面ではテンションや特別行動はまだ使用できない。

## 6. 実装前に決める項目と検証順

| 未確定項目 | 決める内容 |
|---|---|
| テンション変動 | どの行動・反応でどれだけ増減するか。停止中や特別行動中の変動 |
| ゲージ消費 | 固定量か全量か。超過分と発動後の残量 |
| 猫の任意発動 | 80〜100未満で発動する判断主体と条件 |
| 特別行動の効果 | 通常行動を置き換える範囲、体力消費、他方のゲージへの影響 |
| 終了との優先順位 | 成功条件、最終tick、体力切れ、強制予約を持ったまま終了する場合 |
| 資金ボーナス | 各発動・同時発動の額または倍率、会計との接続 |
| 種類拡張 | 最初に増やす種類、好み・効果・飽き分類と変更操作 |

次はこの表の暫定値と処理順を具体化し、単独交流で2ゲージと予約発動を検証する。
種類拡張は独立した実装単位にすると、特別行動との効果の切り分けがしやすい。
低体力バランスの比較は、成功条件と特別行動の仕様が決まった後に新ルールで行う。

境界テストには、79から80、99から100、100超過、任意発動による消費、片側だけの予約、
両側の予約、任意＋強制の同時発動、ボーナス一度だけの加算、終了と予約の競合、保存再生を含める。
任意発動を待って同時発動を狙う戦術と即発動を比較し、停止や低消費行動による無制限な資金獲得も調べる。
