# 猫の特徴とお客さんの好み：初回仕様

更新日：2026-09-22 / 状態：初回実装済み

[検討案](HumanToCatCustomerPreferencesPlan.md)のうち、外見的特徴と好みの一致によるテンション補正を実装した。
「特徴」は属性、「特性」はパッシブ効果、「個性」は猫の遊び方の好みとして分ける。
細かな数値調整は全体の流れが固まった後に行う。

## 特徴と保持数

| カテゴリー | 種類 | 同時保持 |
|---|---|---|
| 毛色・柄 | 白猫、黒猫、三毛、茶トラ、キジトラ、白黒 | 最大1つ |
| 毛の長さ | 短毛、長毛 | 最大1つ |

猫は「白猫＋長毛」のように最大2つの特徴を持てる。同じカテゴリーの重複は不可。
未設定も認める。名前から特徴を推測せず、設定に明記する。
白猫好きは白猫だけに一致し、白黒・三毛には一致しない。特徴のIDによる完全一致を使う。
既存の接客好き・のんびり屋・外出好きは引き続き最大1特性またはなし。特徴の数には含めない。

新規ゲームの初期猫は次の設定。元設定は [cafe_new_game.json](../config/cafe_new_game.json)。

| 猫 | 特徴 |
|---|---|
| ミケ | 三毛・短毛 |
| タマ | 白黒・短毛 |
| ソラ | 白猫・長毛 |
| コハク | 茶トラ・長毛 |
| ムギ | キジトラ・短毛 |

新しく提示される保護猫候補は、ハルが白猫・短毛、リンが黒猫・短毛、ユキが三毛・長毛。
定期追加でもこの組み合わせを暫定使用し、候補提示時に保存して加入時に引き継ぐ。
元設定は [cafe_recruitment.json](../config/cafe_recruitment.json)。

## お客さんの好み

新規ゲームで導入し、来店時に1人1つの好みを決める。
白猫好き・黒猫好き・三毛好き・茶トラ好き・キジトラ好き・白黒好き・短毛好き・長毛好きの8種類。
ゲームのseedとお客さんIDを用いて決定し、同じお客さんは翌日・保存再開後も同じ好みを持つ。
画面を開き直したり、担当猫を変更したりしても好みは変わらない。
顧客の名前・来店曜日・常連度を管理する名簿全体を実装したわけではない。

候補プールと倍率は [cafe_customer_preferences.json](../config/cafe_customer_preferences.json) に設定し、新規ゲーム開始時に固定する。

## 相性バフ

特徴が一致すると、**通常行動の正のテンション上昇量を1.25倍**にする。数値は暫定。
例：通常の好反応による＋12が、相性一致なら＋15になる。
猫からお客さんへの好感度、猫の関心、体力消耗、特性の効果を直接増やさない。

- 対象は通常行動の熱中・好反応・中立による正のテンション上昇。
- 困惑・無気力・そっぽを向く等のテンション低下には補正しない。
- 休止・行動切り替えには補正を発生させない。
- 「心を開く」によるテンション上昇には補正しない。「心をつかむ」の消費量や特別ボーナス額も変更しない。
- 補正後に従来の上限処理と80・100の閾値判定を行う。100到達なら次回の強制行動が従来どおり予約される。
- お客さんの好みは1つなので、複数特徴でも1回だけ補正。倍率を重ね掛けしない。
- 不一致や特徴未設定では倍率1。通常どおり接客でき、デバフはない。
- プレイヤーとの交流、派遣の満足度には適用しない。

テンションの上がり方が変わることで、特別行動の発動時点や最終的な報酬・好感度が間接的に変わる場合はある。
好みの一致を猫側からの好感度上昇として直接扱わない。

## 配置前の表示と操作

- 猫の詳細と保護猫候補の詳細に、個性・特性とは別に「特徴」を表示する。
- 営業画面でお客さんと担当候補の猫を選ぶと、特徴・好み・一致理由・倍率を表示する。
- 「お客との相性…」で来店済みのお客さんを選び、全猫の特徴・相性・現在の担当可否を比較できる。
- 相性画面は閲覧のみ。開くと営業を一時停止し、閉じても停止状態を維持する。
- 相性が良くても、休養・療養・不在・体力不足等で担当不可の猫は配置できない。
- 自動割り当ては従来の体力優先（同値ならID順）を維持。相性優先への変更は後続。
- 接客コマンドは従来どおり自動で選択する。

## 保存・互換性

営業セーブ形式2・チェックポイント1に任意の `cat_features` と `customer_preferences` を追加。
猫ごとの特徴、好みの設定、来店済みのお客さんIDと好みを保持する。
初期設定はリプレイ4に `initialize_preferences` 操作として記録する。
来店時の好みは営業進行から再現し、特徴・好み・加入候補との一致を復元時に検証する。

交流の設定に `customer_tension_multiplier` を必要時だけ保存する。倍率1では項目を省略し、旧交流ログの表現と結果を維持する。
接客開始時に組み合わせに合った倍率を確定し、接客途中の保存再開でも再計算による上乗せをしない。
通常行動のテンション増分は既存の交流ログに補正後の値で残る。
復元時に接客中の倍率と猫・お客さんの組み合わせが一致していることも検証する。

旧セーブの所属猫・提示済みの候補へ特徴を後付けしない。旧セーブのお客さんには好みを自動付与せず、相性バフも発生させない。
旧ゲームでも更新後に提示された新しい加入候補には特徴があり、加入後も表示・保存するが、お客さんの好みは未導入のまま。
通常の新規ゲームから、特徴と好みの両方を利用できる。
既存ゲームへの好み導入・特徴の編集や再抽選は今回追加しない。
