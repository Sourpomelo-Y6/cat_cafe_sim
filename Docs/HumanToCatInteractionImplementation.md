# 人と猫の単独交流：初期実装と検証結果

更新日：2026-09-06 / モード：`human-cat-interaction` / ルール版：1

[設計書](HumanToCatInteractionDesign.md)の最小範囲を実装した。
6行動・6反応、関心・体力・好み・飽き・終了判定を持つ、標準ライブラリだけの単独交流モード。
数値は試作用の暫定値で、`config/human_cat_interaction.json`に分離している。
既存営業の猫方策・客満足・気力回復とは独立している。

## 実行と再生

リポジトリのルートで実行する。

```bash
python3 -m cat_cafe_sim.human_cat_demo run \
  --actions direct direct pause feint --output reports/human_cat_example.json
python3 -m cat_cafe_sim.human_cat_demo replay reports/human_cat_example.json
python3 -m cat_cafe_sim.human_cat_demo compare
```

行動IDは`direct`、`adapt`、`intense`、`feint`、`pause`、`switch`。
`--actions`は指定列を1回だけ実行する。短い列なら継続中のログを保存し、終了が先に起きたら残りの操作は実行しない。
終了状態からの追加操作はcoreではエラーとなる。`pet`中の`intense`・`feint`も状態更新前に拒否する。
`run --stamina 20`で低体力開始、`run --config PATH`で別設定を指定できる。
好みは設定JSONの`preferences`を変更する（遊び、なでるの順）。

上の例は関心12 → 22.2 → 22.2 → 34.8、体力95 → 90 → 92 → 84となる。
停止は飽き履歴を保持し、その直後のフェイントだけに条件付き基本効果18を適用する。
開始直後の停止や連続停止ではこの効果が発生しない。

APIでは`HumanCatInteraction.observation()`を操作側方策に渡す。
この辞書は公開状態のコピーで、猫の好み・判定スコアを含まない。
`step()`の返り値と保存ログには診断情報を含むため、そのまま方策の観測には使用しない。
`valid_actions()`は現在有効な文字列IDを返し、終了後は空になる。

ログにはモード・版・設定・開始体力・実行した操作・全tickの状態・反応・実増分・最終集計を保存する。
再生は設定と開始体力から操作を再実行し、各tickと集計を照合する。途中までのログも検証できる。
異なるモードや版を拒否し、既存営業ログとは別形式で扱う。
照合は記録の内部整合性を確認するもので、ログの真正性を保証する電子署名ではない。

## 固定行動列の比較

好み4種類×開始体力2種類×方策6種類の48条件を実行し、全件のログ再生一致を確認した。
決定的なルールの仕様診断であり、学習済み方策の性能評価や未使用条件での検証ではない。

| 方策 | 行動規則 | 成功 / 8 | 消耗終了 / 8 | 時間切れ / 8 | 平均関心 | 平均体力消費 |
|---|---|---:|---:|---:|---:|---:|
| direct | 素直連打 | 1 | 7 | 0 | 24.09 | 51.88 |
| intense | 激しく連打 | 1 | 7 | 0 | 29.45 | 53.12 |
| pause_feint | 最初に素直、以後停止→フェイント | 1 | 4 | 3 | 28.28 | 46.50 |
| responsive | 体力20以下なら停止、直前が否定的反応なら合わせる、それ以外は素直 | 1 | 0 | 7 | 39.48 | 32.38 |
| switching | 素直→素直→変更を反復 | 3 | 4 | 1 | 44.98 | 36.88 |
| pause | 停止のみ | 0 | 0 | 8 | 0.00 | 0.00 |

`responsive`は公開観測だけを参照し、体力閾値20を持つ固定の比較方策。
別設定で低体力閾値を変更してもこの方策の閾値は変えない。
比較の開始体力は100・20に固定しているため、最大体力100未満の設定はこの比較には使用できない。

体力100・好み(2,0)では激しく連打が3tickで成功した。一方、体力20開始は全方策で成功しなかった。
切り替え方策は成功条件が多いが、今回の少数条件だけで最適とは判断しない。
反応に合わせる方策は消耗終了を避けたが、好み0の種類から自分で切り替えないため進捗しない場合がある。
停止連打は関心を増やさず、時間切れになることを確認した。
結果を理由に今回の暫定係数を追加調整していない。

比較JSON・Markdownは`reports/human_cat_comparison.json`と`.md`、各条件のログは同名ディレクトリ。
JSONには反応内訳・使用tick・関心・体力消費・終了理由を条件別に保存する。
生成レポートは従来どおりGit管理外とし、本書に結果を記録する。

## 検証と次の範囲

`venv/bin/python -m unittest discover -s tests`で112件成功（既存98件＋追加14件）。
手計算、6反応の境界と優先順位、直前反応への適応、飽き下限、停止連携、切り替え往復、
無効操作の無更新、消耗と成功・時間切れの同時成立、入力検証、公開観測の分離、
途中／終了ログの再生と改変検出、48条件の網羅を確認した。
CLIは`python3 -S`でも実行・比較でき、Gymnasium等の追加依存を必要としない。
