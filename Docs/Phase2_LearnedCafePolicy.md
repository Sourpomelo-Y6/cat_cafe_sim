# 学習済み猫の1日営業への接続

更新日：2026-09-05

続く[接客開始状態の指定](Phase2_InteractionStart.md)では、低リソース・閉店間際からの
接客環境の開始とログ再生を追加した。開始条件を混ぜた再学習は未実装。

保存済みQモデルを`SimulationCore`の猫方策として使用できるようにした。
今回の実装単位は営業CLIへの接続と境界条件テスト。
猫の追加学習や、料金・接客ルールの調整は行っていない。

## 実行手順

```bash
# モデルがない場合は先に学習する（既存モデルがあれば不要）
venv/bin/python -m cat_cafe_sim.training train

# モデル内のゲーム設定で1日営業。モデルのseedとは別に営業seedを指定
venv/bin/python -m cat_cafe_sim run --policy learned \
  --model models/cat_q.json --seed 42 --output reports/learned_day_seed42.json

# モデル・Gymnasium・NumPyがなくても、記録された行動で営業結果を再生可能
python3 -m cat_cafe_sim replay reports/learned_day_seed42.json

# 同じ既定条件で固定・ランダム猫と比較
python3 -m cat_cafe_sim run --policy fixed --seed 42 --output reports/fixed_day_seed42.json
python3 -m cat_cafe_sim run --policy random --seed 42 --output reports/random_day_seed42.json

# 境界条件を含む全テスト
venv/bin/python -m unittest discover -s tests -v
```

`--policy learned`には`--model`が必須。ほかの方策に`--model`を指定した場合もエラーにする。
学習済み猫のみ`requirements-env.txt`の依存が必要。固定・ランダム営業とログ再生では読み込まない。

`--config`省略時は、学習済み猫ではモデル内の設定、固定・ランダムでは`config/default.json`を使う。
独自設定で学習したモデルと比較する場合は、固定・ランダムにも同じ設定JSONを指定する。

## 観測と方策の契約

`policies/learned.py`の`LearnedCatPolicy`が営業用の`choose(observation)`を提供する。
`envs/observations.py`で学習環境と観測変換を共通化し、資源の正規化・float32への丸め・履歴符号を揃えた。
float64のまま離散化すると、区間境界付近で学習時とは違うQ行を参照するため、この変換もテストする。

満足、直前行動、交流種類、連続回数、初回フラグはcoreの現在の来店から受け取る。
方策側に顧客履歴を蓄積しないので、次の客へ前の客の満足・飽きが持ち越されることはない。
体力・気力と営業の残り時間は、実際に持ち越された値を使う。
非公開の好み・将来の来店列は方策の観測に追加していない。

営業中は探索・Q更新を停止する。未知状態では既存Qエージェントの規則に従い、
全Q値0として最小の有効行動ID（0）を選ぶ。今回は未知状態の代替として固定方策へ切り替える処理は加えていない。
営業中の判断回数・未知状態の回数と割合を別途記録する。カウンターはモデルの学習状態を変更しない。

## 設定互換性

CLIとcoreの初期化時にモデルと営業設定を照合し、不一致を開始前に拒否する。

- 変更可能：来店時刻、客の好み、待機列上限、待機期限、初期資金。
- 営業時間：学習時以下への短縮は可能。学習時の観測上限を超える延長は拒否する。
- 上記以外：体力・気力上限、行動効果、飽き・切り替え、料金などはモデルと同じ値を要求する。

営業設定の変更例は、モデル内設定をJSONとして書き出し、`arrival_ticks`や`preferences`のみ編集して
`--config`に渡す方法。短縮する場合は来店時刻も営業時間内に収める必要がある。
互換性チェックは好成績を保証するものではなく、状態番号の意味やゲームルールの取り違えを防ぐための制約。
ルール変更前のモデルを意図的に転用する比較モードは今後の拡張とする。

## 保存と再生

営業JSONに次を追加する。

```text
cat_policy_version = tabular-q-cafe-v1
cat_policy_metadata:
  model_sha256, policy_version, encoder_version, training_seed
  exploration=false, learning=false
  decisions, unknown_states, unknown_state_rate
```

CLIから読み込んだモデルは元JSONのSHA-256を記録する。
Pythonで直接構築した方策では元ファイルがないため、SHA-256はnullになる。
標準出力にも`policy_diagnostics`を含める。CSVは従来の営業指標を出力する。

再生は保存した猫行動と店長コマンドを実行し、各tickの状態・イベント・最終会計を照合する。
**モデルの判断そのものを再計算・検証する機能ではない。** 来店条件やモデルが違った実験を追跡できるように
識別情報を残すが、メタデータは再生結果の一致判定に使わない。
モデルJSONなし、さらにPythonの`-S`で外部ライブラリを読み込まない条件でも再生一致を確認した。

ゲームルール・状態遷移は変更していないため、シミュレーター0.2.0、環境cat-interaction-v2、
既存モデル形式を維持する。営業ログへのメタデータ追加は任意フィールドであり、既存ログも再生できる。

## 検証結果

69件のテストが成功。今回追加した12件では、顧客切り替え、既知Q行の選択、
体力0での成功と次客前の回復、気力が回復コスト未満／同値、閉店と成功の優先順位、
相性0の客、設定互換性、丸め境界、推論時の無更新、CLI引数、依存なし再生を確認した。

前回保存した3,000接客・学習seed 42のモデルをそのまま用い、営業seed 42・40tick・6来客で比較した。
モデルSHA-256は`08c3cee46d3cc741482624a7cfc0faa75d107e82ed7fc6d22e3b8eacc82fb9f6`。
店長はすべて同じFIFO固定方策。

| 猫方策 | 満足退店 | 接客不能による不満退店 | 未対応 | 気力消費 | 売上 | 未知状態率 |
|---|---:|---:|---:|---:|---:|---:|
| 固定 | 5 | 1 | 0 | 90 | 920 | — |
| ランダム | 5 | 0 | 0 | 90 | 900 | — |
| 学習済み | 3 | 0 | 2 | 90 | 790 | 82.05% |

学習済み猫は39回判断し、そのうち32回が未知状態だった。満足退店3人のほか、
着席中の客1人が閉店退店、未対応2人は待機期限で退店した。
表の「接客不能による不満退店」はcoreの`failures`で、待機中の不満はこの列には含まない。

追加診断として全客の好みを(.1,.1)にした場合、全方策の満足退店は0。
閉店直前tickだけに1人来店させた場合は、全方策で1行動・料金10・閉店退店となった。
低気力の境界は、低い気力上限と整合するテスト用モデルで検証している。
学習済みモデルの上限を変えて低気力に見せかける評価はしていない。

単一接客で良い成績だったモデルでも、営業全体では固定方策を下回った。
学習は体力・気力が満タンかつ営業時間の最初から始まる接客が中心で、
営業中の「消耗した猫が次の客を担当する」「閉店が近い状態で接客を始める」場面を十分に経験していない。
未知状態率はこの条件差を示しており、次の改善では学習開始状態を広げるのが優先候補になる。

今回は1モデル・1営業seedの動作診断。これだけで方策の一般的な優劣は判断しない。
営業評価を見てモデルや報酬を調整する場合は、別の来店条件を新しい未使用評価用に確保する。
