# 親しみの持ち越しと交流成果：初回実装用の暫定仕様

更新日：2026-09-12 / 状態：仕様具体化、未実装

[交流の目的・終了・成果の見直し](HumanToCatInteractionPurpose.md)を具体化する。
初回は「猫から特定のお客への親しみ」を持ち越し、終了理由と成果を分けて表示する。
ユーザーが了承した方向性を具体化した案であり、以下の呼称・数値・保存方式はアシスタントが置く暫定仕様。
製品としてのバランスや長期的な進行速度を検証したものではない。コード・既存設定は今回変更しない。

## 1. 初回の範囲

単独交流の次版（ルール版4）で、猫ID・客ID、親しみ、任意終了、成果確定、同じ相手との再会を扱う。
客満足や営業の財布への接続、客から猫への好意、別の信頼ゲージ、長期疲労・病気は後続に分ける。
学習や、両側の特別行動発動率を高める方策の実装は保留する。

親しみは関係性を育てる成果として表示し、初回は行動効果・初期ゲージ・ボーナス額への補正を付けない。
親しい相手だから苦手な種類も好きになる、といった個性の変更も行わない。
数値を持ち越す挙動と成果の妥当性を確認してから、親しみによる行動や演出の違いを検討する。

## 2. 関係データ

| 項目 | 初回仕様 |
|---|---|
| 関係の方向 | 猫からその客への一方向 |
| 表示名 / 内部名 | 親しみ / `affinity` |
| 識別 | `(cat_id, customer_id)`の組み合わせ |
| 初期値・範囲 | 初対面は0、0〜100、小数可 |
| 持続 | 同じ保存データ内で、同じ組み合わせの再会へ引き継ぐ |
| 自然減少 | 初回はなし |
| 更新時点 | 交流中は変化予定を積算し、終了結果の確定時に一度だけ反映 |

猫名・客名は表示用とし、名前を変更してもIDを変えない。
別の客なら同じ猫でも別の親しみを持つ。別の猫との関係も独立する。
初期値0のため不快な経験を負の数として蓄積しない。この制約と「初対面より嫌われる」表現は後続の検討対象。

開始時に親しみのスナップショットを読み、交流中の表示は「開始時」「変化予定」「終了時の見込み」を分ける。
ゲージの関心やテンションを親しみとして流用しない。特別行動で関心を消費しても、それ自体では親しみは減らない。

## 3. 通常交流による変化

人がdirect・adapt・intense・feintを実行したとき、種類と個性を反映した**通常反応**から親しみの変化予定を積算する。

| 通常反応 | 親しみの変化予定 |
|---|---:|
| 熱心に応じる | +1.0 |
| 好意的に応じる | +0.5 |
| 普通に応じる | 0 |
| 戸惑う | 0 |
| けだるそうにする | 0 |
| そっぽを向く | −1.0 |

普通・戸惑い・けだるさだけで関係を悪化させない暫定案。
そっぽを向く交流では関係の負の変化を記録するが、その後で適切な交流をすれば同じ交流内でも積み直せる。
停止・種類変更では、反応が表示されてもこの表を適用しない。
終了操作や再会した事実だけでは加点しない。停止連打や開始直後の終了で親しみを増やせないようにする。

猫だけopen_upするtickでも、人の通常交流に対する算出用の`normal_reaction`をこの表に使う。
画面に表示されるopen_upを通常反応としてさらに加点する処理は作らない。
猫の好みそのものを更新処理で直接報酬にせず、実際の交流結果を使う。

## 4. 特別行動と消耗の成果

| イベント | 親しみの変化予定 | 資金ボーナス |
|---|---:|---:|
| 心をつかむの実行 | +1.0 | +50 |
| 心を開くの実行 | +2.0 | +50 |
| 同じtickで両方を実行 | 上記に加えて+1.0 | 上記に加えて+100 |
| 体力切れによる終了 | −2.0を1回 | 既に発生したボーナスを取り消さない |

両側同時発動の合計は親しみ+4、資金200。
猫だけopen_upしつつ通常交流も行う場合は、前節の通常交流分とopen_up分を別イベントとして加算する。
例えば好意的な通常交流と猫のopen_upなら親しみ+2.5、資金50。
人のconnectは通常交流を置換するため、通常反応による加点はない。

体力切れは「交流全体を失敗にする」のではなく、消耗の記録と親しみ−2の要因として扱う暫定案。
終了前の良い交流や資金は消去しない。低体力で始めたこと自体には減点しない。
任意終了・時間終了には終了理由だけによる加減点を付けない。

ゲージ80消費、100到達で次回予約、猫側の固定選択規則などは版3を引き継ぐ。
**両側発動済みという理由での自動終了は廃止する。** 同時発動後も、時間と体力が残っていれば続けられる。
追加の発動回数制限や報酬減衰は初回には入れず、継続可能になったことで親しみ・資金を稼ぎすぎないかを検証する。

## 5. 終了操作と優先順位

| 終了理由 | 識別子 | 挙動 |
|---|---|---|
| 自分で切り上げる | `manual` | tickを消費せず終了。猫の反応、回復、ゲージ増減を発生させない |
| 残り交流時間が0 | `time_limit` | 最後の行動の効果を処理してから終了 |
| 体力0 | `exhausted` | 最後の行動の効果を処理し、消耗による親しみ変化を一度加えて終了 |

`finish()`を通常動作とは別の操作として追加する案。
強制connect予約があっても任意終了は選べる。予約は「交流を続ける場合の次回動作」であり、継続そのものを強制しない。
終了で予約は失効し、未実行分のゲージ消費・ボーナス・親しみ変化を発生させない。
開始直後の任意終了も可能で、成果はすべて0、親しみは変わらない。

通常stepの順序：

1. 入力と終了状態を検証する。無効入力は完全に無更新。
2. 版3の両側選択・ゲージ消費・通常効果・テンション・ボーナスを計算する。
3. 通常交流・特別行動の親しみ変化予定を記録し、残り時間を減らす。
4. 体力0ならexhausted、そうでなければ残り時間0ならtime_limit、それ以外は継続する。
5. 継続時は次回予約を更新。終了時は予約を失効させ、終了結果を作る。

最後の行動で発動と体力切れ・時間終了が重なっても、実行済み成果はそのtickに記録する。
exhaustedとtime_limitが重なったらexhaustedを優先する。独立した「成功」フラグは追加しない。
終了後のstepは拒否する。終了後のfinishは元の終了結果を返すだけで、理由を上書きせず成果を再加算しない。

## 6. 結果の計算と表示

```text
変化予定の合計 = 通常交流分 + 特別行動分 + 同時発動追加分 + 消耗終了分
確定後の親しみ = clamp(開始時の親しみ + 変化予定の合計, 0, 100)
実際の変化 = 確定後の親しみ − 開始時の親しみ
```

変化予定は途中で0〜100に切り詰めず、終了時に一度だけ親しみの範囲を適用する。
上限・下限で反映されなかった分も結果に記録する。上限到達や変化0で交流を自動終了させない。

結果には終了理由、猫と客のID、使用tick、親しみの前後・実変化・内訳、
獲得資金、消費体力・回復量・残体力、両側と同時の発動回数を表示する。
客満足はまだ単独交流へ接続しないため、親しみやテンションを客満足と呼び替えて表示しない。
資金も初回は交流ボーナスの成果記録で、既存営業の財布には反映しない。

## 7. 再会・新規開始・保存

初回実装では、保存データを選んで猫と客のIDを指定し、同じ組み合わせで再会できるようにする。
関係データは組み合わせごとの親しみと更新番号、結果データは一意の`session_id`と成果を持つ。

| 操作 | 関係データの扱い |
|---|---|
| 同じ猫・客と再会 | 直前までに確定した親しみを読む |
| 別の猫・客で開始 | その組み合わせの既存値を読む。なければ0 |
| 個性の試作用編集 | 関係と別項目。表示名や個性変更だけで別IDへ切り替えない |
| 新しい保存データを作成 | 空の関係データで開始。既存ファイルへ自動上書きしない |
| ログの保存・再生 | 本番の関係データへ成果を加算しない |

結果計算と永続データへの反映を分離する。終了結果を確定するとき、同じsession_idを一度だけ適用する。
親しみ更新と「適用済みsession_id」の記録は、同じ保存内容へまとめて書き込む。
ファイルは一時ファイルへ完全に書いて置き換える方式とし、再保存や保存失敗後の再試行で二重加算しない。
単一プロセス・単一の進行中交流を初回の対象とする。開始時の更新番号が変わっていた場合は上書きせず競合として扱う。

保存失敗時は終了結果を保持し、未保存と表示して再試行できるようにする。未確定のまま次の交流へ進まない。
再生用ログには開始時親しみ・ID・通常操作列・任意終了イベント・結果を保存し、保存先への書き込みなしで検証する。
旧版ログから過去の親しみを推定・遡及加算しない。

進行中の「再開始」は即座に履歴を消す操作から見直す。
GUIは「切り上げて結果を保存してから再会」「試遊を破棄」「戻る」を区別する。
破棄では親しみも資金成果も適用しない。ウィンドウを閉じたことを勝手に良い交流や消耗終了として確定しない。
終了しても未保存の場合は、保存再試行または未保存結果の破棄を明示して選べるようにする。

再会では関心・テンション・履歴・時間を初期化する。体力は単独試遊の指定開始値を使う。
これは営業中に無料で体力回復できるゲームルールではない。日・休養・再来店時間との接続は後続とする。

## 8. 手計算例と受け入れ条件

以下は暫定係数に基づく期待値で、未実行。

| 状況 | 終了理由 | 親しみの変化予定 | 確定例 | 資金 |
|---|---|---:|---|---:|
| 好意的な通常交流1回で切り上げる | manual | +0.5 | 0→0.5 | 0 |
| 特別行動なしで、熱心1回・好意的2回、時間終了 | time_limit | +2 | 10→12 | 0 |
| 停止だけで時間終了 | time_limit | 0 | 10→10 | 0 |
| 開始直後に切り上げる | manual | 0 | 10→10 | 0 |
| 同時発動1回後に切り上げる | manual | +4 | 10→14 | 200 |
| そっぽ1回の後、体力切れで終了 | exhausted | −3 | 10→7 | 0 |
| 同時発動1回、親しみが上限付近 | manual | +4 | 99→100、実変化+1 | 200 |
| 親しみ0でそっぽ1回の後に切り上げる | manual | −1 | 0→0、実変化0 | 0 |

低体力の猫を短い交流で切り上げ、特別行動なしでも成果を持ち帰れることを確認する。
全条件で特別行動を発動できることや、すべての交流で親しみが増えることは受け入れ条件にしない。

実装時には、次を検証する。

- 猫・客の組み合わせの独立性、同じIDでの再会、表示名変更、初対面と新規保存。
- 通常反応の内訳、停止・変更・終了による無加点、猫だけopen_up時の重複しない集計。
- 同時発動後の継続と再発動、任意終了と予約失効、最終tickと体力切れの優先順位。
- 親しみ0／100での実変化、消耗しても過去成果を全消去しないこと。
- 終了の再呼び出し、保存再試行、session_idの再適用、途中書き込み失敗、更新競合。
- ログ再生の読み取り専用性、版1〜3の再生維持、破棄と確定の区別。
- 即終了・短い交流の反復・停止連打・特別行動の反復による、親しみと資金の増加速度。

評価は成功率ではなく、親しみ・資金・消耗・交流の長さ・終了理由を並べる。
低消耗での交流にも意味があるか、短時間反復だけが有利になりすぎないか、個性の違いが残るかを試遊で確認する。
親しみを反応や初期状態へどう反映するか、双方向の好意、客満足・営業会計への接続はこの初回検証の後に扱う。
