# 交流の目的・終了・成果の見直し

親しみ・終了・成果・持ち越しの初回案を[暫定仕様](HumanToCatRelationshipSpecification.md)へ具体化した（未実装）。
本書は見直しの目的と、その時点の未確定事項を記録する。


更新日：2026-09-12 / 状態：目的と評価方針の整理、実装変更なし

## 1. 見直す理由と資料の位置づけ

現在の単独交流では「お客と猫がそれぞれ特別行動を1回以上発動すると成功終了」としている。
これは実装時にアシスタントが置いた暫定条件であり、ユーザーの特別行動案そのものに含まれていたクリア条件ではない。
同様に、低体力からの成功経路を探したのは立て直しの診断であり、すべての開始条件でクリアできることを製品要件にする根拠はなかった。

本書は今後の目的・評価方針の整理を優先する資料とする。
既存仕様書の終了条件と比較結果は、版1〜3で何を実装・測定したかを説明する記録として残す。
本書の追加で実行コード・保存ログ・試遊画面の挙動は変わらない。
好感度の導入を確定実装済みとして扱わず、関係性を育てる方向の設計案として分ける。
記憶を使う方策の実装と、低体力の成功率を上げる調整は保留する。

## 2. 何のために交流するのか

元の[猫カフェ実装資料](CatCafeSimulation_ImplementationGuide.md)は、猫の健康を保ち、客を満足させ、収益で店を育てる経営ゲームを想定している。
単独交流はその一部分であり、特別行動を毎回両方出すことだけを目的にしない。

今回の整理では、次の役割分担を提案する。

| 時間幅 | 交流の役割 | 成果として見るもの |
|---|---|---|
| その場 | 猫の状態と反応に合わせて交流する | 反応、客の満足、猫の消耗、特別行動と獲得資金 |
| 同じ猫と客の再会 | 相手との関係性を積み重ねる | 組み合わせごとの好感度・信頼の変化（未実装案） |
| 営業・日をまたぐ運営 | 猫を休ませながら客に楽しんでもらう | 客満足、関係性、健康・疲労、収益の釣り合い |

「関係が少し進む」「客が楽しむ」「無理をせず切り上げる」など複数の成果を扱えるようにする。
特別行動が出なかった交流にも意味を持たせる方向で検討するが、単に時間を使えば必ず好感度が上がるとは定めない。
店全体のクリア条件・破産条件・長期目標は今回新たに設定しない。

## 3. 終了理由と成果を分離する

終了理由は「なぜ交流が止まったか」、成果は「その交流で何が起きたか」。一つの成功／失敗フラグにまとめない。

| 終了理由の候補 | 意味 | 成果との関係 |
|---|---|---|
| 任意に切り上げる | プレイヤーや運営側が交流を終える | 早く終えたことだけを理由に失敗や減点にしない |
| 交流時間の終了・閉店 | 利用時間が終わる | 時間内に得た成果を集計する。両特別行動未達だけで失敗にしない |
| 猫の体力切れ・継続不能 | 猫が交流を続けられない | 終了と消耗を記録する。既に得た資金や関係変化の扱いは個別ルールで決める |
| 客が満足して切り上げる | 営業接続時に客側が終了する | 猫の関心と別の客満足に基づく。単独交流での実装は未確定 |

任意終了は新しく提案する操作で、現在のGUIを閉じる・再開始する操作を自動的にこの終了として扱うものではない。
猫の体力0まで続けることを目標にせず、低体力なら休む・短く交流する・交流を始めない判断も扱えるようにする。

将来の結果画面は、終了理由と、客満足の変化、関係の変化、獲得資金、消費体力、特別行動回数を別項目で示す案とする。
まだ実装していない客満足・関係変化を、現在の関心やテンションから表示だけ読み替えて算出しない。

## 4. 特別行動の位置づけ

ユーザー指定の次の内容は維持する。

- 心をつかむ：お客のテンション80以上で消費して使用可能。100以上になったら次回のお客側行動として発動。
- 心を開く：猫の関心80以上で消費して使用可能。100以上になったら次回の猫側行動として発動。
- それぞれにボーナスを付け、同時発動ならもらえる資金がさらに増える。

見直し案では、特別行動は交流中に良い成果を得る機会とし、両側が発動したことだけによる自動終了を外す方向とする。
片側だけの発動、別々のtickでの発動、同時発動は引き続き区別して記録する。
「心を開く」という表示だけで長期の信頼が必ず上がると確定しない。長期関係への効果は別途定義する。

ゲージ80消費、単独各50・同時追加100という数値は版2／3の暫定値で、ユーザーが指定した固定値ではない。
自動終了を外すと発動回数と資金が増える可能性があるため、同じ値が適切かは再検証する。
繰り返しの上限や減衰を根拠なく追加せず、終了・報酬の設計が決まった段階で検討する。
任意終了と次回強制予約が重なる場合も、予約があるから交流継続を強制するとはまだ決めない。

## 5. 好感度・信頼の案

現状、猫と客の組み合わせに蓄積する値はない。
導入するなら、短期ゲージや性格とは別の、猫IDと客IDの組み合わせに紐づく状態とする。

| 項目 | 主体・相手 | 持続期間 | 現状／提案 |
|---|---|---|---|
| 関心 | その場の猫 | 交流中 | 実装済み。特別行動で消費 |
| テンション | その場のお客 | 交流中 | 実装済み。特別行動で消費 |
| 種類・強さの好み | 猫自身 | 個性設定として維持 | 実装済み。特定の客への好意とは別 |
| 客満足 | 来店中のお客 | 来店ごと | 営業coreには存在。新しい単独交流との接続は未実装 |
| 猫から客への親しみ・信頼 | 猫→特定のお客 | 次回の再会へ持ち越す | 新規提案。呼称・数値・更新規則は未確定 |
| 客から猫への好意・お気に入り | お客→特定の猫 | 次回の再会へ持ち越す | 後続候補。猫側と同じ値に自動的にまとめない |

最初は「猫からその客への親しみ・信頼」の一方向から始める案を推奨するが、採用はまだ確定しない。
両方向の感情を表現したい場合は二つの値にする。好感度と信頼をさらに別々に数値化する必要性も検討する。

更新要因の候補は、好みに合う交流、嫌がる反応への対応、無理をさせた交流、特別行動など。
短く終了しただけで必ず加点する、体力切れだけで一律に全成果を消す、といった規則は置かない。
何を良い交流と見なすかに基づいて更新条件を決める。

好みを恒久的に書き換えて親しみを表現しない。親しくなることで苦手な種類が自動的に好きになる仕様にはしない。
関係性による初期ゲージ・反応・会計への補正も、実装前に効果を分けて決める。

持ち越しには安定した猫ID・客IDと保存先が必要。単独交流の再開始で同じ相手と再会するのか、新しい相手になるのかも明示する。
通常の再会では関係を保持し、テスト用の初期化・新規データ開始とは別操作にする案とする。
保存ログの再生が本番の関係値へ再加算しないよう、成果計算と永続データへの反映を分ける必要がある。

## 6. 低体力と過去の成功率の読み替え

低体力でも必ず特別行動を両方出せる必要はない。
低体力テストで確認すべきなのは、状態が正しく反映されるか、無理をせず終えられるか、終了までの成果を説明できるかである。
特別行動が出せる条件があれば選択肢として記録するが、全条件での達成を採用基準にしない。

[到達経路の診断](HumanToCatReachabilityAnalysis.md)の「9/10条件で成功」は、版3の両側発動条件への到達結果。
好感度が上がったこと、客が満足したこと、ゲームとして良い交流だったことは測っていない。
残体力が少なくなる経路や、同じ操作を繰り返す経路が見つかっても、そのまま推奨プレイにはしない。

中立・体力20の未発見を直すために、時間や好みを緩める必要は現時点ではない。
探索の未解決事項としては残るが、ゲーム設計の必須修正項目から外す。
過去の結果やログは変更せず、測った対象と解釈を訂正する。

今後は、関係変化・客満足・消耗・資金・終了理由を並べ、何を重視した方策かを明記する。
目的が決まる前に、両側発動率や資金だけを報酬にした新たな学習・方策最適化を進めない。

## 7. 次に具体化する事項

| 決める事項 | 今回整理した方向 | まだ決まっていないこと |
|---|---|---|
| 交流の目的 | 猫に合わせた交流と、客満足・関係性・健康・収益の釣り合い | どの成果を中心にプレイの目標とするか |
| 関係性 | 短期ゲージと別に、組み合わせごとに持ち越す案 | 一方向／双方向、呼称、初期値・範囲・増減・効果 |
| 終了 | 両側発動と分離し、任意終了も選択肢にする案 | 操作の時間消費、予約との優先順位、客満足による終了 |
| 通常交流の成果 | 特別行動以外にも意味を持たせる | 通常反応から客満足・関係値へどう反映するか |
| ボーナス | 単独・同時発動の資金増加を維持 | 継続可能になった場合の額・回数・会計との接続 |
| 継続と保存 | 同じ猫・客の再会と新規開始を区別 | ID管理、保存形式、結果確定とログ再生の責務 |

次の仕様化はこの表を対象とする。係数や好感度の閾値を今回の説明だけから確定しない。
実装時は終了・結果・保存の意味が変わるため、新しいルール版として旧版ログと区別する。
まず終了理由と成果を分けるデータ設計を作り、その上で関係性と会計への反映を具体化する。
