# 猫の特性：初回仕様

更新日：2026-09-22 / 状態：3種類の初回実装済み

接客・休養・派遣の担当選びに猫ごとの差を出す、常時適用のパッシブ効果。
既存の「個性」は遊びの種類・強さ・飽きやすさ等の好みであり、今回の「特性」と別に保持する。
数値は全体の流れを確認する暫定値。細かなバランス調整や家出のランダム化は今回行わない。

2026-09-22追記：[お客さんの特性・猫の特徴と相性の案](HumanToCatCustomerPreferencesPlan.md)で区分と複数保持を検討し、[特徴と好みの初回仕様](HumanToCatCustomerPreferences.md)を実装。猫の特性は本書の最大1つを維持し、特徴とは別に扱う。

## 種類と効果

1匹につき特性1つ、または特性なし。特性を持たない猫は従来どおりの係数で処理する。

| 特性 | メリット | デメリット |
|---|---|---|
| 接客好き | 接客によるストレス増加が通常の0.5倍 | 接客による疲労増加が通常の1.25倍 |
| のんびり屋 | 在店での休養・休業による疲労回復が通常の1.5倍 | 接客による疲労増加が通常の1.25倍 |
| 外出好き | 派遣の資金報酬が通常の1.25倍 | 派遣帰還を確定したときストレス＋10 |

元設定は [cafe_traits.json](../config/cafe_traits.json)。効果は基礎ルールに掛け合わせる。
例：現在の基礎ルールなら、接客好きの接客1行動はストレス＋0.5・疲労＋1.25。
のんびり屋の在店休養は疲労30回復。外出好きの近所への派遣は報酬125・帰還時ストレス＋10。
小数は整数に丸めず保持し、疲労・ストレスの既存の下限0・上限100で切り詰める。

## 初期猫と加入候補

新規ゲームの初期猫：

| 猫 | 特性 |
|---|---|
| ミケ | 接客好き |
| タマ | 外出好き |
| ソラ | なし |
| コハク | のんびり屋 |
| ムギ | なし |

新たに提示する保護猫の候補：ハルは接客好き、リンは外出好き、ユキはのんびり屋。
割り当ては [cafe_new_game.json](../config/cafe_new_game.json) と [cafe_recruitment.json](../config/cafe_recruitment.json) で指定する。
候補の特性は提示時に固定し、加入時にその内容を引き継ぐ。画面の開き直しで変わらない。

既存セーブの所属猫へ自動で付与しない。以前のセーブに既に提示されている候補にも後付けしない。
旧ゲームでも、更新後に初めて候補を提示した場合、その新しい候補には特性が付く。
テスト猫追加・共用関係データの猫登録は変更せず、通常の新規ゲームと新たな加入で導入する。

## 適用時点と対象外

### 接客・休養

疲労とストレスは従来どおり閉店時に一度だけ更新する。特性を持つ猫の当日接客行動数に基づいて計算する。
出勤予定だけで接客しなかった猫は、疲労・ストレス増加なし。休養予定の猫は在店している場合だけ回復する。
のんびり屋の疲労回復は在店の療養中にも適用するが、療養日数そのものを短縮しない。
派遣中・行方不明・譲渡済みの猫に、在店休養の特性効果を適用しない。

疲労の更新後に従来の発症判定を行うため、疲労増加の短所は発症リスクにもつながる。
出勤・休養画面の予測も同じ特性係数を使う。出勤の予測は従来どおり前日の接客量に基づく目安。
のんびり屋のストレス回復量は通常どおり20で、疲労回復だけが1.5倍になる。
[休養スペース](HumanToCatRestEquipment.md)を購入した場合は特性倍率の計算後に疲労回復＋10。基礎回復20なら、のんびり屋は30＋10＝40回復する。設備の追加回復量には特性倍率を掛けない。

プレイヤー交流によるストレス増減、体力の消耗・翌日回復、好感度の反応、人気獲得条件は今回変更しない。

### 派遣

派遣先ごとの条件・必要な余剰猫・日数は[派遣仕様](HumanToCatCafeActivities.md)に従う。報酬は派遣先の基本額に猫の倍率を掛ける。
帰還・報酬の受け取りで、資金とストレスを一度だけ反映する。
受け取り前に閉店・休業・保存を行っても、報酬と帰還ストレスを先に適用しない。
同じ帰還を再操作しても二重適用しない。ゲームオーバー後は受け取り不可。

ストレスは経営ルールが有効な場合にだけ扱う。帰還確定時に未導入ならストレスを加えず、後から遡及適用もしない。
出発後、帰還確定までに経営ルールを有効にした場合は帰還時の増加を適用する。
出発確認には現在の経営ルールでの報酬・ストレス増加を表示し、帰還確認待ち一覧にもその時点の効果を表示する。

今回の＋10は派遣帰還時の負担。派遣中にランダムで家出する機能ではない。
帰還直後に家出を抽選する処理も追加しない。以後の家出は従来の「在店で接客した日の閉店・ストレス80以上」の条件に従う。

## 表示・保存・再現

- 猫の詳細に特性名と全ての補正を表示する。特性のない猫は「なし」。
- 保護猫候補の一覧に特性名、詳細に効果を表示し、受け入れ前に判断できるようにする。
- 派遣画面の猫一覧にも特性名を表示する。派遣前の確認・帰還一覧は補正後の報酬を表示する。
- 帰還時のストレス増加を営業ログに記録する。営業一覧のストレスにも反映する。

営業セーブ形式2・チェックポイント1へ任意の `traits` を追加する。
特性を持つ猫IDごとに名前・係数を保存する。候補にも任意の `trait` を保存する。
共用の関係ファイルの構造は変更せず、特性はその営業の猫の状態として保持する。
設定ファイルを変更しても、初期猫はゲーム開始時、候補は提示時の特性を使い続ける。
既存の任意拡張がないセーブは特性なしとして復元し、旧リプレイの結果も変更しない。

リプレイ4に初期特性の設定操作を追加する。加入猫は既存の候補提示・加入操作に保存された特性を引き継ぐ。
疲労・ストレスは閉店操作から、派遣の成果は帰還操作から再現する。
派遣イベントの基本報酬と保存済みの特性から実収入を計算し、営業セーブの所持金・日次収入も同じ計算で照合する。
加入済みの特性が候補と異なるセーブや、不正な係数・対象猫は拒否する。

特性の付け替え・育成による獲得、複数特性の併用は後続。接客好き・外出好きを条件とする派遣先は実装済み。
