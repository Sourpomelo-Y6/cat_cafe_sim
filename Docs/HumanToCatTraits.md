# 猫の特性：初回仕様

更新日：2026-10-01 / 状態：マイペースを含む6種類を実装済み

接客・休養・派遣の担当選びに猫ごとの差を出す、常時適用のパッシブ効果。
既存の「個性」は遊びの種類・強さ・飽きやすさ等の好みであり、今回の「特性」と別に保持する。
数値は全体の流れを確認する暫定値。細かなバランス調整や家出のランダム化は今回行わない。

2026-09-22追記：[お客さんの特性・猫の特徴と相性の案](HumanToCatCustomerPreferencesPlan.md)で区分と複数保持を検討し、[特徴と好みの初回仕様](HumanToCatCustomerPreferences.md)を実装。猫の特性は本書の最大1つを維持し、特徴とは別に扱う。

## 種類と効果

1匹につき特性1つ、または特性なし。特性を持たない猫は従来どおりの係数で処理する。

| 特性 | メリット | デメリット |
|---|---|---|
| 接客好き | 接客によるストレス増加が通常の0.5倍 | 接客による疲労増加が通常の1.25倍 |
| のんびり屋 | 在店での休養・休業による疲労回復が通常の1.5倍 | 接客による疲労増加が通常の1.25倍 |
| 体力自慢 | 接客による疲労増加が通常の0.75倍 | 在店での休養・休業による疲労回復が通常の0.75倍 |
| 働き者 | 接客による疲労増加が通常の0.75倍 | 接客によるストレス増加が通常の1.25倍 |
| マイペース | 接客によるストレス増加が通常の0.75倍 | 在店での休養・休業による疲労回復が通常の0.75倍 |
| 外出好き | 派遣の資金報酬が通常の1.25倍 | 派遣帰還を確定したときストレス＋10 |

元設定は [cafe_traits.json](../config/cafe_traits.json)。効果は基礎ルールに掛け合わせる。
例：現在の基礎ルールなら、接客好きの接客1行動はストレス＋0.5・疲労＋1.25。
のんびり屋の在店休養は疲労30回復。体力自慢は接客1行動で疲労＋0.75、在店休養で疲労15回復。外出好きの近所への派遣は報酬125・帰還時ストレス＋10。
小数は整数に丸めず保持し、疲労・ストレスの既存の下限0・上限100で切り詰める。

## 初期猫と加入候補

新規ゲームの初期猫：

| 猫 | 特性 |
|---|---|
| ミケ | 接客好き |
| タマ | 外出好き |
| ソラ | なし |
| コハク | のんびり屋 |
| ムギ | なし |

新たに提示する保護猫の候補：初回のハルは接客好き、リンは外出好き、ユキはのんびり屋。2回目のソラと4回目のフクは体力自慢。5回目のナギと6回目のチャイは働き者、6回目のシオンはマイペース。紹介元の18匹と巡回順は[受け入れ](HumanToCatRecruitment.md)を参照。初期猫のソラとは別の加入候補で、初期猫へ体力自慢を後付けしない。
割り当ては [cafe_new_game.json](../config/cafe_new_game.json) と [cafe_recruitment.json](../config/cafe_recruitment.json) で指定する。
候補の特性は提示時に固定し、加入時にその内容を引き継ぐ。画面の開き直しで変わらない。

既存セーブの所属猫へ自動で付与しない。提示済みのソラ・フクが接客好きなら、その特性を維持する。体力自慢は更新後に新しく提示する候補から利用できる。以前のセーブに既に提示されている候補にも後付けしない。
旧ゲームでも、更新後に初めて候補を提示した場合、その新しい候補には特性が付く。
テスト猫追加・共用関係データの猫登録は変更せず、通常の新規ゲームと新たな加入で導入する。

## 適用時点と対象外

### 接客・休養

疲労とストレスは従来どおり閉店時に一度だけ更新する。特性を持つ猫の当日接客行動数に基づいて計算する。
出勤予定だけで接客しなかった猫は、疲労・ストレス増加なし。休養予定の猫は在店している場合だけ回復する。
のんびり屋の疲労回復は在店の療養中にも適用するが、療養日数そのものを短縮しない。
派遣中・行方不明・譲渡済みの猫に、在店休養の特性効果を適用しない。

疲労の更新後に従来の発症判定を行うため、疲労増加の短所は発症リスクにもつながる。
出勤・休養画面の予測も同じ特性係数を使う。出勤の予測は従来どおり前日の接客量に基づく目安。
のんびり屋のストレス回復量は通常どおり20で、疲労回復だけが1.5倍になる。
[休養スペース](HumanToCatRestEquipment.md)を購入した場合は特性倍率の計算後に疲労回復＋10。基礎回復20なら、のんびり屋は30＋10＝40回復する。設備の追加回復量には特性倍率を掛けない。体力自慢は15＋10＝25回復する。成長による休養の追加回復も特性倍率の計算後に加算する。体力自慢は療養中の在店休養にも適用し、療養日数は変更しない。

プレイヤー交流によるストレス増減、体力の消耗・翌日回復、好感度の反応、人気獲得条件は今回変更しない。

### 派遣

派遣先ごとの条件・必要な余剰猫・日数は[派遣仕様](HumanToCatCafeActivities.md)に従う。報酬は派遣先の基本額に猫の倍率を掛ける。
帰還・報酬の受け取りで、資金とストレスを一度だけ反映する。
受け取り前に閉店・休業・保存を行っても、報酬と帰還ストレスを先に適用しない。
同じ帰還を再操作しても二重適用しない。ゲームオーバー後は受け取り不可。

ストレスは経営ルールが有効な場合にだけ扱う。帰還確定時に未導入ならストレスを加えず、後から遡及適用もしない。
出発後、帰還確定までに経営ルールを有効にした場合は帰還時の増加を適用する。
出発確認には現在の経営ルールでの報酬・ストレス増加を表示し、帰還確認待ち一覧にもその時点の効果を表示する。

今回の＋10は派遣帰還時の負担。派遣中にランダムで家出する機能ではない。
帰還直後に家出を抽選する処理も追加しない。以後の家出は従来の「在店で接客した日の閉店・ストレス80以上」の条件に従う。

## 表示・保存・再現

- 猫の詳細に特性名と全ての補正を表示する。特性のない猫は「なし」。
- 保護猫候補の一覧に特性名、詳細に効果を表示し、受け入れ前に判断できるようにする。
- 派遣画面の猫一覧にも特性名を表示する。派遣前の確認・帰還一覧は補正後の報酬を表示する。
- 帰還時のストレス増加を営業ログに記録する。営業一覧のストレスにも反映する。

営業セーブ形式2・チェックポイント1へ任意の `traits` を追加する。
特性を持つ猫IDごとに名前・係数を保存する。候補にも任意の `trait` を保存する。
共用の関係ファイルの構造は変更せず、特性はその営業の猫の状態として保持する。
設定ファイルを変更しても、初期猫はゲーム開始時、候補は提示時の特性を使い続ける。
既存の任意拡張がないセーブは特性なしとして復元し、旧リプレイの結果も変更しない。

リプレイ4に初期特性の設定操作を追加する。加入猫は既存の候補提示・加入操作に保存された特性を引き継ぐ。
疲労・ストレスは閉店操作から、派遣の成果は帰還操作から再現する。
派遣イベントの基本報酬と保存済みの特性から実収入を計算し、営業セーブの所持金・日次収入も同じ計算で照合する。
加入済みの特性が候補と異なるセーブや、不正な係数・対象猫は拒否する。

特性の付け替え・育成による獲得、複数特性の併用は後続。接客好き・外出好きを条件とする派遣先は実装済み。体力自慢は新規ゲームの[猫の運動教室](HumanToCatExerciseDispatch.md)へ派遣できる（人気120以上・派遣報酬1回受取で解放、疲労40以下、2日・基本報酬300）。

## 働き者（2026-10-01）

特性IDは `hardworking`。接客疲労0.75倍・接客ストレス1.25倍、在店休養の疲労回復と派遣資金報酬は通常の1倍、派遣帰還の追加ストレスは0です。体力自慢と同じ接客疲労軽減を持ちますが、休養の回復量を維持する代わりに接客ストレスが増えます。小数を保持し、疲労・ストレスの既存の上限・下限を維持します。プレイヤー交流・健康判定・療養日数・体力のルールは変えません。

既存の初期猫・保護猫12候補の割り当ては維持し、紹介元の5回目のナギ（中立・黒猫／短毛・費用200）に導入します。紹介は3匹単位のため、同じ回にミント（遊び好きで繊細な猫・白黒／長毛・のんびり屋）とレオ（活発な探検家・キジトラ／短毛・接客好き）を追加し、紹介元を15匹とします。最初に1日目に候補を開いて3日ごとに追加した場合は13日目に登場します。

提示時に特性の名前・効果を固定します。旧セーブの所属猫・提示済み候補へ自動付与せず、新たに提示する紹介回から新しい巡回を使います。4回で巡回していた旧ゲームも更新後の新しい候補追加は5回の巡回になり、過去の提示回・候補・加入記録は再生成しません。提示・受け入れ後の保存再開と詳細リプレイは保存された特性を使い、現行設定を読み直しません。保存形式を変更しません。

特性の詳細説明、保護猫の一覧・条件絞り込み、加入後の猫詳細、出勤予測は既存の特性処理で対応します。[追加テスト](../tests/test_cafe_hardworking_trait.py)で効果と小数、通常休養・設備回復、予測の副作用なし、派遣中の休養除外・報酬維持、5回目の紹介と初期割り当て維持、受け入れ失敗後の再試行・二重加入防止、設定固定の保存再開・詳細リプレイ、旧4回巡回ゲームの既存候補維持、候補の絞り込みと長所・短所表示を確認します。

検証結果：追加６件はGUIを含め成功（0.506秒）、GUIを含む全997件成功（226.488秒）。ローカルリンク968件と差分チェックも成功しました。


## マイペースと６回目の紹介（2026-10-01）

特性IDは `easygoing`。接客ストレス0.75倍・在店休養の疲労回復0.75倍、接客疲労と派遣報酬は1倍、帰還時の追加ストレスは0です。標準の接客1行動はストレス＋0.75・疲労＋1、在店休養の疲労回復は20×0.75＝15です。ストレスの休養回復は通常どおり20で、防音改修があれば固定10を加算します。数値は暫定です。

疲労回復へ特性倍率を掛けた後、休養設備と成長の追加回復を加えます。通常の休養設備があれば15＋10＝25回復します。小数・上下限を維持し、療養中にも疲労回復倍率を適用しますが、療養日数は短縮しません。派遣中・行方不明・譲渡済みの猫には在店休養を適用しません。プレイヤー交流、体力と好感度の効果は変更しません。

紹介元の６回目にシオン（距離を大切にする猫・白猫／短毛・マイペース）、ルナ（穏やかな甘えん坊・茶トラ／長毛・外出好き）、チャイ（遊び好きで繊細な猫・三毛／長毛・働き者）を追加。費用は各200、紹介は3匹ずつ3日間隔を維持します。18候補・6回で一巡し、初日に開いて3日ごとに紹介すれば16日目に登場します。

初期猫・所属猫・既存15候補の割り当ては維持します。旧ゲームでも新しく提示する回から6回の巡回を使用し、提示済み候補・加入履歴を再生成しません。既に旧巡回の６回目を提示済みなら、その候補は維持し、以後の新しい回を6回巡回で選びます。特性と候補は提示時に固定し、保存再開・詳細リプレイで現在の設定を読み直しません。保存形式は維持します。

予測、特性の詳細、候補の絞り込みと受け入れは既存の共通処理を使用します。[追加テスト](../tests/test_cafe_easygoing_trait.py)で小数効果、予測と実回復、設備加算、療養日数、派遣中の回復除外・報酬、６回目の提示と巡回、加入失敗後の再試行、設定固定、旧５回巡回の提示済み候補、保存と詳細リプレイ、不正な加入特性、GUIの絞り込み・効果・取消・加入・履歴表示を確認します。追加７件成功（GUIを含む0.699秒）。既存の働き者６件と受け入れ18件も成功しました。

マイペース追加後の全体検証：GUIを含む全1043件成功（243.771秒）。候補の組み合わせがペットショップと重ならないことも確認しました。

マイペースは新規ゲームの[小さな美術館](HumanToCatMuseumDispatch.md)へ派遣できます。人気第２段階達成で解放し、健康・疲労40以下・２日・基本報酬350。来館者との交流を引き受けると報酬＋100・疲労とストレス各＋10で、専用イベントの負担に接客ストレス倍率は掛けません。
