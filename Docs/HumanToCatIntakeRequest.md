# 保護猫の受け入れ依頼イベント

新規ゲームの4日目の準備時に、保護猫「ナナ」の受け入れ依頼が一度だけ届く。営業後の翌日移行・休業のどちらでも発生する。日数・費用は暫定値とし、細かな調整は全体の流れが固まってから行う。

## 操作と結果

営業画面の案内欄の「確認する」、または「準備・お店」→「保護猫を迎える…」から依頼を開く。名前・個性・特徴・特性・初期費用と支払い後の所持金を確認し、「迎える」「見送る」を選ぶ。閉じただけでは回答を確定しない。

| 項目 | 初回内容 |
| --- | --- |
| 名前 | ナナ |
| 個性 | 穏やかな甘えん坊 |
| 特徴 | 白黒・長毛 |
| 特性 | のんびり屋 |
| 初期費用 | 200 |
| 加入時 | 健康・体力全回復・疲労0・ストレス0・好感度0・在店休養 |

迎える場合は、費用を払った後にも資金が残る必要がある。所持金と費用が同額の場合は迎えられない。費用は当日の「受け入れ費用」に合算し、既存の猫と同じく出勤・休養・派遣・プレイヤー交流などへ接続する。
見送る場合は費用・人気の変化なし。再依頼はしない。回答後は通常の候補画面の「依頼・回答履歴…」で結果を確認できる。

回答待ちは営業開始・翌日移行・休業・準備中の変更を止める。派遣帰還などの確認待ちや目標結果が重なる場合、先にそれらを解決してから依頼に回答する。ゲームオーバー後は加入できない。
通常の3日ごとの候補追加とは別の加入経路で、依頼の猫を通常候補に重複掲載しない。

## 保存と互換性

設定は `config/cafe_intake_request.json`。新規ゲーム作成時に発生日・猫ID・個性・特性・特徴・費用を固定し、任意項目 `intake_request` に保存する。状態は未発生・回答待ち・受け入れ済み・見送り済みとし、発生日・回答日も保持する。
既存セーブには依頼を後付けしない。読み込みや画面の開き直しで加入・請求を実行しない。回答済みの同じ回答は何も変更せず、別の回答への変更は拒否する。
受け入れは関係データの登録成功後に営業状態へ反映する。書き込み失敗時は未回答のまま残り、再試行で加入・費用を重複適用しない。

## 初回の範囲と検証

固定日・固定1匹の依頼で、一連の流れを確認する。ランダム発生、依頼の期限、複数依頼、スカウトのサブゲームは後続。
営業・休業からの発生、受け入れ・見送り、進行停止、資金不足、帰還との同時発生、保存再開・リプレイ・二重回答・書き込み失敗・旧セーブ互換をテストする。GUIでは案内からの回答・回答履歴・最小サイズでの操作ボタン表示を確認する。
