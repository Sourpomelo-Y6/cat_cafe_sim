# 猫の詳細画面：初回実装と後続計画

更新日：2026-09-20 / 状態：現在状態・相手別親しみ・日次実績の閲覧を実装済み

[全体の流れと実装順](HumanToCatGameFlowPlan.md)の最初の機能として、[ユーザー案の猫別パラメータ・行動履歴](HumanToCatPlannedFeatures.md)を段階的に実現する。
初回は現在ある情報を確認する画面とし、派遣や新しい能力の実装を前提にしない。

## 開き方と操作

通常営業の猫一覧で猫を選び、一覧右側の「猫の詳細…」から開く。猫一覧に選択がない場合は担当猫の選択欄の猫を開く。
画面上部で猫を切り替え、「状態・個性」「お客との親しみ」「日次実績」のタブを使う。
開くと自動進行を止め、閉じた後も一時停止を維持する。準備中・営業中・閉店後とも閲覧可能にする。
表示する猫を切り替えられ、閲覧だけでは担当・出勤予定・親しみ・資金・日付を変更しない。
出勤変更は既存の出勤・休養画面で行う。詳細画面で個性や数値を編集する機能は初回に含めない。

## 初回に表示するもの

| 領域 | 内容 | 主な既存データ |
|---|---|---|
| 基本情報 | 名前、猫ID、個性と好み | 営業セッションの登録情報と個性設定。未登録はIDと使用中の既定個性を区別して表示 |
| 現在の状態 | 体力、疲労、健康／療養残日数、出勤／休養、交流中などの担当可否 | 営業中の猫と既存の出勤・交流状態 |
| お客との関係 | 客ID別の確定済み親しみと段階 | 関係保存データ。交流中の見込みや未保存結果と混同しない |
| 日次の活動実績 | 日番号、営業／休業、出勤／休養、接客件数・行動数、体力消耗、疲労・体調変化、親しみ増減 | 日次結果と既存の比較用集計 |

日次実績は閉店済みの記録を対象にする。営業中の今日を確定済みとして混ぜず、現在状態と分ける。
初日で実績がない場合は「記録なし」と表示し、記録がない値を0として補わない。親しみの未交流時の0と、履歴欠落も区別する。
履歴の親しみ増減合計を、特定のお客への現在の親しみとして表示しない。
未保存の交流成果がある場合は既存の保存再試行が必要な旨を表示する。

## 行動履歴は段階を分ける

初回の日次実績は「いつ出勤・休養し、どれだけ接客したか」を確認するためのもの。
「何時に誰へどの種類の行動を実行し、どんな反応だったか」という毎行動の履歴とは異なる。
[軽量セーブ](HumanToCatCompactSaves.md)は確定済み交流の成果と日次集計を保持するが、過去の全行動列は保持しない。
そのため、初回の日次表示だけでユーザー案の行動履歴がすべて完成したとは扱わない。

詳細履歴の後続実装では、猫ID、日・時点、行動、相手や派遣先、結果、確定／未確定を区別する。
保持件数・期間・詳細ログとの役割分担・セーブへの追加方法を先に決める。保存再開後に存在しない過去の行動を集計値から推定して作らない。
イベント基盤で派遣・交流・家出などの記録を追加するときも、既存の成果保存と二重計上しない。

## 後続機能への拡張

派遣先・帰還予定、家出による不在、譲渡済み状態、プレイヤーとの好感度、ストレス、特性は、対応する機能が実装された段階で表示を追加する。
現段階で未導入の値を0や「特性なし」と表示し、ゲーム内に存在するようには見せない。
子猫は外部への引き渡し・譲渡費用だけを扱う方針なので、猫一覧や詳細画面の対象として作成しない。

## 初回の完了条件

- 猫を切り替えると、現在状態・相手別関係・日次実績がその猫の情報になる。
- 閲覧・切り替え・閉じる操作で営業状態や保存ファイルを変更しない。
- 保存再開後も、セーブに残る日次実績を同じ内容で確認できる。旧データの欠落を明示する。
- 健康／療養、出勤／休養、交流中、初日、休業日、未保存成果がある場合を区別できる。
- 頭数・日数・相手が増えてもスクロールで閲覧でき、小さい画面でも閉じる操作と一覧を使える。
- 通常営業の担当選択や出勤設定、自動進行の停止・再開を壊さない。

[日次比較](../cat_cafe_sim/cafe_history.py)の表、[営業セッション](../cat_cafe_sim/cafe_interaction.py)の日次結果、[関係保存](../cat_cafe_sim/storage/relationships.py)の既存データ取得を再利用している。
セーブ形式・ゲームルールは変更していない。詳細な毎行動履歴と、未導入のパラメータは後続の計画として残す。


## 表示と検証

日次実績は保存されている項目を使い、旧データに接客件数・行動数・疲労・体調などの項目がない場合は「記録なし」と表示する。
お客は関係データと現在・過去の来店で分かるIDを対象にする。その猫との交流記録がない相手は親しみ0・未交流とし、保存済みの交流後に親しみが0の相手と区別する。
表は縦横スクロールできる。未登録猫は猫IDと営業で使用する既定個性を表示し、閲覧だけで新たな関係ファイルを作らない。
未保存成果があると案内を表示する。日次の親しみ増減は営業で会計済みの結果であり、お客別の保存済み親しみとは別に扱う。

表示データは `cat_cafe_sim/cafe_cat_details.py` で読み取り専用に組み立てる。欠落した旧履歴を0として補完しないため、日次結果を直接参照して項目の有無を判定する。
既存の日次比較画面のスクロール付き表と、体調・親しみ段階の表示関数を共用する。

検証項目：猫別表示、初日、未登録、療養・休養、休業日、旧項目の欠落、未保存成果、軽量セーブ再開後の一致、閲覧時の状態・ファイル非変更。
GUIでは選択した猫での表示、切り替え、一時停止の維持、500×400での各タブと閉じるボタンを確認した。

検証結果：全体テスト300件中268件成功、GUI32件スキップ。GUI有効での画面テストファイル35件も全件成功（通常テスト3件を含む）。
