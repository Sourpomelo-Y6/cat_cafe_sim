# 未着手機能と検討事項

更新日：2026-10-01 / 状態：後続候補。実装順・未指定の数値は未確定

実装済み機能は[全体計画](HumanToCatGameFlowPlan.md)へ集約しました。本書には初回範囲を超える候補だけを残します。原案の「未決定」は当時の状態なので、現在の未着手項目とは区別します。ユーザーの提示案・修正と当時の論点は[整理前の記録](History/2026-09-30/HumanToCatPlannedFeatures.md)に保存しています。

## 開発方針

ゲーム全体の流れを先に固める方針を維持します。細かなバランス調整は従来後回しでしたが、現在は自動プレイと併せて調整したいという希望を下記に記録しています。人気目標・期限は長めの案を採用決定済みで、その他の調整範囲・数値は未確定です。スカウトはユーザー指定で低優先度です。人気目標の自動プレイCLI初版と日本語ログは実装済みです。テスト用実行・日本語ログ・GUIのおまかせ操作は[自動プレイ計画](HumanToCatAutoPlayPlan.md)を参照してください。次に着手する機能はユーザーの依頼に沿って決めます。

子猫は個体管理せず外部への引き渡し費用のみ扱い、6匹目標へ算入しません。お詫び費用は採用しません。通常接客のコマンドは自動で、プレイヤー交流とは別です。

## エンディングまでの自動プレイ

ユーザーはテスト用自動プレイの導入、実行内容の可視化、将来のGUIで約10日まとめて進める機能を希望しています。[会話整理と設計案](HumanToCatAutoPlayPlan.md)にまとめました。人気目標のCLI初版は実装済みで、投資・予約を使うクリア方針も実装済みで、GUIの最大10日進行も実装済みで、好感度・有力者のCLI検証経路も実装しました。その他の派遣・加入やGUIの対象拡張は後続です。

初版の対象は人気3段階の最終結果です。有力者・猫6匹の好感度を達成するCLI操作経路を追加しました。[対象別の検証](HumanToCatAutoPlayObjectives.md)を参照。複数シード比較と数値調整は後続です。資金・人気のゲームオーバーは初版でも終了理由として扱います。

初版の単純な方針を `basic`（基礎営業）として維持し、`clear`（安定経営）と `fast`（積極経営）を実装しました。同じ通常設定・シード0で安定経営41日、積極経営39日で人気3段階を達成し、基礎営業は20日目に人気230で期限切れとなりました。人気条件・期限・保存形式は維持しています。[10シード比較](HumanToCatAutoPlaySeedEvaluation.md)も実施済みで、店舗イベントの回答順を修正して同じ10シードを再評価しました。数値調整は後続です。[経営3方針と比較結果](HumanToCatAutoPlayPolicies.md)を参照してください。

必勝を初回要件とせず、一定日数内の正常な終了、進行不能の検出、終了理由の報告、途中保存・再開での結果一致を検証する案です。通常の自動接客や100日比較と役割を分けます。

## 自動プレイを使ったバランス調整

2026-10-02の相談では、人気目標・期限は現在の設定を維持する方針。第2段階の追加シード評価や期限変更は今回着手せず、GUIのおまかせに判断一覧と理由全文の表示を追加しました。期限日に一括判定する案や物語の追加も、この相談だけで採用済みとは扱いません。

クリア時間を延ばす相談に沿って、必要人気と期限を一緒に増やす[比較評価](HumanToCatPopularityDurationEvaluation.md)を追加しました。ユーザーの指示により、長めの案（人気250→450→650、期限20→20→25日、人気上限650）を採用決定しました。通常の新規ゲームへの反映まで実装しました。他モードからの途中挑戦は新しいゲームで長めの案を使い、旧上限300のゲームは従来の挑戦を使います。旧セーブに保存された目標・期限・上限を維持します。

ユーザーは自動プレイに加えてバランス調整も希望しています。通常設定・シード0の5条件で資金・人気・達成日数・猫の負担・設備支出を比較し、[予備評価と調整候補](HumanToCatAutoPlayBalanceEvaluation.md)を記録しました。まず出勤猫数に応じた増設判断の比較を優先する案です。新規加入・派遣や複数シードでの比較は後続です。具体的な難易度や調整範囲は未確定で、人気目標・期限・上限以外の数値は変更していません。[自動プレイ計画](HumanToCatAutoPlayPlan.md)に希望と検討案を記録しています。

## 追加時の共通確認

準備で判断し、一日を進め、結果を確認して次の配置へつなげる経路を確認します。選択待ちの保存再開、同じ猫への二重配置、費用・報酬・健康更新の重複、終了後の進行制限、旧セーブと詳細リプレイの互換を維持します。検証後に関連仕様と引き継ぎを更新し、コミットは別途依頼を受けて行います。
