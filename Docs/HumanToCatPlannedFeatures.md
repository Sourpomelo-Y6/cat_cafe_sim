# 実装予定機能案：派遣・猫との関係・イベント・クリア目標

記録日：2026-09-20 / 出典：ユーザー提示案 / 状態：実装予定の機能案、詳細仕様は未確定

[ゲーム全体の流れ](HumanToCatGameFlowPlan.md)を具体化するために追加された案を記録する。
以下の「提示された内容」はユーザーの案。「未決定事項」は実装前に整理する点であり、今回追加で決めたルールではない。
各機能は未実装として扱う。追記された子猫の扱いと資金0の終了条件はユーザー指定として記録し、実装順・未指定の数値・発生確率はここでは確定しない。全体の流れを優先し、細かな調整を後回しにする開発方針を維持する。

## 1. 猫の派遣

### 提示された内容

席数の関係で店内の接客に余る猫を、条件の合った場所へ派遣する。
派遣によってお金やアイテムなどを取得する。店内の席に入れない猫にも役割を作る。

### 未決定事項

- 派遣先の条件と、条件判定に使う猫のパラメータ・特性。
- 派遣を指示できる時点、期間、人数、帰還や中断の扱い。
- 店内接客・休養・療養と派遣の両立可否、疲労やストレスへの影響。
- 報酬の決め方、取得アイテムの保管・使用・売却などの用途。

有力者の家への派遣はクリア案（2）、派遣中の出来事はイベントシステムと接続する。

## 2. 各猫のパラメータ表示と行動履歴

### 提示された内容

各猫のパラメータを確認できる表示を作る。
その猫に実行してもらった行動の履歴を確認できるようにする。

### 未決定事項

- 体力・疲労・好感度・ストレス・特性など、表示する項目と公開範囲。
- 接客の個々の行動、派遣、プレイヤーとの遊びなど、履歴に含める行動の範囲。
- 日付、相手、場所、結果などの履歴項目と、詳細表示・日次要約の分け方。
- 保存件数や保持期間。既存の軽量セーブを踏まえた履歴の保存方法。

既存の営業中の猫一覧・日次結果・交流ログを土台にするが、猫別にまとまった新機能として整理する。

## 3. 保護猫譲渡とプレイヤーとの交流

### 提示された内容

好感度がかなり上がった猫とお客さんの組み合わせがある場合に、その猫をお客さんが引き取るイベントを発生させる。
対抗・予防する手段として、準備中や休みのときに、プレイヤーが猫と決まったターン数遊べるようにする。
プレイヤーとの好感度も上げ、お客さんとの関係に対抗できるようにする。

**この引き取りイベントが発生するかどうかを切り替えられるようにする。**

### 未決定事項

- 発生条件となる好感度の向き・閾値。現行の「猫からお客への親しみ」と同一にするか。
- プレイヤーとの好感度の管理方法と、お客さんとの好感度を比較する規則。
- 「休み」が猫の休養日、店の休業日、別の休憩時間のどれを指すか。
- 遊べるターン数・頻度・行動内容と、時間経過や体力・疲労への影響。
- イベント発生から譲渡までの手順、確認・拒否・選択の有無、譲渡後の所属や履歴の扱い。
- 発生切り替えの初期値、変更できる時点、発生済みイベントへの影響。

切り替えの対象として指定されたのは引き取りイベント。家出や他のイベントも一括で無効になるとは決めない。
プレイヤーとの交流を追加する案は、通常営業でプレイヤーが接客コマンドを選ばない既存の役割分担とは別に扱う。

## 4. 家出・行方不明と子猫の預け先・譲渡費用

### 提示された内容

派遣時のイベントや、ストレスなどが溜まりすぎたことをきっかけに、猫が一定期間出て行ってしまうイベントを作る。
時々、子猫を連れて帰ってくることがある。
子猫はほかのところに預ける・譲渡したものとして、資金が減るだけの処理にする。
カフェの猫と同様に管理すると煩雑になるため、子猫を所属猫として登録せず、個別の能力・好感度・出勤・育成・継続的なお世話の管理は追加しない。クリア案（3）の22匹にも数えない。

また、猫を過酷な状況に置くと家出が多くなる案を追加する。家出時には店の人気を下げ、人気が下がりきった場合のゲームオーバーへつなげる。

### 未決定事項

- 発生のきっかけ、ストレスの蓄積・解消方法、疲労との区別。
- 不在期間、帰還の条件、捜索や予防の手段の有無。
- 不在中の出勤・派遣・交流・所属頭数の扱い。
- 子猫を連れてくる条件と、預け先への引き渡し・譲渡に伴う費用の額・精算タイミング。
- 過酷な状況の判定、家出の増え方、家出時の人気減少量。

ストレスを既存の疲労と同じ値にすることや、永久に戻らなくなることは今回の案から確定しない。

## 5. イベントシステム

### 提示された内容

ゲーム内のイベントを扱うシステムを作る。

### 未決定事項

- 発生条件、発生タイミング、対象の猫・お客・派遣先などの指定方法。
- 選択肢、結果、進行中の状態、再発の可否、複数イベントが重なった場合の順序。
- 営業・派遣・休業・日付進行との接続、画面表示と履歴・セーブへの記録。

派遣中の出来事、引き取り、家出・帰還、子猫の預け先・譲渡費用を、この仕組みに接続する対象として整理する。
既存の営業ログのイベント記録だけで、これらのゲームイベントが実装済みとは扱わない。

## 6. 猫の特性

### 提示された内容

猫ごとに、メリット・デメリットがあるパッシブスキルとしての特性を持たせる。

### 未決定事項

- 特性の種類・効果・保持数と、ひとつの特性に長所と短所を併せるか、別々の特性として持たせるか。
- 初期付与・後天的な取得や変化の有無。
- 接客、派遣、ストレス、関係、イベント条件などへの作用。
- 複数特性の重複・競合と表示方法。

現行の好み・個性とは区別して設計する。既存の個性プリセットをそのままパッシブスキルとみなさない。

## 7. ゲームクリア案

3案ともユーザー提示の候補として保持する。どれを採用するか、選択式にするか、併存させるかは未決定。

| 案 | 提示された内容 | 未決定事項 |
|---|---|---|
| （1）店の人気 | 店のパラメータとして人気ポイントを設け、日数制限内に目標値へ届いたらクリア。何段階かに分ける | 人気の増減要因、日数、段階ごとの目標と期限、未達時や最終達成後の扱い |
| （2）有力者への派遣 | とある有力者の家に猫を派遣して満足度を稼ぎ、一定値に達したらクリア。有力者は複数人いてもよい | 派遣条件、満足度の増減、対象人数、複数の場合の達成条件、期限の有無 |
| （3）好感度の高い猫22匹 | 好感度が高い猫の頭数を**22匹**にする | 誰との好感度か、高いとする閾値、同時に22匹必要か、所属・派遣中・行方不明・譲渡済みの集計対象（子猫は対象外） |

案（3）の好感度を、プレイヤーとの好感度と勝手に確定しない。22匹という目標頭数は提示された値として保持する。
案（2）の有力者満足度、案（1）の店の人気、猫と相手の好感度、既存の交流中の関心・テンションは別の概念として整理する。
100日検証の期間や既存の親しみ段階を、そのままクリア期限・達成閾値へ転用しない。

## 8. ゲームオーバー条件・案（ユーザー追記）

### 資金0によるゲームオーバー

**資金が0になったらゲームオーバーとする。** 子猫の預け先・譲渡費用に限らず、資金についての終了条件として扱う。
子猫を個別管理して支出を回避する仕組みは設けない。

未決定事項は、初期資金、支出が残高を超えたときの精算方法、判定タイミング、ゲームオーバー画面・再開方法。
残高を超える支出で0を飛び越した場合の扱いを仕様化し、判定漏れを防ぐ必要がある。
現行の既定初期資金は0なので、実装時は新規開始・旧セーブ移行時の扱いも合わせて決める。今回の資料更新では現行の営業を終了させる処理は追加しない。

### 家出と人気低下によるゲームオーバー案

子猫の費用とは別の案として、次の流れを追加する。

**猫を過酷な状況に置く → 家出が多くなる → 家出時に店の人気が下がる → 人気が下がりきったらゲームオーバー。**

店の人気はクリア案（1）の人気ポイントと関連付けて仕様化する。下限の具体値は未指定のため、人気0と勝手に確定しない。
過酷な状況の条件、家出の発生規則、人気の減少・回復方法、初期人気、下限と終了判定のタイミングは未決定。
クリアとゲームオーバーの同時成立時の優先順位、各クリア案・モードへの適用範囲も実装前に整理する。
引き取りイベントのON/OFFで、家出やゲームオーバーまで無効になるとは扱わない。

## 9. 全体の流れとの接続

処理タイミング・猫の状態・更新した実装順は[全体計画の4〜6節](HumanToCatGameFlowPlan.md)を参照。初回の機能候補は[猫の詳細画面](HumanToCatCatDetailsPlan.md)。本書のユーザー案と、全体計画で補った処理順の提案は区別する。

以下は依存関係を整理したもので、実装順を確定するものではない。

| 場面・仕組み | 今回の案との接続 |
|---|---|
| 準備・猫の配置 | 店内接客・休養に加えて派遣先を選ぶ。プレイヤーと遊ぶ機会を設ける |
| 猫の情報 | パラメータ・特性・行動履歴を、配置や交流の判断材料にする |
| 営業・派遣の進行 | 資金・アイテムを得る。関係やストレス、イベントの結果を扱う |
| 結果・翌日 | 帰還・不在・譲渡・子猫の預け先への引き渡し費用など、猫の状態と資金の変化を次の判断へつなぐ |
| 長期目標・終了 | 人気、派遣先の満足度、好感度の高い猫の頭数の各クリア案に加え、資金0と家出による人気低下のゲームオーバーを整理する |

仕様化では、猫の所属と活動状態、相手別の好感度、派遣先と報酬アイテム、イベント進行、クリア進捗の保存範囲を整理する必要がある。
設備先行の従来案を見直し、猫の詳細画面から、活動状態・イベント基盤、派遣、プレイヤー交流と譲渡へ段階的に進める案に更新した。費用・人気低下は終了判定と合わせて導入し、全機能を一度に実装しない。
