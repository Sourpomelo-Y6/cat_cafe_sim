# 日次の店舗運営費

更新日：2026-09-29 / 状態：初回実装済み

## 目的

席の増設を売上増加だけで終わらせず、店を大きくするほど毎日の固定費も増える経営判断へつなげる。休業にも費用を設け、猫を休ませる必要と手元資金の両方を考える流れを作る。

## 初回ルール

新規ゲームでは、毎日の営業終了時または休業確定時に次の費用を1回だけ支払う。

`店舗運営費 = 基本費40 + 現在の席数 × 10`

| 席数 | 1日の運営費 |
| ---: | ---: |
| 2席 | 60 |
| 3席 | 70 |
| 4席 | 80 |
| 5席 | 90 |

金額は全体の流れを確認するための暫定値とし、細かな収支調整は後回しにする。営業日の売上が0でも全額を精算し、休業日にも同額を支払う。購入費、設備費、保護猫の受け入れ費、子猫の引き渡し費とは別に記録する。

精算後に資金が0以下になった場合は、既存の資金ゲームオーバーとする。運営費を免除する操作や後払いは設けない。

## 増設との接続

増設画面には現在と増設後の日次運営費を表示する。増設した席は購入当日から費用計算に含め、その日の閉店または休業時に新しい席数で精算する。増設購入費と運営費は同日に両方発生し得る。

## 表示・保存

- 閉店結果に当日の店舗運営費を表示する。
- 複数日の営業結果比較に「運営費」列を追加する。
- [日次収支](HumanToCatDailyFinance.md)の支出合計と純収支へ反映する。
- 営業ログに基本費、席数、席数分の費用、合計を表示する。
- 営業セーブには開始日、設定、日ごとの精算内訳を保存する。
- 保存再開、結果の再閲覧、翌日への移動で二重請求しない。
- 詳細リプレイでも有効化と各日の精算を再現する。

旧セーブは運営費なしの状態を維持する。新規ゲーム用設定から `operating_cost` を除いた検証用ゲームも従来どおり費用なしで動作する。

## 確認範囲

営業日、休業日、増設当日、資金0のゲームオーバー、日次結果、保存再開、詳細リプレイ、旧セーブ互換、設定・精算記録・会計の破損検出を確認する。
