# Unityから猫と交流する

2026-10-07。営業準備中に猫カードの「詳細」を開き、「猫と交流する」を選ぶ。猫との交流は既存のPython処理を使い、1日3セットまで、1セット最大10ターン。接客と体力を共有し、営業時間と資金は交流操作では進まない。体調・在店状況・イベント・本日の残り回数などで開始できない場合は理由を表示する。

交流画面には現在の動作の種類、残りターン、体力・関心・テンション、好感度の見込み、猫の反応の履歴を表示する。「動作を切り替える」では切り替え先を選択し、1ターンを使って変更する。現在の種類や特別な働きかけの条件に応じて、Pythonが認めた行動だけを有効にする。「このセットを切り上げる」で途中終了できる。自動終了と途中終了のどちらも、終了時に好感度を確定し、既存の好感度目標の判定に反映する。

「閉じる（途中状態を保持）」は交流を終了しない。猫詳細の「交流を再開」から再開する。「前回の交流を見る」ではその猫の直近の交流画面を開ける。交流中は営業開始と出勤・休養変更を無効にし、交流の終了または保存再開を先に行う。通信中・未接続時は行動や終了を無効にする。

画面上部の「保存」で途中状態または確定結果を保存できる。保存から再開すると交流画面も表示し、消費済みセット数・行動履歴・体力・好感度を復元する。読み取りだけでは交流を進めず、同じ送信要求の再試行では行動や交流回数を二重に消費しない。失敗した行動要求ではゲームを変更しない。

実Unity営業シーンに反映済み。Python状態サーバーを再起動し、営業シーンを再読み込みして確認する。開発用の再生成は `Cat Cafe/開発用/UI再生成/猫との交流`。配布用のUnityインストーラにも交流の実装と検証用スクリプトを追加した。

## 検証

既存のテストを含むUnity連携テスト26件が成功した。

`PythonPlayerVerification.Run` では検証用Unityプロジェクトと独立した8191番サーバーで、詳細画面の開始ボタン、動作切り替え、途中保存・復元、閉じて再開、途中終了、確定好感度、好感度目標の達成、結果保存・復元、結果確認後の営業再開が成功した。ログは制作ツールの `generated/player-play.log`、成功表示は `CAT_CAFE_PLAYER_PLAY_OK`。

表示と未接続などの操作制限は `PythonPlayerSetup.BuildAndVerify` で確認し、`generated/player-build.log` と実Unityプロジェクトでの `generated/player-actual.log` に記録した。画面画像は検証プロジェクトの `Logs/PlayerLive.png`、`Logs/PlayerResult.png` と、実プロジェクトの `Logs/PlayerInteraction.png`。

達成確認用の独立したゲームは好感度条件を「1匹・0.5」に下げる。通常の条件「6匹・80」やユーザーの保存データは変更しない。標準条件での長期のゲームバランス検証は含まない。

## 行動に対応する画像（2026-10-08）

交流画面の右上に猫の画像を表示する。ねこじゃらし・ボール・ぬいぐるみ・トンネル・なでる・ブラッシング・声かけ・見守りで切り替わり、「動きを止めて待つ」は専用の待機画像になる。強弱・フェイント・特別な働きかけは、下記の組み合わせ画像が未登録ならその種類の共通画像を使う。保存再開・前回結果も記録された最終行動から表示を復元する。

制作ツールの場面選択に交流別の画像を追加した。各場面でPNG登録、生成プロンプト編集、基準画像からの生成、ポーズLoRA設定ができる。新しい場面は画像を登録した場合だけUnityパックに含める。既存のプロンプト設定は読み取り時に追加場面の初期値を補い、保存済みの設定を維持する。紹介文・文章編集とLLMの4場面形式は従来どおり。

専用画像がない場合、遊び系は「遊ぶ」、ブラッシングは「撫でられる」、声かけ・見守り・待機は「通常」へ戻る。代替もない場合は画像未登録と表示する。素材はゲーム猫IDに対応する制作猫IDで検索し、別の猫の素材は使わない。画像表示はターンを消費しない。新しい画像を使うには制作ツールでUnity向け書き出しを行い、パックを取り込む。

検証：制作ツール28件中20件成功、GUI依存8件はスキップ。交流のHTTPテスト2件成功（開始、種類切替、待機、保存・再開、結果復元の画像キーと素材猫IDを確認）。Unity 2021.3.45f1でコンパイルと `PythonPlayerLayout.BuildAndVerify` が成功し、遊び・ブラッシングの代替表示、素材なし時のクリア、操作制限を検証した。画面画像は実プロジェクトの `Logs/PlayerLayout.png`。利用可能なエディターがf1のため検証時に使用し、プロジェクトの指定バージョンは元のf2に戻した。追加場面の専用画像自体は未制作。

切り替え一覧の確認（2026-10-08）：全8種類から現在の種類を除いた7種類を送信することをHTTPテストで検証。Unityの一覧高さを180から280へ広げ、スクロールせずに7種類が見えることを `Logs/PlayerTargets.png` で確認した。

## 動作 × 行動の画像（2026-10-08）

制作ツールの「場面」で動作を選び、追加した「行動」で具体的な行動を選ぶ。例えば「ボール遊び」「フェイントを入れる」の画像キーは `ball__feint`。「動作の共通画像」を選ぶと従来の動作画像を編集する。行動選択にはその動作で使えるものだけを表示する。「心をつかむ」は実行条件を満たした時のための登録枠。全8動作で合計47組み合わせ。なでるは場面の「撫でられる」を使う。

PNG登録、基準画像からの生成、生成プロンプト、ポーズLoRA設定は組み合わせごとに独立する。外見とデザインLoRAは猫ごとに共有する。新しいプロンプトの初期値は旧設定に読み取り時に補い、既存設定を保つ。待機の初期プロンプトは各動作の道具などを残し、動きを止めた場面を指定する。紹介文・行動描写の編集およびLLMは従来の4場面を維持する。

Unityの表示は最後に実行した行動から決まり、選択しただけでは切り替わらない。開始時は動作の共通画像。「切り替える」は切り替え後の動作と `switch` の組み合わせ。途中終了・自動終了・保存再開・前回結果は最終行動の組み合わせを保持する。画像キーは交流ログから計算し、既存のセーブ形式は変更しない。

表示順は組み合わせ画像 → 動作の共通画像 → 従来の場面画像 → 通常画像。待機では従来の待機画像も動作共通画像の後に候補にする。PNGが欠落した場合も次の候補へ戻る。47枚全部を登録する必要はなく、登録した追加画像だけを書き出す。既存パックも利用できる。Python版の素材読み込みも拡張キーを受け付けるようにした。

検証：制作ツール30件がGUIを含め成功。実際のゲーム設定との47通りの一致、猫・組み合わせ別登録、不可能な組み合わせの拒否、PNGの重複排除と書き出し、旧プロンプトの移行、LoRA保存、GUIの2段階選択を確認。ゲーム側の交流HTTP2件と素材読込2件が成功。Unity検証では組み合わせキーの検証、組み合わせ画像の優先と未登録時の代替、既存画面動作を確認。新規の絵自体は制作していない。

## 心を開く・同時発生を特殊行動として登録（2026-10-08）

制作ツールの操作は「場面（動作）」と「行動」の2項目のまま。各動作の行動欄に追加する特殊パターンは「（なにか）+心を開く」「心をつかむ+心を開く」の2種類だけ。通常行動ごとに特殊パターンを増やさない。画像キーは動作IDに `__open_up` または `__simultaneous` を付ける（例：`ball__open_up`）。8動作すべてを用意する場合は猫ごとに最大16枚の追加画像になる。必要な動作だけ登録できる。

前者は同じ動作でどの通常行動の後に心を開いても使う。後者は心をつかむと心を開くが同じ行動記録で発生した場合に使う。動作の道具や姿勢を含む生成プロンプト、PNG登録、基準画像生成、ポーズLoRA、Unity書き出しに対応。特別反応だけを単独の場面として選ぶ方式は撤回した。

Unityの表示順は同じ動作の特殊パターン画像 → 実際に行った動作×行動画像 → 動作共通画像 → 既存場面画像。別の動作や旧共通の特別画像は使わない。最終行動記録の `open_up_source` と `connect_source` で判定し、選択しただけ・ゲージが高いだけでは変えない。心をつかむだけなら動作×connect画像を使う。次の行動で特別反応がなければ通常の画像へ戻り、結果・保存再開は最終行動の表示を復元する。

検証：制作ツール31件がGUIを含め成功。行動欄の特殊項目が2つであること、登録枠が16通りであること、登録・生成設定・LoRA・書き出しを確認。ゲーム交流3件で発生の区別と保存再読込を検証。Unityで動作別の特別画像優先、同時発生、未登録時の代替を確認。新規画像は未制作。
