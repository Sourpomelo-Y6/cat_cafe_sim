# アイテムの購入・派遣報酬と猫のケア

更新日：2026-09-30 / 状態：ケア用品・栄養おやつ・特製ケアセットの購入・使用・売却を実装済み。所持品・ケア画面からケア用品1個100、栄養おやつ1個150、特製ケアセット1個200で購入できる。価格は暫定。

## 初回仕様

新しく出発する「近所のお店への訪問」で、資金報酬に加えてケア用品を1個入手する。派遣出発時に報酬設定を固定し、帰還の「帰還・報酬を受け取る」で所持品に加わる。派遣中・帰還確認待ちの品は使えない。
商店街・郊外・有力者の派遣には今回はアイテムを追加しない。特性による資金報酬の倍率はアイテム個数にかけない。

| アイテム | 入手数 | 使用効果 |
| --- | --- | --- |
| ケア用品 | 対象の派遣1回につき1個。購入も可能 | 在店猫1匹のストレスを10下げる（最低0） |
| 栄養おやつ | 購入1回につき1個（費用150） | 在店猫1匹の疲労を15下げる（最低0） |
| 特製ケアセット | 購入1回につき1個（費用200） | 在店猫1匹の疲労とストレスを各10下げる（最低0） |

個数・効果量は暫定。細かな調整は全体の流れが固まった後に行う。

## 操作と使用条件

1. 「準備・お店」→「派遣・帰還を確認する…」で、出発前に資金・アイテム報酬を確認する。
2. 帰還したら報酬を受け取る。受取済みの同じ帰還を再度処理しても報酬は増えない。
3. 「準備・お店」→「所持品・ケア…」で、購入する用品・所持数・効果・対象猫のストレスと疲労を確認する。
4. アイテムと猫を選び、「選んだ猫に1個使う」で変化量を確認して使用する。
5. 画面に使用結果を表示し、「使用履歴」で日付・対象猫・品名・ストレス・疲労の変化を確認できる。

使用できるのは営業準備中。ケア用品はストレスを管理する経営ルール、栄養おやつは疲労を管理する出勤ルールが必要。未解決イベント・目標結果・進行中のプレイヤー交流・未保存の交流結果がある間は使えない。
対象は在店している猫。出勤・休養・療養中のいずれも使用できるが、病気を治す効果はない。派遣中・行方不明・譲渡済みの猫には使えない。
ストレス0の猫には使えず、品も消費しない。ストレスが10未満でも1個消費して0にする。ケア用品は体力・疲労・好感度・所持金を変えない。栄養おやつは疲労0の猫に使えず消費しない。疲労15未満なら1個消費して0にする。回復量は固定15で特性や休養設備の倍率・加算は適用しない。ストレス・体力・好感度・所持金・病気の状態と療養日数は変えない。
営業中・閉店中・ゲームオーバー後は閲覧のみ。帰還を閉店時に受け取った場合、翌日の準備で使える。

同じ名前・効果の所持品は画面上でまとめて個数を表示する。使用時はその中の未使用品を1個消費する。効果設定が異なる品は別の行で表示する。

## 保存・互換性

設定は `config/cafe_item_rewards.json`。各派遣イベントの任意項目 `item_reward` に、出発時の品名・種類・効果を保存する。保存再開時に現行設定を読み直して変更しない。
既に出発済みの派遣や旧リプレイには後付けしない。旧セーブでも、新しく対象の派遣に出発した分から入手できる。ストレス管理が未導入でも入手・所持でき、使用には経営ルールの導入が必要。

残数は「受取済みのアイテム報酬＋購入品 − 使用済みの品 − 売却済みの品」から算出する。別の残数台帳を作らず、帰還の重複受取による二重加算を防ぐ。
使用記録は任意項目 `item_uses` に、入手元の派遣ID・使用日・猫ID・変化前後を保存する。対象の状態は入手元の品の効果から判断し、既存ケア用品の記録形式を変更しない。栄養おやつ使用後は当日の閉店時の疲労計算の基準も更新し、営業・休業後に回復を取り消さない。各品は1回だけ使え、未受取品の使用や重複した使用記録を拒否する。詳細な交流ログや画面の開閉記録は追加しない。
使用後は通常の営業セーブで保存する。保存失敗時も使用結果はメモリに残り、保存の再試行では使用を繰り返さない。未保存の変更を破棄して以前のセーブへ戻る場合は、そのセーブ時点の状態に戻る。

## 検証と後続範囲

1席・2席、出発・帰還待ち・受取・使用後の保存再開、資金報酬との併用、重複受取防止、効果の固定、ストレス下限、対象外の拒否、旧派遣互換、保存失敗の再試行、不正な使用記録、詳細リプレイをテストする。
GUIでは所持数・効果・使用確認とキャンセル・使用履歴、メイン画面と所持品画面の最小サイズでの表示を確認する。
購入は下記の仕様で実装済み。さらに多くの種類・抽選報酬・所持上限は後続。今回、猫の個体数や子猫の扱いは変更しない。

2026-09-29に記録した方針（購入の初回機能は2026-09-30に実装済み）：まず準備中に既存のケア用品を資金で購入できる初回機能を優先する。購入費を日次収支、資金ゲームオーバー、保存再開、詳細リプレイへ接続する。種類の大量追加、価格調整、売却はその後とする。新規ゲームからエンディングまで進めるテスト用自動プレイは、この購入機能やほかの通常進行機能を先に揃えてから実装する。


## 3種類の用品の購入（実装済み）

「準備・お店」→「所持品・ケア…」で、購入する用品を選び、資金、価格、所持数、効果を確認して購入ボタンを押す。初期選択は従来どおりケア用品で、「栄養おやつ」を選ぶと1個150・疲労回復15を表示する。確認をキャンセルした場合は資金・在庫を変えない。購入した品は派遣報酬と同じ一覧にまとめ、在店猫へ使用できる。

購入は営業準備中のみ。未解決イベント、成長選択待ち、プレイヤー交流中、未保存の接客結果、資金不足、ゲームオーバー後は購入できない。資金が価格と同じ場合は確認時に案内し、購入後に資金0のゲームオーバーを適用する（経営ルール導入済みの場合）。

購入設定はケア用品が `config/cafe_item_shop.json`、栄養おやつが `config/cafe_nutrition_snack.json`。購入ごとに入手元ID、購入日、価格、効果を任意項目 `item_purchases` に固定し、保存再開と詳細リプレイで維持する。旧セーブには購入記録を後付けせず、更新後の準備中から購入できる。購入費は日次収支の支出と複数日比較の「用品購入費」に含める。使用・購入後の保存再試行で在庫や費用を二重適用しない。

## 所持品の売却（実装済み）

準備中の「所持品・ケア」で所持品を選び、「選んだ用品を1個売却」を押す。ケア用品は50、栄養おやつは75、特製ケアセットは100（暫定）。確認画面に金額と売却後の所持金を表示し、取消では何も変更しない。猫を選ぶ必要はなく、猫の状態は変えない。同じ効果の品が複数ある場合は1個だけ売り、残数を更新する。

購入品・受取済みの派遣報酬・入手済みの店舗イベント報酬を売却できる。未受取・使用済み・売却済みの品は対象外。営業準備中だけ操作でき、未解決イベント・目標結果・プレイヤー交流・未保存の接客結果がある間や、営業中・閉店後・ゲームオーバー後は売却できない。ストレス・疲労の管理ルールは売却に必要ない。

売却履歴に日付・品名・金額、営業ログに売却と収入を表示する。日次・期間収支へ「用品売却収入」を別項目で加算し、購入費と相殺して隠さない。休業日に売却した分も当日の収入として精算する。

価格設定は `config/cafe_item_sales.json`。任意項目 `item_sales` に入手元ID・売却日・金額を固定保存する。営業セーブ形式2・チェックポイント1・詳細リプレイ4を維持し、旧セーブの入手・使用記録を変更しない。旧ゲームも準備中から明示的に売却でき、未操作なら売却記録・集計項目を後付けしない。保存再開・詳細リプレイは保存した金額を使い、価格設定を読み直して過去の収入を変更しない。

復元では入手済みか、使用記録と売却記録が重複しないか、売却日・金額、日次収入と資金の整合性を確認する。保存失敗後も売却結果を保持し、再保存・二重操作で在庫や収入を増やさない。

[売却の追加テスト](../tests/test_cafe_item_sales.py)で両用品と1席／複数席、購入・派遣・店舗イベント由来の品、未受取・使用済み・二重売却、確認待ち・未保存結果・営業中・閉店後・ゲームオーバーの拒否、猫を選ばず売却できること、営業・休業の日次収支と資金連続性、旧セーブ、固定価格と詳細リプレイ、保存失敗再試行、不正記録を確認する。GUIでは取消・同種在庫の1個消費・金額表示・売却履歴・営業ログ・期間比較、580×460の最小サイズを確認する。

売却追加後の検証結果：追加10件を含むGUI付き全810件成功（148.228秒）。ローカルリンク851件と差分チェックも成功。

## 特製ケアセット（実装済み）

購入候補の3番目から1個200で購入し、準備中に在店猫1匹の疲労とストレスを固定で各10回復する。使用には疲労管理とストレス管理の両ルールが必要。両方が0なら消費せず、片方だけが正の場合も1個消費してその値を回復する。10未満は0まで回復する。特性・設備の倍率や加算を適用せず、体力・好感度・病気と療養日数は変えない。疲労回復後は閉店計算の基準も更新する。

設定は[購入・効果設定](../config/cafe_special_care_set.json)。購入時の効果と価格を固定し、旧セーブも新しい購入操作から利用できる。既存2種類の効果・既定購入と記録を維持する。特製ケアセットの使用記録だけは `before` / `after` に `fatigue` と `stress` を持つ辞書を保存し、従来品の数値形式も引き続き読み込む。保存・再生では現行設定を読み直さない。使用済みの品は売却できず、未使用品を1個100で売却できる。

[追加テスト](../tests/test_cafe_special_care_set.py)で固定回復・片方だけの回復・両方0の拒否、特性の除外、出勤／休養と閉店基準、購入費と売却収入、対象と操作制限、資金境界、病気の維持、従来品の記録、保存失敗再試行、固定効果、保存・詳細リプレイ、不正記録を確認する。GUIでは購入・使用・売却の確認取消、両状態の変化・履歴・営業ログ・猫のできごと、異なる効果の在庫分離、最小サイズを確認する。

特製ケアセット追加後の検証結果：追加9件を含むGUI全890件成功（185.944秒）。ローカルリンク903件と差分チェックも成功。
