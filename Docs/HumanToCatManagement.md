# ストレス・家出・帰還と経営終了：初回仕様

更新日：2026-09-21

全体の流れを確認する最小構成。係数・期間・確率の細かな調整は後回しにする。
今回の家出は在店猫のストレスによるもの。派遣中のランダムイベント、有力者の満足度、人気による来客数変化は後続。
2026-09-22追記：[人気獲得と期限付き目標](HumanToCatPopularityGoal.md)を追加。目標導入後は人気上限300となり、接客分を閉店時に加算してから家出の損失・終了判定・クリア判定を行う。

## 導入と旧セーブ

2026-09-21追記：[通常の新規ゲーム](HumanToCatNewGame.md)では初期条件とともに経営ルールを有効化する。以下の手動導入は未導入の旧セーブと明示オプションで起動する従来の試遊に適用する。旧セーブの読込だけでは導入しない。

「派遣・イベント…」→「ストレス・家出・経営…」の「経営ルールを開始」で有効にする。
営業準備中に一度だけ開始でき、開始後は解除できない。プレイヤー交流中や未確認イベント、接客結果の未保存時は開始不可。
出勤・健康ルールのない旧セーブでは先に出勤設定を保存する。

従来の試遊の初期資金は0なので、明示オプションでの試遊と旧セーブでは自動導入しない。通常の開始画面から作る新規ゲームは資金1,000・経営ルール有効で始める。
未導入の営業にはストレス・家出・経営終了判定を適用しない。保存を読むだけで即ゲームオーバーにはしない。
明示的な開始時に、所持金が1,000未満なら不足分だけ補充する。既に1,000以上あれば増減しない。
これは経営ルール開始時の一度だけの資金で、売上ではない。金額と開始日を保存し、再開・再操作では補充しない。
新規開始画面と初期条件を統合済み。既存の店で任意に資金を復活できる救済操作にはしない。

設定元は [cafe_management.json](../config/cafe_management.json)。開始時の設定を営業セーブへ保存し、途中で設定ファイルが変わってもその営業には適用しない。

## ストレスと家出

2026-09-22追記：[猫の特性](HumanToCatTraits.md)導入後は、接客好きの接客ストレスを基礎値の0.5倍にする。外出好きは派遣帰還時に＋10。以下の表は特性補正前の基礎値。

ストレスは猫ごとに0〜100。開始時は全猫0。

| 場面 | 初回ルール |
|---|---|
| 在店・出勤日の閉店 | 接客行動数 × 1 を加算。出勤予定だけで接客しなかった場合は増減なし |
| 在店・休養／休業日の閉店 | 20減少。療養中も在店なら対象 |
| プレイヤー交流の終了 | 好感度の上限・下限に丸める前の反応合計がプラスなら5減少、マイナスなら5増加、0なら変化なし |
| 派遣・不在・譲渡済み | 店内の日次ストレス更新の対象外。派遣由来のストレスはまだ導入しない |

画面の開閉や保存では更新しない。行動せずにプレイヤー交流を切り上げてもストレスは回復しない。
好感度100でも反応合計がプラスなら回復する。

閉店時、在店でその日に接客した猫のストレスが80以上なら家出する。抽選はせず、条件成立で発生。
休養中の猫を、その日の家出判定には入れない。
既存の疲労・健康処理を行った後に判定する。療養中・体力切れになった場合も、接客実績があれば家出の対象になる。
同じ猫に譲渡の申し出が出ている場合は申し出を優先し、その日は家出させない。
見送った場合も閉店処理は再実行せず、翌日以降に再判定する。

家出した猫は「行方不明」とし、出勤予定から外す。接客・派遣・プレイヤー交流へ同時参加できない。
家出時に店の人気を20下げる。人気の初期値は100、下限0。複数の猫が同日に家出した場合も1匹につき一度ずつ下げる。
不在中の日数経過や、表示・保存・読み込みで再度減点しない。目標未導入の旧営業では人気の回復や接客による増加は扱わない。目標導入後は同仕様に従い加算する。

## 不在期間・帰還・子猫

家出した日は不在期間に数えず、その後2日分の閉店・休業を経て帰還確認待ちになる。
例：1日目の閉店で家出 → 2日目の閉店で残り1日 → 3日目の閉店で帰還確認待ち。
休業は既存仕様どおり翌日の準備へ直接進むため、3日目を休業した場合は4日目の準備で帰還を確認する。
確認待ちの間は次の営業・休業・翌日への進行を止める。

不在中は体力の翌日全回復、疲労回復、療養日数の進行を適用しない。
帰還の確定時に在店へ戻し、体力を全回復、ストレスを20にする。疲労と療養状態は保持する。
療養中なら接客不可のまま。在店へ戻った後の日次処理で療養を再開する。
出勤予定には自動で戻さず、次の準備で設定する。

帰還時に25%の確率で子猫を連れてくる。
猫ID・家出日・営業seedから得た抽選結果を家出イベントへ保存し、保存再開や画面の開き直しで抽選し直さない。
結果は帰還時に画面へ表示する。子猫は外部への預け入れ・譲渡として扱い、引き渡し費用250だけを精算する。
**子猫を管理対象の猫として追加しない。個性・育成・出勤・22匹目標の頭数にも追加しない。**

「帰還・費用を確定」で猫の帰還と費用を同時に一度だけ反映する。
確認ダイアログをキャンセルした場合は未解決のまま。費用だけを回避して次の日へ進むことはできない。
費用は確定した日へ計上し、過去の休業日の結果を書き換えない。
派遣帰還・譲渡・他の猫の帰還が重なった場合は一覧から個別に確認する。

## ゲームオーバー

経営ルール導入後、資金が0以下、または店の人気が0になったらゲームオーバー。
費用が所持金を超えた場合は負の残高を記録し、0を通過しても終了判定から漏らさない。
家出はその日の対象猫すべてを反映してから人気による終了を判定する。
子猫の費用は帰還確定の直後に判定し、後から他の報酬を受け取って復活することはできない。
両方が同時成立する場合は資金による終了を表示理由として優先する。

終了後は営業、翌日、休業、交流、派遣、イベントの新たな解決、設定変更を止める。
猫の詳細、営業比較、イベント結果、保存・読み込みと接客成果の保存再試行は利用できる。
未解決イベントが残っていても終了状態を優先し、そこからの進行を再開しない。
人気や資金の補充による終了取り消しは提供しない。新たに遊ぶ場合は新規営業を起動する。
「結果・再開始…」から終了結果を確認し、独立した新規ゲームを始める導線を追加した。人気目標のクリアは別仕様で実装済み。

## 2026-09-22：ストレスの可視化と暫定緩和

ユーザーから「2日稼働・疲労40で家出するのは早すぎる」と指摘があった。
以前は接客1行動につき疲労＋1・ストレス＋2で、回復なしの累計40行動でストレス80の家出条件に達していた。
疲労とは別の判定値が営業一覧に見えない問題もあった。

- 営業一覧に「ストレス」列を追加し、疲労と並べて表示する。経営ルール未導入の営業は「未導入」と表示する。
- 接客1行動あたりのストレス増加量を、暫定で＋2から＋1へ変更する。閉店時の加算方式は維持する。
- 家出条件80、休養による回復20、プレイヤー交流による増減は今回は変更しない。
- 0から始め、他の増減がなければ累計80接客行動で条件に達する。日数や回転数だけで判定するわけではない。

開始時のルールを保存する既存仕様を維持するため、新規ゲームと今後の経営ルール導入から＋1になる。
既に経営ルールを導入したセーブは、保存されている＋2等の値と累積ストレスを保持する。過去の履歴・発生済みの家出を自動で変更しない。

ユーザー案として「家出判定にランダム性を入れてもよい」を記録する。
今後はストレスに応じた家出確率、抽選する時点・頻度、予兆の表示を検討する。
今回は抽選を実装せず、80以上での確定発生を維持する。導入時は保存再開で再抽選されない方式を使う。
全体の流れを優先する開発方針は維持し、今回は早すぎる家出への暫定対応とする。
