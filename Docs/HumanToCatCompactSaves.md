## 原因と変更

旧形式は各操作に営業全体のスナップショットを持ち、その中に過去の全交流ログを繰り返し含めていた。
日をまたいで終了済み交流を保持するため、全員休養でも同じ過去データを毎tickコピーし、容量が急増していた。
保存・読み込み時の全操作リプレイも遅延の原因だった。

形式2は操作履歴をセーブから分離し、現在状態から直接復元する。

| 保存対象 | 内容 |
|---|---|
| 現在の営業 | 日・tick・資金・猫・席・待機列・来店と会計・出勤設定・疲労・病気・療養状態 |
| 過去の日次結果 | 売上、猫別接客件数・体力消耗・親しみ増減・疲労・体調変化 |
| 確定済み交流 | 成果、開始時の関係情報、元ログのSHA-256ハッシュ。各交流につき1件 |
| 進行中の交流 | 再開に必要な初期条件・行動列・ゲージ・予約等。各席の交流だけを再生検証する |
| 未保存の終了結果 | 関係保存の再試行に必要な完全な交流ログ。保存済みの結果には保持しない |
| 関係データ | 従来どおり保存先と照合用の状態。読み込み時に巻き戻さない |
| 表示用イベント | 当日の来店・会計・体調等。詳細な毎行動ログと前日以前のイベントは省略 |

確定済み交流の詳細ログは営業中の状態管理からも成果記録に置き換える。
新しい通常営業では、操作ごとの全状態コピーを保持せず、詳細ログ用の操作・イベント・状態ハッシュを記録する。
日次集計と適用済み交流IDの保持量は日数・交流件数に比例して増えるが、同じ履歴を毎操作で重複保存しない。

## 検証と安全性

- 保存時：直近操作の状態ハッシュと現在状態を照合し、操作を通さない変更を拒否する。
- 復元時：現在状態のチェックサム、猫と席、進行中交流、会計合計と所持金を検証する。
- 確定済み成果：関係データの適用済みID・ハッシュ・成果と照合する。過去の全交流を再生しない。
- 未保存成果：その交流を検証し、未適用の結果だけを再試行する。
- 古いセーブ：既知の未保存結果の適用以外に関係データが進んでいると、従来どおり再開を拒否する。
- 一時ファイルからの置換で保存する。失敗時は既存セーブを維持する。

チェックサムは破損検出用で、セーブの意図的な編集を防止する暗号署名ではない。
読み込み時は会計・親しみを追加反映せず、自動進行も開始しない。

## 旧セーブの読み込みと別名変換

旧営業セーブ形式1（内部ログ形式1〜3）も「続きから開く」で読み込める。
旧形式だけは操作ごとに再生検証し、読み終わった状態を軽量な現在状態に変換する。
全ファイルをPythonのオブジェクトとして展開せず、ファイルを参照しながら1操作ずつ読み進め、過去の操作スナップショットを保持しない。
初回は旧ログの検証に時間がかかる。次に「営業を保存」で形式2になり、それ以降は全営業リプレイを行わない。

元ファイルを残して変換する場合：

```bash
python3 -m cat_cafe_sim.cafe_interaction compact-save \
  saves/cafe_day_all_rest.json saves/cafe_day_all_rest.compact.json

python3 -m cat_cafe_sim.cafe_interaction gui \
  --resume saves/cafe_day_all_rest.compact.json
```

`compact-save` は元ファイルと関係ファイルを変更せず、新しい別名のファイルだけを作る。存在する変換先への上書きは拒否する。
変換時はセーブ内の関係情報で整合性を検証するため、現在の関係データより古いセーブも保存資料として変換できる。
ただし、変換しても古いセーブの再開制限は解除しない。関係データを巻き戻す処理は含めない。
形式2も別名へ変換できる。旧アプリは形式2を開けない。

## 詳細ログ

「営業ログを保存…」は、セーブとは別に詳細な再生ログを出力する。
形式4は現在の起点と、そこからの操作・イベント・状態ハッシュを保存する。
新規営業では開始時から、セーブ再開後は再開時の現在状態からの操作を再生できる。
再開前の細かな行動列はセーブから復元しない。必要なら終了・再開前に詳細ログを別途保存する。
再開前の売上・猫別成果・接客件数の比較は日次集計から引き続き利用できる。
旧詳細ログ形式1〜3の再生も維持する。

## 実測とテスト

実データを別名へ変換し、元ファイルは保持した（数値はファイルのバイト数）。

| 旧セーブ | 旧形式 | 軽量版 | 初回変換 |
|---|---:|---:|---:|
| cafe_day.json | 61,295,303 | 91,801 | 約7.7秒 |
| cafe_day_hirou_max.json | 437,265,993 | 176,035 | 約52秒 |
| cafe_day_all_rest.json | 1,154,924,053 | 246,007 | 約137秒 |

最大のファイルは約99.98％縮小。軽量版の14日目・0tick・資金13,690と、過去13日分の比較結果を確認した。
同環境で軽量版の読み込み約0.05秒・保存約0.045秒。再保存後の状態・日次比較・詳細ログ再生も一致した。
最初の2件は関係データが先へ進んでいるため、変換後も再開を拒否することを確認した。
環境や営業状態によって時間・サイズは変わる。

全営業リプレイを呼ばない保存・再開、片方の結果だけ未保存の再試行、破損・未記録変更・古いセーブの拒否を検証した。
