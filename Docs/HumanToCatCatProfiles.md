# 猫の名前・個性の登録と再会

更新日：2026-09-13 / 単独交流ルール版4・関係保存形式2

猫IDごとに名前と個性を保存する。登録済みの猫は、お客が変わっても同じ保存済み個性で交流する。
親しみは引き続き猫ID・客IDの組み合わせごとに管理する。

## 登録方法

1. 未登録の猫IDと、使いたい個性・開始体力を指定して「この条件で再開始」を押す。
2. 「現在の猫の名前」を入力する。初期値は猫ID。
3. 「現在の名前・個性で猫を登録」を押す。

登録対象は現在交流している猫と、その交流に適用済みの個性。「次の猫ID」や未適用の個性選択を登録する操作ではない。
登録ボタンを押さずに交流を進めた場合も、最初の結果保存時に入力した名前と交流時の個性を一緒に保存する。
結果保存が失敗した場合は名前・個性だけを先に書き込まず、従来どおり再試行できる。
明示的に登録ボタンで登録した猫は、その後に交流を破棄しても登録が残る。

登録後は名前欄と登録ボタンを無効にし、開始時の表示に名前・猫ID・登録状態を示す。
この初回実装では登録後の名前変更・個性変更・削除は提供しない。別の名前・個性で同じIDを再登録しようとすると拒否する。
同じ名前・個性での登録再試行はファイルを書き換えない。

## 再会と一覧

登録済みの猫の再会には保存済み個性を優先し、画面で選択した別の個性では上書きしない。
画面上の個性選択は、未登録の猫を次に開始するときに使用する。開始体力は従来どおり指定値を使う。
関係一覧には猫の名前とIDを両方表示する。未登録の猫の名前欄はIDを表示する。
猫を登録しただけではお客との関係は作られず、関係一覧には交流結果を保存した組み合わせが表示される。

登録の範囲は選択した関係保存ファイル内。同じIDでも別の保存ファイルへ登録内容は自動転送しない。
CLIでも登録済みの猫は保存済み個性を使う。未登録の猫の`--save-result`ではIDを名前として登録する。
再生ログには交流時の個性スナップショットを維持し、現在の猫登録情報で過去ログを上書きしない。

## 既存データと保存

保存形式1は引き続き読み込める。閲覧・交流開始だけでは移行も書き込みもしない。
既存IDに過去の個性を推測して付与せず、未登録として扱う。最初の明示登録または次の結果保存で現在の個性を登録する。
登録・結果保存時に形式2へ移行し、猫IDをキーとする`cats`（名前・個性）を追加する。
既存の親しみ、保存版、適用済み交流の内容・順序を保持する。猫登録は関係の保存版を進めない。

登録済みの個性と異なる個性で開始済みの交流を新たに保存しようとした場合は、競合として拒否する。
既に適用済みの過去結果の再試行は従来の交流ID・内容照合で扱い、二重加算しない。
保存は既存の一時ファイル・置換処理を共用する。単一プロセスでの利用という前提は維持する。
版4の交流ルール・係数・ログ形式は変更しない。保存形式2は旧アプリでは読めないため、以後は更新後のアプリを使う。

## 検証

通常テスト183件と実際のTkウィジェットを使う画面専用9件、計192件が成功。
名前と個性の登録、お客を変えた再会、別の猫との分離、形式1からの移行と既存履歴保持、登録競合、書き込み失敗と再試行、不正な個性の拒否を確認した。
画面では登録後の入力制御、保存済み個性の優先、新しい猫の個性選択、結果保存時の名前登録、一覧の名前表示を確認した。目視によるレイアウト評価は含まない。
