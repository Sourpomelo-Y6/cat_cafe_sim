# 単独交流と営業の接続：初回仕様・実装

更新日：2026-09-13 / 交流ルール版4 / 営業交流ログ形式1

営業中のお客と猫で交流を始め、終了時に資金・残り体力・親しみを反映する初回実装。
[通常営業の割り当て・自動交流](HumanToCatAutomaticCafe.md)に対応済み。以下の手動コマンド操作は検証用画面・CLIを指す。
従来の自動接客営業と並存する「営業交流」モードを追加した。旧営業の満足達成・成功率を版4交流の目標として使わない。

## 既存処理との接続方針

既存営業は1匹・1席・固定来客で、来店、待機列、待機期限、時間料金、閉店を扱う。
版4には任意終了、通常反応と特別行動による親しみ、特別行動の資金、残り体力がある。
初回は来客と会計の処理を共用し、接客部分を版4交流へ置き換える専用coreを設けた。

| 項目 | 初回の扱い |
|---|---|
| 相手の選択 | 営業へ参加する猫と待機中のお客を選ぶ。満席・退店済み・体力切れ・不健康の猫は開始不可 |
| 着席 | 選択操作では時計を進めない。旧営業の自動接客も実行しない |
| 時間 | 通常行動・切り替え・停止・特別行動はいずれも営業1tick。通常画面の自動進行中はタイマーで進み、一時停止中は進まない |
| 来客・待機期限 | 交流行動中も進める。待機だけなら「営業を1tick進める」を使う |
| 滞在期限 | 交流の最大行動数を使う。開始時に閉店までの残りtickを上限にする |
| 任意終了 | tickを進めず、予約を失効させ、そのお客を会計・退店させる |
| 時間終了 | 交流時間終了で会計・退店。最終営業tickなら営業側の理由はclosing |
| 体力切れ | 会計・退店し、その日の猫は交流不能。閉店と同時なら体力切れを優先 |
| 資金 | 行動tick数×既存の時間単価＋版4特別行動の資金。旧営業の成功・完全成功ボーナスは加えない |
| 猫の体力 | 営業の現在値で開始し、各行動後の残りを営業へ反映。次のお客にも引き継ぐ |
| 親しみ・個性 | 関係保存データから読み、終了時に保存。同じIDなら既存の親しみと猫の個性を使用 |
| 客満足・不満 | 親しみから換算しない。版4交流の終了だけでは不満を加えない。列満杯・待機期限の不満は既存どおり |

交流中の「停止」には版4の体力回復を使う。空席時の時間送りには回復を追加しない。
営業と交流の体力上限は一致を必須とし、自動換算しない。気力を使った旧営業の自動全回復はこのモードで発生させない。
着席して即終了した場合は滞在0tick、料金0。待機中のお客にも時間料金を付けない。
通常の短い交流でも親しみが増えることがあり、特別行動が出なくても営業として会計できる。

## 画面で試す

```bash
python3 -m cat_cafe_sim.cafe_interaction gui
# 単独試遊で登録した猫や関係を使う場合
python3 -m cat_cafe_sim.cafe_interaction gui --relationships saves/relationships.json
```

既定の保存先は`saves/cafe_relationships.json`。初回は単独試遊と別ファイルを使う。
通常画面では「営業を開始・再開」で来店させ、担当猫の割り当て後は自動進行する。自動割り当ても選べる。
検証用画面（`gui --manual`）では「営業を1tick進める」で来店させ、待機中のお客を選び、「選んだお客と交流」で開始する。
検証用画面では通常行動・変更先・心をつかむを操作でき、「切り上げて会計」で任意終了する。
画面には営業時計・所持金・猫の名前と体力・交流中のゲージ・親しみ見込みと、営業／交流ログを表示する。
ログ欄は小さい画面でも高さを確保する。登録済みの猫の名前と個性を使用し、未登録の猫は初回結果保存時に既定個性・ID名で登録する。
個性・名前を指定したい場合は、先に単独試遊画面で同じ保存先へ猫を登録する。

営業の所持金・時計・体力は画面を開いている間だけ保持する。アプリを開き直すと新しい1日になる。
固定来客のguest-1等をこの試遊では同じお客IDとして扱うため、次の試遊日には親しみを引き継ぐ。
一般の来店IDと永続的なお客IDを分ける仕組みや、再来店予定の生成は後続の作業。

## CLI・再生

```bash
python3 -m cat_cafe_sim.cafe_interaction run --operations wait start:guest-1 direct finish
python3 -m cat_cafe_sim.cafe_interaction replay reports/cafe_interaction.json
```

`wait`は空席時の時間送り、`start:客ID`は着席、`finish`は任意終了、`retry`は保存再試行。
通常行動IDと`switch:種類ID`も使える。`--relationships`、`--output`で保存先を指定し、`--config`で営業設定を指定できる。
上記の手動操作例では営業2tick、交流1行動、時間料金10、特別行動資金0、残り体力95となる。親しみは保存済みの個性に従って計算する。

営業交流ログは従来の営業ログと区別し、着席時の交流設定・関係のスナップショットと、営業操作・状態・イベント・成果を保存する。
専用replayは保存データを参照・更新せず、ログ内のスナップショットから再生する。
ログ再生は営業セーブのロードや未保存結果の再送ではない。営業途中のログも検証用に保存できる。

## 保存失敗と整合性

会計と体力は終了時にメモリ上の営業へ反映し、その後に関係保存を行う。
関係保存が失敗した場合は終了結果を保持し、次の時間送り・着席を拒否する。「結果保存を再試行」で再開できる。
会計と親しみの反映はそれぞれ交流単位で一度。任意終了の連打や保存再試行で資金・親しみを二重加算しない。
登録個性や親しみが別の操作で変わっていた場合の競合は、既存の保存処理で拒否する。
無効な行動・相手選択では時計や来客も進めない。営業ログで関係データを上書きする指定は拒否する。

営業全体の永続セーブは今回含まない。関係保存とメモリ上の会計はプロセス終了をまたぐ一括トランザクションではなく、アプリ終了時には営業の所持金・時計・体力は失われる。
営業日程・休養・翌日への資金と体力の持ち越し、顧客台帳、営業途中の復元は未実装。複数席は[2席での同時交流](HumanToCatMultiSeatCafe.md)に対応した。複数猫からの担当選択は[参加猫の仕様](HumanToCatCafeRoster.md)として追加した。

## 実装と検証

- `core/cafe_interaction.py`：営業時間・交流・退店会計と専用再生。
- `cafe_interaction.py`：関係保存との接続、保存再試行、CLI。
- `cafe_interaction_gui.py`：営業試遊画面。

任意終了、開始直後の終了、次のお客への体力持ち越し、来客・待機期限、交流時間終了、閉店、体力切れとの同時終了、保存失敗・再試行、改変ログの検出を確認する。
特別行動資金200＋時間料金20＝会計220の検証には、ゲージ増加を大きくした診断設定を使用する。既定値のバランス評価とは分ける。
GUIではお客の選択から交流・会計までと、保存失敗後の操作停止・再試行、860×600でのログ表示を確認する。

通常テスト194件と画面専用12件、計206件が成功。CLIの実行・再生も確認した。
40tickの営業を閉店まで実行し、途中状態を含む全操作ログの再生一致を確認した。既存の版1〜4の計320交流ログも再生一致した。
画面テストは実際のTkウィジェットによる操作・配置の確認であり、目視のデザイン評価は含まない。
