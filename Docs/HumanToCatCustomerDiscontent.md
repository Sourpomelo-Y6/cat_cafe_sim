# お客さんの累積不満と一時的な来店停止

2026-09-28追記：来店停止を2回繰り返した後は[信頼回復と永久離脱](HumanToCatCustomerTrust.md)へ接続する。信頼回復に費用は使わず、満足なら回復、不満または未対応なら永久離脱する。

2026-09-28追記：[1回ごとの接客評価](HumanToCatCustomerSatisfaction.md)を接続。「満足」で－25、「不満」で＋25、「普通」は増減なしとする。高難度条件未達の＋10は同じ接客内で合算する。

更新日：2026-09-28 / 状態：初回実装済み

## 目的と区分

混雑や接客条件の未達を当日だけの結果で終わらせず、今後の来店へ影響させる。
4席への増設や常連化で来客を増やす一方、対応できる猫・席・待機列が不足するリスクを作る。

累積不満は店に対する客ごとの値。[常連度](HumanToCatCustomerLoyalty.md)、猫から客への親しみ、今回の高難度条件、ゲーム全体の人気とは別に保存する。
新規ゲームの全目標モードで導入し、旧セーブには後付けしない。

## 初回ルール

| きっかけ | 累積不満の変化（暫定） |
| --- | --- |
| 待機列が満員で入れず退店 | ＋25 |
| 待機時間切れで退店 | ＋25 |
| 高難度客の接客条件が未達 | ＋10 |
| 接客で猫から客への親しみが増加 | －25 |

高難度客の条件未達と親しみ増加が同じ接客で起きた場合は差し引きして一度更新する。通常料金や既存の追加料金判定は変更しない。
閉店だけを理由とする退店、未発生の来店、休業では不満を増やさない。不満は0未満・100より上にはしない。

累積不満が初めて100に達した日は来店済みとして扱い、翌日から7日間来店を停止する。
停止日の翌日から不満50で復帰し、元の曜日予定・常連の追加曜日・高難度客・増設客の予定を再び使う。
停止期間に本来の来店日があっても翌日へ振り替えず、期間終了後の次の対象日を待つ。

常連客も停止対象とする。来店停止によって常連度・常連化日・猫との親しみを失わない。
復帰後に再び100へ達した場合は、もう一度7日間停止する。

## 画面と営業ログ

「準備・お店」→「お客さんの名簿・来店予定…」に累積不満の列を追加する。
お客さんを選ぶと現在値、停止期限、復帰後の値を確認できる。今日／翌日の切り替えでは、停止中の客を「来店停止（○日目まで）」と表示し、予定の進行を `—` にする。

営業ログには不満の増減理由と前後の値を表示する。100へ達した場合は停止期限も表示する。
名簿の閲覧では不満・停止期間・来店予定・時間を変更しない。

## 保存と検証用の日次記録

`config/cafe_customer_discontent.json` の増減量、上限、停止日数、復帰値を新規開始時に営業セーブへ固定する。再開時は設定ファイルを読み直さない。
客ごとに現在値・最後に値が変わった日・停止期間だけを保存する。最後の変更日は、復帰値を適用した後に増減した値が過去の停止履歴で巻き戻らないために使う。来店停止の整合性を確認するため、日次結果には客ID・退店理由・その来店の既存不満値だけを軽量に保存する。毎ターンの行動ログは追加しない。

累積不満は接客成果と日次の退店結果から再計算して照合する。来店予定の検証では停止期間中にその客が来ていないことを確認する。
接客・退店後の保存失敗では結果を保持して再試行し、再開時に不満を再加算しない。初期化操作は詳細リプレイへ記録する。
累積不満項目と日次の退店結果がない旧セーブ・旧リプレイは従来どおり読み込む。

## 確認

待機列満員・待機時間切れ、高難度条件の達成／未達、親しみ増加あり／なし、不満0・100、停止当日・7日間・復帰日、常連客、休業、通常曜日との重複、複数回の停止、途中保存・翌日保存・保存失敗、詳細リプレイ、破損データ、旧セーブ互換を確認する。
GUIは名簿660×520で、不満・常連度・予定・停止期限と猫一覧をスクロールを含めて確認する。
