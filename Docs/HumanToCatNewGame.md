# 新規ゲーム・セーブ再開・終了後の再開始

更新日：2026-09-21 / 状態：初回実装済み

全体の流れを固めるため、通常起動の入口とゲームごとの保存先を追加した。
2026-09-22追記：[人気目標](HumanToCatPopularityGoal.md)を新規開始時に有効化する。10日以内に人気150を目指し、達成・未達の結果確認後も継続営業できる。細かな数値調整は後続。

## 起動と初期条件

```bash
python3 -m cat_cafe_sim.cafe_interaction gui
```

オプションを付けない通常起動では「新しく始める」「セーブから続ける…」「終了」の開始画面を表示する。
新規開始では条件を確認し、「この条件で新しく始める」で初期セーブを作成してから営業画面へ進む。
「戻る」や画面を閉じる操作ではゲームや保存ファイルを作らない。

| 項目 | 初回の条件 |
|---|---|
| 開始日・時刻 | 1日目の準備、営業は一時停止 |
| 資金・人気 | 1,000・100 |
| 席数 | 2席 |
| 猫 | ミケ、タマ、ソラ、コハク、ムギの5匹。個性はそれぞれ甘えん坊・探検家・距離を大切にする・遊び好きで繊細・中立 |
| 猫の状態 | 健康、体力・気力は設定上限、疲労・ストレス0、全猫出勤予定 |
| 特性 | ミケは接客好き、タマは外出好き、コハクはのんびり屋。ソラ・ムギはなし。[効果の仕様](HumanToCatTraits.md)を参照 |
| 関係 | お客への親しみ・プレイヤーへの好感度・交流回数は0 |
| 出勤・病気・経営ルール | 有効。資金0以下または人気0でゲームオーバー |
| 譲渡イベント | 初期OFF。準備中に既存の設定画面で変更できる |
| 人気目標 | 開始日を含む10日以内に人気150。接客による人気獲得と上限300を導入 |
| 自動割り当て | 初期OFF。営業画面で切り替え可能 |

初期猫と席数の設定元は [cafe_new_game.json](../config/cafe_new_game.json)。
初期資金・人気や家出等のルールは [cafe_management.json](../config/cafe_management.json)を使う。
初回画面では固定の開始条件を案内する。難易度・初期猫の個別選択などのカスタマイズは後続。
開始時に条件を営業へ記録し、セーブ読込時に現行設定で上書きしない。

## ゲームごとの分離と保存

新規作成のたびに `saves/games/game-<固有文字列>/` を作る。

- `cafe.json`：営業セーブ。新規開始時点を保存し、「営業を保存…」の既定の候補になる。
- `relationships.json`：そのゲーム専用の猫の登録・お客との関係データ。

新しいゲームでは既存の共用関係ファイルを使わない。
初期猫のIDは同じでも関係ファイルが異なるため、以前のゲームの好感度・受け入れた猫・譲渡・家出・資金・日数を引き継がない。
以前のゲームのファイルは上書きせず残し、後からその営業セーブを選んで再開できる。

初期セーブ以降の進行は従来どおり「営業を保存…」で保存する。自動保存機能の追加ではない。
営業セーブは関係ファイルの絶対パスを参照する既存形式のまま。ファイルを移動するための機能は今回追加しない。
同じゲーム内で関係データが進んだ後に古い営業セーブへ戻れない制約も維持する。

「セーブから続ける…」では新旧の営業セーブを選べる。復元後は必ず一時停止し、設定された自動割り当てだけを復元する。
経営ルール未導入の旧セーブは未導入のまま再開し、資金補充・経営ルール導入・猫の追加を自動で行わない。
不正なセーブやキャンセルの場合は開始画面に留まる。

## 営業中・ゲームオーバー後の再開始

営業画面の「新規ゲーム…」から別のゲームを開始できる。開くと自動進行を停止する。
終了後は同じボタンが「結果・再開始…」になり、終了理由・日付・資金・人気・累計接客売上を表示する。
結果の下に新しいゲームの初期条件と開始ボタンを表示する。新しく始めず「戻る」で結果の閲覧・保存へ戻れる。

現在の操作や未保存の接客成果がある場合、開始実行時に次を選ぶ。

- 保存してから新しく始める。
- 現在の営業状態を保存せず新しく始める。
- キャンセルして現在のゲームに留まる。

保存ダイアログのキャンセル、保存失敗、新規ゲームの作成失敗では現在のゲームを置き換えない。
新規作成に失敗した場合は、その呼出しで作った専用ディレクトリだけを片付ける。以前のゲームを削除しない。
新規作成が完了した場合だけ、一覧・ログ・担当選択を切り替え、一時停止状態で準備を始める。
ゲームオーバーの店を復活させる処理ではなく、新しい店の開始である。

## 既存の試遊・直接再開

以下の明示オプションを使う場合は、従来どおり営業画面を直接開く。

```bash
# 既存の営業セーブを直接再開
python3 -m cat_cafe_sim.cafe_interaction gui --resume saves/cafe_day.json
# 共用の登録猫を使った従来の試遊
python3 -m cat_cafe_sim.cafe_interaction gui --relationships saves/cafe_relationships.json
# 検証用の手動コマンド画面
python3 -m cat_cafe_sim.cafe_interaction gui --manual
```

`--cats`・`--seats` を指定する試遊も維持する。これらの起動では経営ルールを自動導入しない。
`--resume` と猫・席・関係保存先・手動画面指定の併用禁止も従来どおり。
CLIの `run`、テスト猫追加の `seed-playtest` は変更しない。
