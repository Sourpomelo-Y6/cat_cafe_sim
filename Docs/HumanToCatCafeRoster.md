# 複数の猫から担当を選ぶ営業

更新日：2026-09-13 / 複数猫・1席 / 営業交流ログ形式2

登録済みの猫を営業へ参加させ、相手との親しみや体力を見て担当を選べるようにした。
割り当て後の交流コマンドは従来どおり自動。席は1つで、交流途中の担当交代はできない。

## 参加猫と起動

```bash
# 同じ保存先の単独試遊で、猫ID・名前・個性を先に登録する
python3 -m cat_cafe_sim.human_cat_gui --relationships saves/relationships.json
# 登録済みの猫すべてを営業へ参加させる
python3 -m cat_cafe_sim.cafe_interaction gui --relationships saves/relationships.json
# 登録したIDのうち、参加する猫を指定する
python3 -m cat_cafe_sim.cafe_interaction gui --relationships saves/relationships.json --cats cat-a cat-b
```

参加猫は起動時に決める。`--cats`省略時は登録済みの猫すべてをID順に参加させる。
まだ交流履歴がない登録猫も対象。登録が1匹もない場合のみ、従来の試遊用cat-1で開始する。
明示的な`--cats`指定では未登録ID・重複ID・空の一覧を拒否する。起動・一覧表示だけでは関係保存先を書き換えない。
営業中の猫の追加・離脱は今回含めない。新しく登録した猫を参加させるときは次の起動で選ぶ。

## 手動割り当て

「営業を開始・再開」で来客を待ち、お客と担当猫を選んで「担当猫を割り当てる」を押す。
一覧で次を比較できる。

- 名前と猫ID。
- 個性プリセット名。一致しない個性は「カスタム」と表示する。
- 現在の体力。
- 選択中のお客への保存済み親しみ（未交流の組み合わせは0）。
- 担当可能・交流中・交流不可。

個性の詳細編集・確認は単独試遊の個性画面で行う。
親しみ一覧は起動時と営業内の結果保存時に更新する。別のアプリから同時変更された場合、開始時には保存データを読み直し、結果保存時には既存の競合チェックを行う。
交流中は他の猫へ割り当て直せない。終了・会計後、次のお客には別の猫を選べる。

## 体力と自動割り当て

猫ごとに体力・気力・健康状態・交流不能状態を保持する。
交流で消耗・回復するのは担当猫だけ。他の猫の体力は変わらず、担当を替えても体力は初期化しない。
初期体力・気力は各猫とも営業の開始設定値。待機猫の自動回復は追加していない。
体力切れの猫がいても、別の健康な猫に体力が残っていれば営業を続けられる。

自動割り当ては次の順で決める。

1. お客は待機順。
2. 猫は健康で、交流不能でなく、体力が正の参加猫に絞る。
3. 残り体力が最も多い猫を選ぶ。同値なら猫ID順。

自動選択では親しみや個性に重みを付けない。これらを用いる選択はプレイヤーが一覧を見て判断できる。
全猫が交流不可なら着席させず、時間を進めて待機期限・閉店を処理する。

## 保存・再生・CLI

```bash
python3 -m cat_cafe_sim.cafe_interaction run --relationships saves/relationships.json --cats cat-a cat-b
python3 -m cat_cafe_sim.cafe_interaction replay reports/cafe_interaction.json
```

名前・個性・親しみには既存の関係保存形式2をそのまま使う。営業の資金・時計・猫ごとの体力は起動中のみ保持する。
関係保存失敗時は営業全体を一時停止し、再試行が終わるまで担当を替えられない。
会計と親しみは交流ごとに一度だけ反映する。

営業交流ログ形式2に参加猫ID一覧と各猫の状態を記録する。集計の`cat_stamina`には各猫の残り体力を含める。
既存の`cat`・`stamina`欄は直近の担当猫を表し、全猫の合計ではない。
従来の1匹用ログ形式1も再生可能。再生では関係保存先を読み書きせず、記録済みの参加猫と交流スナップショットを使用する。

## 検証

参加猫の全件・部分指定、未登録・重複の拒否、猫ごとの体力保持、保存済み個性、相手別親しみ、体力優先と同値時のID順、体力切れの猫から別の猫への交代を確認する。
保存失敗時の担当変更拒否と再試行、複数猫ログの再生、改変検出、旧ログ形式1の再生も確認する。
GUIでは2匹の一覧・選択した猫への割り当て・交流不可の制御・860×600でのログ領域を検証する。

通常テスト205件と画面専用17件、計222件が成功。2匹を指定したCLI営業も閉店まで進行し、記録上の担当がcat-aからcat-bへ交代することと、各猫の残り体力を含めた再生一致を確認した。
画面検証は実際のTkウィジェットの操作・配置を対象とし、目視によるデザイン評価は含まない。
