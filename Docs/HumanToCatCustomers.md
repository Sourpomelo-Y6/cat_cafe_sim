# お客さんの名簿と当日の来店予定

## 初回実装

「準備・お店」→「お客さんの名簿・来店予定…」で確認する。営業前に来るお客さんを見て、猫の出勤・休養・派遣を判断するための閲覧画面。
営業中・閉店後も閲覧でき、開くと自動進行は停止する。閉じただけでは再開しない。

- お客さんの表示名、猫の好み、来店回数、当日の来店予定の進行時点、現在の状態を表示。
- お客さんを選ぶと、猫別の「猫からそのお客さんへの親しみ」、好みとの一致、出勤・休養・所在・体調を表示。
- 営業画面の担当割り当て欄・席の状況・来退店ログにも表示名を使う。IDを併記して取り違えを防ぐ。
- 閲覧による来店・好感度更新・好みの登録・時間進行・ファイル書込みは行わない。

親しみは関係データへの保存済みの値を表示する。進行中の交流の見込み値は含めない。接客結果の保存待ちがあれば案内を表示する。

## 予定と好み

新規ゲームでは[曜日別来店](HumanToCatWeekdays.md)を導入し、今日・翌日の予定を切り替えて表示する。お客さんごとの曜日も表示する。旧セーブは設定の `arrival_ticks` 順に固定IDが毎日来店する予定を維持する。
進行0は開店時。時計の時刻や接客回数ではなく、営業を進める単位である。
休業なら当日の来店は発生せず翌日の予定に切り替わる。閉店済みの画面では実際に来た客を退店済みとして表示する。

好みが有効なゲームでは、来店前も保存済みの好み候補・営業seed・お客さんIDから来店時と同じ好みを計算する。
未導入の旧セーブでは「未設定」と表示し、閲覧によって好みを追加しない。
当日の予定にも既存の好み記録にもない独自IDの好みを推測しない。

常連度・来店確率・予定の編集は未導入。名簿の追加で自動割り当ての優先順位は変更しない。

## 名前・来店回数・保存

表示名はIDに対応した固定名（例：guest-1＝佐藤さん）を使用する。20人を超えた場合は「お客さん21」など、独自IDにはそのIDを表示する。
表示名の変更機能は設けない。名前の対応順は既存ゲームの再開時も維持する。

来店回数は**この営業セーブ内の来店実績**である。既存の日次結果の来店数と当日の来店一覧から集計する。
曜日未導入の旧セーブは毎日同じ順番の固定IDが来る方式で集計する。新規ゲームは日次に保存した実来店IDを使う。接客・会計に至らず列満杯などで帰った来店も1回と数え、休業日は数えない。翌日への移行や保存再開で二重計上しない。
別の営業・単独交流に由来する親しみだけがある場合も名簿に載せるが、その交流件数を来店回数に換算しない。

名前・予定・回数・相性は保存済みのID・設定・営業実績・関係から算出する。曜日来店の導入に伴い、新規ゲームは曜日設定と日次の来店IDを保存する。旧セーブは項目を増やさず、そのまま閲覧できる。

## 確認

来店前の好みと実際の一致、同時刻の来店、未接客の退店、休業・翌日・保存再開での回数、旧関係と独自ID、閲覧の非更新をテストする。
GUIでは最小サイズの一覧・スクロール、閲覧時の一時停止、表示名から正しいIDへの担当割り当てを確認する。
