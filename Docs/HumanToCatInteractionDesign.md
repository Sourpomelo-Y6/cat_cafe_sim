# 人の動作と猫の反応：接客行動の設計案

作成日：2026-09-06

初期範囲の実装が完了した。[実装記録と検証結果](HumanToCatInteractionImplementation.md)を参照。
以下は初期版の実装前に整理した設計案の記録。
2026-09-07の[テンション・特別行動・種類拡張案](HumanToCatSpecialActions.md)で、特別行動の条件を更新した。
関心100での終了と2種類の切り替えは初期版の仕様であり、拡張時に見直す。

## 位置づけ

[行動原案](HumanToCatActionProposal.md)を、人が動作を選び、猫の反応を見ながら交流する仕様へ整理する。
本書は実装前の提案。原案にない数値・判定・段階分けは本書で追加した暫定案であり、採用済みのゲームルールではない。
原案はそのまま保存する。本書の追加時点では実行コード・モデル・既定設定を変更しない。

最初は猫1匹との単独交流を固定ルールで検証する。人側の操作は手動または固定の行動列、
猫側は非学習の反応規則とし、効果を説明できる状態を先に作る。
営業への接続と学習対象の変更は、その結果を踏まえた別の実装段階とする。

## 1. 主体と既存仕様との関係

| 項目 | 現在の実装 | 今回の提案 |
|---|---|---|
| 毎tickの選択者 | `cat_policy`として扱う猫方策 | 人。試遊時はプレイヤー、検証時は固定方策 |
| 選ぶ内容 | ねこじゃらし／なでなでの3速度＋休む | 素直・合わせる・激しく・フェイント・停止・変更 |
| 反応する相手 | 客の好みから満足増分を計算 | 猫。関心・体力・好み・履歴から反応を計算 |
| 進捗 | `Visit.satisfaction`＝客の今回の満足 | `engagement`＝この交流での猫の関心。別の値 |
| 非公開条件 | `Config.preferences`＝客の遊び／なで好み | 猫の遊び／なで好み。別の設定 |
| 店長 | 割り当て・待機を操作 | 店長の経営操作と、交流中の人の操作を区別する |
| 学習 | 猫方策のQ学習 | 初期段階は学習なし。後で人側の行動選択を学習候補にする |

現行の行動名は人の動作にも見えるが、APIと報酬は猫方策として設計されている。
名前だけの置換では、学習主体と満足度の意味が一致しない。
猫の好反応から客の満足を増やす営業接続は考えられるが、関心と客満足を同じ変数にはしない。
猫自身が選ぶ行動を学習したい場合は、反応規則を猫方策へ置換する別設計が必要。
人と猫の双方を同時に学習させる構成は初期範囲に含めない。

## 2. 原案の行動を具体化する

「激しいく動作」は設計上の表示を「激しく動かす」に整理する。
動作対象はねこじゃらしを使う`play`と、なでる`pet`の2種類。開始時は`play`。
「激しく」は玩具の動かし方で表現し、強くなでる行動にはしない。
以下の消費は人の体力ではなく、反応する猫の体力の暫定コスト。

| 原案の対応 | ID / 表示 | 具体的な操作 | 基本関心増分 / 猫体力コスト | 好み・履歴との関係 |
|---|---|---|---|---|
| 質問→素直な動作 | `direct` / 素直に動かす | 遊びなら一定速度、なでるなら穏やかな一定動作 | 12 / 5 | 現在種類の好みを適用する基準行動 |
| 共感→相手に合わせる | `adapt` / 相手に合わせる | 直前の反応を見て動作の強弱を調整 | 通常10 / 5。戸惑い・けだるさ・そっぽの後は8 / 2 | 公開された直前反応だけを参照。好みの正解を直接読む操作にはしない |
| 深掘り→激しい動作 | `intense` / 激しく動かす | 玩具を大きく素早く動かす | 24 / 15 | `play`のみ。大きな進捗と消耗を比較する |
| 自分の話→フェイント動作 | `feint` / フェイントを入れる | 玩具の進行方向やタイミングを変える | 通常10 / 8。直前が停止で、停止前が交流なら18 / 8 | `play`のみ。停止との連携が有効か検証する |
| 冗談→動作停止 | `pause` / 動きを止めて待つ | 交流を終えず、猫の様子を見る間を置く | 0 / 0、体力を2回復 | 同種の飽き履歴は保持。連続停止で連携効果を蓄積しない |
| 話題変更→動作変更 | `switch` / 動作を切り替える | 遊びとなでるを切り替える準備 | 0 / 0、回復なし | 1tick使用。変更しただけでは関心やボーナスを得ない |
| 心をつかむ | `connect` / 心をつかむ（後続候補） | 良好な反応の積み重ねを受けた特別な働きかけ | 初期段階では数値・選択肢を実装しない | 単純連打できる高効果行動にせず、条件付き行動として検討 |

初期の選択肢は6個で、文字列IDをログとAPIで使用する。`pet`中の`intense`と`feint`は無効。
`switch`は現在種類の反転として定義するため、変更先の追加引数は不要。
無効行動は時間も状態も更新せずエラーとし、UIでは選択不可にする。

停止は交流中の短い間で、既存の休憩（体力8回復）とは別ルール。
本格的な休憩・営業離脱は後の接続段階で扱う。停止だけでは関心を増やさず、制限時間を消費する。
停止直後のフェイントへの加算はその1回だけ。停止前が交流でない場合や、途中に切り替えを挟んだ場合は適用しない。

## 3. 猫の反応を具体化する

反応は猫側の出力で、人が選ぶ行動とは別に記録する。
初期実装では確率を使わず、同じ状態・操作で同じ反応となる規則にする。
表の上から順に判定し、1tickにつき反応は1つだけ出す。

| 原案の対応 | 反応ID / 表示 | 初期の判定案 |
|---|---|---|
| 不満を漏らす→そっぽを向く | `turn_away` / そっぽを向く | 交流行動で現在種類への好みが0 |
| あいまいに流す→けだるそうな対応 | `listless` / けだるそうにする | 行動開始時の体力が20以下 |
| 逆質問→戸惑い | `confused` / 戸惑う | 交流行動で基本効果×好み×飽き倍率が6未満 |
| 詳しく答える→熱心な対応 | `enthusiastic` / 熱心に応じる | 同じ計算値が18以上 |
| 好意的反応→好意的対応 | `favorable` / 好意的に応じる | 同じ計算値が10以上 |
| 普通の相づち→通常対応 | `neutral` / 普通に応じる | 上記以外。停止・変更も低体力でなければこれ |
| 心を開く | `open_up` / 心を開く（後続候補） | 初期段階では発生させない。条件付き交流の特別結果として検討 |

関心への倍率は、そっぽ・けだるさ＝0、戸惑い＝0.5、その他＝1とする暫定案。
低体力でも消費コストは発生するため、猫の反応を無視した強い動作には消耗だけが残る場合がある。
判定の計算値は関心上限で切り詰める前の値を使い、目標直前だから反応が弱くなることを避ける。
反応は内面の完全な説明ではない。例えばけだるさが優先されると、その行動が好みに合うかは反応だけでは分からない。

「心をつかむ」は人の条件付き行動、「心を開く」は猫の特別反応として分ける案。
将来は良好な反応の連続・適切な動作変更・体力余裕を発動条件の候補とする。
初期案では関心100だけで自動発生させない方針だったが、この点は[追加案](HumanToCatSpecialActions.md)で置き換えた。
追加案では関心80以上で消費して任意発動でき、100以上で次回の猫側行動が「心を開く」になる。
既存の「満足目標到達と体力0による特別成功」は意味が異なるため、この反応に転用しない。

## 4. 最初に実装する状態と処理

### 状態と公開情報

| 状態 | 初期値・範囲 | 操作側への公開 |
|---|---|---|
| 関心 `engagement` | 0、0〜100 | 初期試遊では数値公開。客満足とは別表示 |
| 猫体力 `stamina` | 100、0〜100 | 公開 |
| 現在種類 `mode` | `play` | 公開 |
| 最後に実行した交流種類・連続回数 | なし・0 | 公開 |
| 直前行動・直前反応 | なし | 公開。開始時の「なし」は通常反応と区別 |
| 停止前が交流だったか | false | 行動履歴から分かる情報として公開 |
| 残りtick | 20 | 公開 |
| 猫の好み | 遊び・なでの2値、各0〜2 | 非公開。診断ログでは別欄に保存 |

各セッションで全状態を初期化する。好みは実験設定で指定し、セッション中は固定。
気力による体力補充、来店、料金、常連関係、日跨ぎ信頼は単独交流の初期範囲に含めない。

### 1tickの処理順

1. 終了状態と行動の有効性を確認する。
2. 開始時の状態・直前反応から基本効果とコストを決める。`adapt`が今回の反応を先読みしないようにする。
3. 交流行動なら、最後に実行した交流と種類が同じ場合は連続回数を増やし、異なる場合は1にする。
   飽き倍率は`max(0.4, 1 - 0.15 × max(0, 連続回数 - 1))`。
   停止・変更自体ではこの履歴を更新しない。変更を2回して元に戻っても飽きを消せない。
4. 基本効果×現在種類の猫の好み×飽き倍率から、前節の優先順位で反応を決める。
5. 反応倍率を掛けた関心増分と体力コストを適用し、関心・体力を範囲内に制限する。
   停止は体力を2回復し、関心は増やさない。変更は種類のみを反転する。
6. 履歴を更新し、残りtickを1減らす。実際の増分・消費・反応をログに保存する。
7. 体力0なら`exhausted`、それ以外で関心100なら`success`、それ以外で残りtick0なら`timeout`。
   終了は1つだけ。体力0と関心100が重なっても特別成功にはせず、消耗終了とする。

7の優先順位は猫への動作を検証する新モードの案で、既存営業の成功優先ルールとは異なる。
この違いを既存の`SimulationCore`へ暗黙に持ち込まない。

### 手計算できる例

初期体力100・好み(1, 1)で、遊びの「素直に動かす」は関心+12、体力−5、好意的反応。
続けて同じ行動なら飽き倍率0.85で関心+10.2、体力−5。
次に停止すると体力+2、関心増分0、交流連続回数2を保持する。
その直後のフェイントは基本18、連続回数3の倍率0.7で関心+12.6、体力−8。

好み(0, 1)で遊びを続けると、そっぽを向いて関心は増えない。
動作変更の1tick後、なでる「素直に動かす」なら関心+12となる。
体力20以下なら好みに合っていてもけだるさを優先するため、停止による回復を試す必要がある。

## 5. 実装単位と変更箇所

初回は「6行動・6通常反応の単独交流を、行動列から実行して再生できる」まで。
下記の新規パスは予定であり、本書作成時点では存在しない。

| 対象 | 次回の実装案 |
|---|---|
| `core/human_cat_interaction.py`（新規） | 状態・行動検証・反応・終了を扱う、標準ライブラリだけの独立した交流core |
| `config/human_cat_interaction.json`（新規） | 本書の暫定値と猫の好みを独立設定として保存。読み込み時に範囲・有限値を検証 |
| `human_cat_demo.py`（新規） | `python3 -m cat_cafe_sim.human_cat_demo`で行動列を実行するCLI。状態と反応を表示 |
| 新モードのログ | モードID・ルール版・設定・初期状態・操作列・各tick結果・終了理由をJSON保存し、再計算で一致確認 |
| `tests/test_human_cat_interaction.py`（新規） | 次節の仕様テスト |
| README | 実装完了後に実行・再生コマンドを追記 |

現行の`core/config.py`はplay3個・pet3個・rest1個を検証しており、新しい6行動はそのまま登録できない。
`core/interaction.py`は客の好みと満足を計算するため、新しい反応計算として直接流用しない。
`core/simulation.py`、`envs/cat_interaction.py`、`envs/observations.py`、`training/encoding.py`、
`training/q_learning.py`、`training/model.py`、`policies/learned.py`は初回の変更対象外。

後続で人側を学習させる場合は専用環境・観測・報酬を定義し、現在7固定の行動数とマスク処理を見直す。
学習済み猫モデルは行動ID・主体・状態・報酬の意味が違うため、新モードへロードしない。
新しいモデルとログにはモード識別子と版を持たせ、異なるものを明示的に拒否する。

営業接続時には、人側の行動選択者、猫反応から客満足への変換、気力・休憩、成功優先順位を設計する。
猫カフェ全体をこのモードへ置き換える判断は、単独交流の検証後に行う。

## 6. 完了条件と評価

初回実装の完了条件は以下とする。

- 原案の6行動と6通常反応が、設定・状態に応じて説明できる。
- 手計算例と結果が一致し、低体力・好み0・飽き下限・目標到達・同時終了をテストする。
- 無効行動と終了後の操作で状態が変わらない。停止・変更の連打で関心や連携効果を稼げない。
- 動作変更の往復で飽きがリセットされず、停止は休憩や特別成功と混同されない。
- 同じ設定・初期状態・操作列の全tickが再生一致し、改変ログを検出できる。
- 操作側観測に猫の好みや内部の判定用スコアを渡さない。
- 既存営業・接客学習・旧モデル読込の回帰テストが通る。

固定行動列は素直連打、激しく連打、停止→フェイント、反応に応じて合わせる、
種類変更を含む列、停止のみを用意する。好み(1,1)、(0,2)、(2,0)、(0.5,0.5)と開始体力100・20で比較する。
反応に応じる固定方策も、公開観測だけを使う。
成功率だけでなく関心増分・体力消費・終了理由・反応内訳・使用tickを並べ、
停止連打や1行動への集中がどの条件で有利になるかを確認する。
これらは仕様診断条件であり、後の学習評価で未使用テスト条件と呼ばない。

数値の釣り合い、関心の数値公開を製品でも続けるか、特別行動・信頼の仕様は検証後の課題。
本書では動く最小範囲の暫定仕様を定め、面白さや学習性能を確認済みとは扱わない。
