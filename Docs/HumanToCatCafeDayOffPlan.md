# 店舗の休業日と翌日へのスキップ

2026-09-21追記：[プレイヤー交流の初回仕様](HumanToCatPlayerInteraction.md)を実装。猫の詳細から準備中に最大10ターンのコマンド交流を1日3セット行い、好感度・使用セット数・途中状態を営業セーブへ保存する。休業日は休業操作の前に遊び、翌日の準備で回数が回復する。[譲渡イベントと予防効果](HumanToCatAdoption.md)も初回実装済み。

## 目的と現状

全猫を休養にして通常営業を進めると、お客が来店して待機期限で帰ってしまう。
猫ごとの出勤・休養設定とは別に、店舗を休業して1日分の休養処理を行い、翌日の準備へ進む操作を追加した。
全猫が休養の場合だけでなく、出勤予定の猫がいる場合も任意に休業できる。

通常営業画面の「今日は休業する」から実行する。確認画面でキャンセルすると日付や疲労を変更しない。
操作時は自動進行を止め、休業後も一時停止を維持する。

## 操作と適用範囲

- 営業開始前の準備中に「今日は休業する」を選ぶ。
- 当日のtickが0で、来店・接客が始まっていないことを条件とする。営業途中の切り上げは対象外。
- 全猫が休養の場合は案内欄で休業操作を案内する。自動で日を進めず、プレイヤーが休業を選択する。
- 出勤予定の猫がいる場合も、その日は全猫を休養扱いにする。
- 来客を発生させず、1日分の休養・体調更新を行って翌日の準備へ進む。翌日は一時停止状態とする。
- 未保存の交流結果や関係データの不整合がある場合は、既存の翌日進行と同様に解消してから実行する。

## 休業日の成果と回復

| 項目 | 扱い |
|---|---|
| 来店・待機列 | 発生しない |
| 接客・売上・ボーナス | 0。所持金を増減しない |
| お客への不利益 | 待機による不満などを発生させない |
| 親しみ・来店経験 | 変化しない。休業を来店・再会した日として数えない |
| 猫の疲労 | 出勤予定に関係なく、全猫に既存の休養日回復を1日分適用する |
| 療養中の猫 | 既存ルールに従い、必要療養日数を1日分減らす |
| 健康な猫 | 疲労回復後の値で既存の発症判定を1回行う |
| 翌日の体力 | 現行の全回復を維持する。体力回復だけで病気は治らない |

休業しても、回復後の疲労が高ければ発症の可能性は残す。
休業日の終了時に新たに発症した猫について、その日を療養済みの1日として数えない。
療養中の再発症判定や、回復した日の再判定は行わない。
疲労・病気の係数は[出勤・休養](HumanToCatCafeShifts.md)と[病気・療養](HumanToCatCafeHealth.md)の既存設定を使う。
家賃などの固定費は現在未導入のため、休業専用の費用は追加しない。

## 翌日の出勤予定

休業日は全猫を休養として集計する一方、翌日用の出勤予定は休業操作前の設定を引き継ぐ。
ただし、翌日も療養中の猫や休業日の終了時に発症した猫は、既存ルールに従って休養にする。
療養を終えた猫は休養予定のままとし、プレイヤーが翌日の準備で出勤を選ぶ。

例：Aが出勤、Bが休養の予定で休業した場合、その日はA・Bとも休養する。
翌日はAが健康なら出勤予定、Bは休養予定を引き継ぐ。Aが発症していればAも休養予定になる。

## 履歴・保存・再現性

休業日も日数を1日進め、日次履歴に「休業日」として残す。
売上0の営業日と区別できるようにし、猫別の疲労・体調・療養日数の変化を比較画面で確認できるようにする。
休業日の実績と翌日の出勤予定を区別して保存する。

休業操作を詳細ログに記録し、同じseed・日・猫IDで同じ結果を再現する。
休業処理と翌日処理で疲労回復・療養日数・発症判定を二重に更新しない。
保存再開や結果の再表示でも更新を繰り返さない。複数日休む場合は、プレイヤーが日ごとに休業を選ぶ。
営業中のtickを繰り返して日を飛ばす方式にはせず、来客を生成しない専用の日次処理とする。
軽量セーブの方針を維持し、旧セーブ・旧ログの営業実績を後から休業日に変更しない。

## 確認した項目

- 全猫休養・一部出勤・全猫療養のいずれでも、準備中に休業できること。
- 来客・会計・待機不満・親しみ・来店経験が増えず、翌日の準備へ進むこと。
- 疲労回復・療養・発症判定が1日につき1回で、復帰までの日数が既存仕様と一致すること。
- 休業日の全猫休養実績と、翌日に引き継ぐ出勤予定が混同されないこと。
- 営業開始後は休業できず、未保存結果や不整合があるときは状態を変更しないこと。
- 日次比較・軽量セーブの再開・詳細ログ再生で休業日とその成果を保持できること。

## 操作ログと互換性

休業は `day_off` 操作として記録し、日次結果に `day_type: day_off` を保存する。
比較画面の「営業区分」で休業日と通常の営業日を区別する。旧日次結果は通常の営業日として表示する。
軽量セーブ形式2と再生ログ形式4に対応し、旧形式の読み込み・再生も維持する。
休業操作の自動保存は行わない。終了前に「営業を保存…」を利用する。

旧セーブで出勤・病気ルールが未導入の場合は、休業を実行すると不足するルールを有効にしてログへ記録する。
既に有効な係数は変更しない。過去の営業結果に遡って休業や病気を追加することはない。

1席・2席で来客が生成されないこと、翌日の予定と初回来店扱いの維持、疲労・療養の1日分更新、
回復日の再発症防止、高疲労での休業日の発症、未保存結果・不整合時の拒否、軽量セーブと再生、
GUIの案内・キャンセル・一時停止・営業開始後の無効化・比較表示をテストした。
