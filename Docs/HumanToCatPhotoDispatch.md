# 猫の撮影スタジオへの派遣

更新日：2026-10-01 / 状態：派遣先と専用の選択イベントを実装済み

接客好きの猫を、店内の接客に残すか撮影へ派遣するか選べます。追加報酬と猫の負担を比べる派遣先です。数値は暫定です。

## 解放と参加条件

新規ゲームの全モードに追加します。人気120以上かつ派遣報酬1回受取で解放し、その後人気が下がっても維持します。

| 項目 | 仕様 |
| --- | --- |
| ID / 名前 | `cat_photo_studio` / 猫の撮影スタジオ |
| 期間 | 2日 |
| 基本報酬 | 350（派遣全体の額） |
| 必要特性 | 接客好き（保存済みID `hospitality` で判定） |
| 疲労上限 | 40以下 |

健康で担当可能な在店猫が対象です。店内の席数を超える担当可能な猫が必要です。準備中の派遣画面で解放進捗・参加条件・期間・報酬を確認できます。二重派遣・同日再派遣・未解決イベント・保存待ちなどの制限は[派遣仕様](HumanToCatCafeActivities.md)と共通です。出発確認の取消や画面閲覧では状態を変更しません。

## スタジオ専用の追加撮影イベント

新しく出発する撮影スタジオへの派遣に、1日目終了時の「追加の撮影をお願いされました」を設定します。出発確認で予告し、回答まで営業・翌日・休業を停止します。

| 選択 | 帰還報酬の増減 | 回答時の疲労 | 回答時のストレス |
| --- | ---: | ---: | ---: |
| 追加撮影を続ける | ＋100 | ＋15 | ＋15 |
| 追加撮影を断って切り上げる | 0 | ＋5 | ＋5 |

両方の選択に基本撮影の負担を含めます。切り上げる場合も派遣期間は2日のままで、早期帰還ではありません。疲労・ストレスは回答時に一度だけ加算し、上限へ制限します。接客好きの接客疲労・ストレス倍率は掛けません。派遣中は在店の休養回復を適用しません。

追加報酬は回答時に入金せず、補正済みの基本報酬へ100を加えて帰還受取時に精算します。歓迎不一致なら続行450／切り上げ350、派遣得意なら350×1.1＋100＝485／350×1.1＝385です。歓迎ボーナスは補正済み基本報酬へ加えます。資金・派遣経験は帰還時に一度だけ反映します。家出トラブル・アイテム報酬は設定しません。新規ゲームの最初の対象派遣には、帰還受取後の[初回限定の猫紹介](HumanToCatDispatchIntroduction.md)を追加しています。詳細・できごと・営業ログ・派遣結果内訳へ選択と効果を表示します。

## 保存と旧セーブ互換

新規開始時に [解放設定](../config/cafe_dispatch_unlocks.json) の条件と派遣先を任意の `dispatch_unlocks.rules.cat_photo_studio` へ固定します。[イベント設定](../config/cafe_dispatch_encounters.json) は出発時に既存の `encounter` へ固定します。設定変更後も保存済みの条件・効果を使います。

撮影スタジオの設定がない旧ゲームには派遣先を後付けせず、一覧にも追加しません。既存派遣先・出発済み記録・旧ログへ撮影イベントや猫紹介を追加しません。営業セーブ形式2・チェックポイント1・詳細リプレイ4を維持し、出発直後・回答待ち・回答後・帰還待ち・受取後の保存再開に対応します。保存失敗後の再試行で負担・報酬・経験を二重処理しません。

## 撮影スタジオの歓迎条件（2026-10-01）

新規ゲームでは白毛（保存済み特徴ID `white`）と得意分野「接客」（成長ID `service`）を歓迎します。独立した条件1件につき追加資金20、両方一致なら40です。追加満足度は0で、有力者の満足度には影響しません。歓迎不一致でも接客好き・健康・疲労・解放などの参加条件を満たせば派遣できます。特性「接客好き」と得意分野「接客」は別の条件で、特性だけでは得意分野の一致になりません。

報酬は基本350×特性倍率×出発時成長倍率＋歓迎ボーナス＋追加撮影の増減です。両方一致なら基本390、続行490／切り上げ390。白毛で派遣得意なら350×1.1＋20＋100＝505／350×1.1＋20＝405です。歓迎補正は疲労・ストレス・紹介費用に掛けません。

候補一覧・選択欄・出発確認で一致条件と報酬見込みを表示し、帰還結果の内訳に歓迎ボーナスを示します。初回のルカ紹介と追加撮影イベントも維持します。解放条件・基本報酬・派遣期間は変更しません。

歓迎設定は既存の新規開始時派遣設定 `dispatch_unlocks.rules.cat_photo_studio.destination.welcome`、一致結果は既存の出発時記録 `welcome_match` に固定します。歓迎設定を持たない旧ゲームや出発済み派遣へ後付けせず、元の報酬を維持します。保存形式を維持し、保存再開・詳細リプレイ・保存失敗再試行に対応します。
