# 親しみ・終了・成果・再会：版4の実装記録

更新日：2026-09-13 / 単独交流ルール版：4

[暫定仕様](HumanToCatRelationshipSpecification.md)に沿って、猫から特定のお客への親しみ、任意終了、成果の保存と再会を実装した。
特別行動が両側で発動しても交流は続く。終了理由と、親しみ・資金・体力消費などの成果を個別に表示する。

## 交流と親しみ

親しみは猫ID・客IDの組み合わせごとに初期値0、範囲0〜100で保存する。
交流中の増減を合計し、終了時に一度だけ範囲へ収める。結果には計算上の増減、実際の増減、上限・下限による未反映分を残す。

| 出来事 | 親しみの増減 |
|---|---:|
| 通常交流：熱中 | +1 |
| 通常交流：好意的 | +0.5 |
| 通常交流：中立・困惑・気だるい | 0 |
| 通常交流：そっぽを向く | −1 |
| 停止・動作切り替え | 0 |
| 心をつかむ | +1 |
| 心を開く | +2 |
| 同時発動の追加分 | +1 |
| 体力切れで終了 | −2（終了時に一度） |

特別行動の資金は各50、同時発動の追加100を維持する。体力切れでも既に得た資金と親しみの増減を消さない。
係数は`config/human_cat_relationship.json`に保存する。8種類の行動と個性は版3を引き継ぐ。

終了理由は任意終了（manual）、時間終了（time_limit）、体力切れ（exhausted）。同時に条件を満たしたら体力切れを優先する。
「切り上げる」はターンを進めず、通常反応・回復・特別行動を発生させずに予約を失効させる。開始直後にも使用できる。
終了処理を繰り返しても成果は変わらず、終了後の行動は受け付けない。

## 起動と保存

```bash
python3 -m cat_cafe_sim.human_cat_gui
python3 -m cat_cafe_sim.human_cat_gui --relationships saves/example.json
```

GUIの既定は版4。猫ID・客ID、次の個性、開始体力を指定して再会する。同じ組み合わせなら保存済みの親しみを引き継ぎ、別の相手なら別の関係として扱う。
画面は交流中の親しみ見込み、終了結果と内訳、保存状態を表示する。「切り上げる」や自動終了時に結果を保存する。
保存に失敗した場合は終了結果を保持し、「保存を再試行」できる。
再会・終了時に未確定または未保存の交流があれば、保存・試遊の破棄・キャンセルを選ぶ。
保存先の選択と新規保存先の指定は次の交流から適用する。

既定の関係データは`saves/relationships.json`。`saves/`はGit管理対象外。
交流ログは再生検証用で、関係データとは別ファイルにする。同じ保存先へのログ書き込みは拒否する。

```bash
python3 -m cat_cafe_sim.human_cat_demo run --rules 4 --cat-id cat-1 --customer-id guest-1 --actions direct finish --relationships saves/example.json --save-result --output reports/relationship_example.json
python3 -m cat_cafe_sim.human_cat_demo replay reports/relationship_example.json
python3 -m cat_cafe_sim.human_cat_demo compare --rules 4
```

CLIの既定ルールは従来どおり1。版4では`finish`で任意終了する。関係データの更新は`--save-result`指定時だけで、未終了の保存は拒否する。
ログ再生は関係データを読み書きしない。版1〜3の過去ログに親しみを遡及加算しない。

保存は交流ID単位で適用済み結果を記録し、同じ結果の再試行で二重加算しない。
同じ交流IDで内容が異なる場合や、開始後に同じ組み合わせの保存版が進んだ場合は競合として拒否する。
一時ファイルの書き込み・同期後に置換するため、置換前の失敗で既存データを壊さない。
単一プロセスでの利用を前提とする。保存版の確認は同時書き込みの排他ロックではなく、複数プロセスからの同時利用は未対応。

## 検証結果

通常テスト171件と、実際のTkウィジェットを使う画面専用テスト6件が成功（計177件）。画面の目視評価は含まない。
任意終了・予約失効・特別行動後の継続・体力切れ・上下限・保存失敗と再試行・競合・再会・破棄とキャンセルを確認した。
同時発動の繰り返しは診断用にゲージ増加量を変更したテストでも確認し、既定値のバランス評価とは分けている。
版1の48件、版2の32件、版3の120件、版4の120件、計320ログが再生一致した。

版4の比較は5個性×開始体力100/20×4方策×同じ相手との3回の交流、計120交流。
各交流で開始体力は指定値へ戻す単独試遊であり、営業中の無料回復ルールではない。

| 方策（各30交流） | 終了理由 | 平均親しみ増減 | 平均資金 | 平均体力消費 |
|---|---|---:|---:|---:|
| 通常交流3回で切り上げ | 任意終了30件 | 0.65 | 0 | 15 |
| 反応に応じて変更 | 時間終了30件 | 3.6 | 70 | 52.6 |
| 停止のみ | 時間終了30件 | 0 | 0 | 0 |
| 特別行動を狙って切り替え | 時間終了30件 | 4.85 | 85 | 40.5 |

親しみの数値は上限・下限適用後の実増減。資金0の短い交流でも親しみが増える例があり、停止だけでは増えない。
この比較に体力切れの事例はなく、体力切れは個別テストで確認した。成功率や低体力からのクリアを目標にせず、成果と消耗を並べる診断である。
出力は`reports/human_cat_relationship_comparison.json`と同名Markdown、個別ログのディレクトリ。

## 今回の範囲

親しみは猫からお客への一方向の値。親しみに応じた反応補正、客側の感情、営業の客満足・所持金、日程や休養との接続は未実装。
成果欄の資金を営業の財布へ加算する処理は含まない。保存済み交流の履歴は保持し、削除・圧縮の機能は設けていない。
