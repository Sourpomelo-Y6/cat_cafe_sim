# Unity：未保存の交流結果と保存再試行

営業画面に未保存の交流結果があると、「未保存の結果・再試行」ボタンを表示し、初回は専用画面を開きます。画面を閉じてもこの入口から再び確認できます。

画面には未保存件数、猫・客、親しみの前後と増減、交流ID、直近の再試行失敗理由を表示します。Pythonセーブに元の失敗理由は記録されていないため、復元直後は理由の記録がない旨を表示します。結果・長い理由はスクロールで確認できます。未接続時と送信中は再試行を無効にします。

「保存を再試行」は `persist_retry` で既存の `CafeInteractionSession.persist()` を呼びます。会計・体力・営業時計・報酬を再計算せず、未保存の親しみだけを確定します。保存済みの交流は処理を飛ばし、同じHTTP操作IDの再送は保存済みの応答を返します。再試行に失敗した場合は候補状態の変更を取り消し、失敗理由だけを状態に残します。新しい操作IDで再試行できます。

未保存の結果が残る間は営業・自動進行・出勤変更・購入・回答・保存再開などの通常操作を止めます。確定後に操作を解放します。Unity版の関係データはメモリ内で保持され、元のPythonセーブと関係ファイルは変更しません。確定した進捗を残すには通常の「保存」を行います。

通常のUnity営業操作の失敗は、従来どおり操作全体を取り消します。この専用画面はPythonセーブから復元した未保存結果など、`session.pending` が存在する場合を対象とします。HTTP通信の再送や通常セーブの失敗とは別の操作です。

実装：Python状態APIの `pending_results`、`persist_retry`、Unityの `PythonPersistPanel` と `PythonPersistSetup`。Pythonの復元・再試行・失敗・同じ操作の再送・確定後の保存再開のテストと、Unityの画面/操作制限検証、隔離HTTPサーバーを使った実Playの失敗→再試行→復旧を確認しました。
