# 疲労を優先した休養・割り当ての比較

開発方針の更新（2026-09-17）：全体の流れの確定を優先し、回復量などの細かな調整と追加比較は保留する。本書の調整案は将来の候補として残す。[現在の開発方針](CatCafeSimulation_ImplementationGuide.md)を参照。

検証日：2026-09-17

検証後の実装：[出勤・休養画面の休養提案](HumanToCatCafeShifts.md)として、疲労順2匹休養の案を確認・編集して保存できるようにした。以下は比較時点の記録。

[前回の100日比較](HumanToCatLongTermEvaluation.md)では、固定順の1匹休養でも療養割合が36.1％あり、全店休業では売上が約42％低下した。
今回は個別の疲労を使う3方針を検証する。通常営業の設定・割り当て処理は変更しない。

## 条件と方針

前回と同じ猫5匹・2席・40tick営業・100日（休業を含む）・seed 0/1/2を使用する。
各試行は初期状態から開始し、疲労回復20、接客1tickにつき疲労1、安全閾値60、療養2日などの数値も維持する。

| 方針ID | 出勤・休養 | 接客への割り当て |
|---|---|---|
| fatigue_rest_one | 朝の疲労が高い健康な猫を1匹休養 | 従来の体力優先 |
| fatigue_rest_two | 朝の疲労が高い健康な猫を2匹休養 | 従来の体力優先 |
| fatigue_assignment | 健康な猫は全員出勤 | 予測疲労の低い猫を優先 |

休養対象は健康な猫から選び、病気の猫は別枠で療養する。同じ疲労では猫ID順で休養させる。
健康な猫の数が休養枠以下なら全員が休みとなり、休業する。疲労ゼロでも休養枠を設けるため、閾値による可変人数の休養とは異なる。

疲労優先の割り当てでは、現在担当できる猫だけを対象にする。
優先キーは `min(疲労上限, 朝の疲労 + 当日の接客tick数 × 疲労係数)` の昇順、体力の降順、猫IDの昇順。
営業中の疲労値は閉店まで更新されないため、当日の接客分を加算して見積もる。今後の接客時間までは予測しない。
交流中のコマンド選択は全方針で従来どおり。まず休養と割り当てそれぞれの効果を分け、両方を同時に変更する方針は今回比較しない。

## 測定と再実行

売上・発症・療養・休業日数の定義、保存確認の方法は前回と同じ。
療養割合は5匹×100日＝500匹日を分母にする。最終日以後に必要になる療養は含めない。
比較対象の既存3方針は前回の保存済み集計を利用し、ゲーム設定・猫・交流方策が今回と一致することを照合する。

```bash
venv/bin/python -m cat_cafe_sim.long_term_evaluation \
  --days 100 --seeds 0 1 2 \
  --policies fatigue_rest_one fatigue_rest_two fatigue_assignment \
  --output reports/fatigue_priority
```

`--policies` を省略した場合は従来の3方針を実行する。
測定時は独立した試行を最大3プロセスで並行実行した。上記コマンドは順次実行するが、時間以外の集計は同じ条件・seedで再現する。
保存容量・保存／読込時間・営業処理時間も記録するが、並行実行の影響があるため前回との速度比較には用いない。
試行用の関係データとセーブは一時領域に置き、プレイヤーの保存先を使わない。
検証専用の割り当て方針はセーブ形式に追加していない。保存確認は状態の一致を検証するもので、通常画面で新方針を再開できることを意味しない。

### 読み取りと採用判断

- **疲労順2匹休養を、選択式の休養提案として採用候補にする。** 全猫出勤比で平均売上は12.9％減、療養は58.3％減。固定順1匹休養比でも売上11.1％減に対して療養47.9％減となる。疲労順1匹休養から2匹に増やすと、追加の減収は3.5％、療養の減少は43.6％だった。今回の条件では予防休養を増やす効果が大きい。
- **疲労順1匹休養への単純な置き換えは優先しない。** 固定順1匹休養に比べて療養は7.6％減るが、売上も7.9％減り、休業日数が増えた。休養対象が疲労順になることと、病気とは別に健康な猫の休養枠を必ず確保することの両方が変わる比較であり、順位付けだけの効果とは断定できない。
- **疲労優先の割り当てを健康改善目的で既定にすることは見送る。** 全猫出勤比で売上は7.0％減り、療養は2.4％増えた。親しみの増加は大きいが、今回の売上・療養の目的には合わない。全員出勤のまま割り当てを分散しても休養日による回復は増えず、負担分散だけでは改善できなかった。疲労順の休養と組み合わせた場合の効果は未検証。

2匹休養でも療養割合は18.8％あり、解決済みとはしない。また、健康な猫が2匹以下になると全店休業する今回の固定人数ルールには営業機会を失う面もある。
次の実装候補は、出勤・休養画面で「疲労が高い2匹を休養」の予定を提案し、プレイヤーが確認・変更できる機能。既定の自動適用は行わず、休業になる場合も画面で確認できる形が適切と考える。
その後、疲労順2匹休養を基準として回復量20→30・40などを個別比較する。人数・来客数が違う編成での妥当性や、疲労閾値に応じた休養人数の変更も今後の検証対象とする。
