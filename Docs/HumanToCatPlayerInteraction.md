# プレイヤーと猫のコマンド交流

更新日：2026-09-21 / 状態：1日3セットの初回実装

ユーザー指定：接客と同じコマンドゲームをテストできるよう、数ターンの交流を1日3セット行える形にする。
店全体で1日3セット、1セット最大10ターンを初回仕様とする。10ターンは暫定値で、数値調整は後回し。
猫からプレイヤーへの好感度を、お客への親しみとは別に持つ。
[譲渡イベント](HumanToCatAdoption.md)の初回実装に接続した。プレイヤー好感度が相手のお客への親しみ以上なら申し出を予防できる。

## 操作と成果

営業画面で猫を選び「猫の詳細…」から「交流を始める（1セット）」を押す。
専用画面でプレイヤーが1ターンずつコマンドを選ぶ。営業中の接客は従来どおり自動のまま。

- 素直に動かす／相手に合わせる／激しく動かす／フェイント／待つ／種類切り替え／心をつかむ。
- ねこじゃらし・ボール・ぬいぐるみ・トンネル・なでる・ブラッシング・声かけ・見守りの8種類。
- 猫の個性、種類ごとの有効行動、関心・テンション、飽き、体力消費と待つ行動の回復、心を開く・同時発動を接客の版4ルールで処理する。
- 特別行動の発動条件に応じてボタンを有効化し、強制発動時も通常の接客と同じルールにする。

画面に残りターン・種類・関心・テンション・体力・好感度の見込みと、ターンごとの行動・反応・好感度増減を表示する。
10ターン終了、体力切れ、「このセットを切り上げる」で成果を確定する。
好感度は固定＋5を廃止し、猫の反応・特別行動・体力切れに応じて増減する。初期0、範囲0〜100。
上限100でもテスト用に交流できる。枠と体力は通常どおり使う。

猫の体力は接客と共通で、行動ごとに営業側へ反映する。体力切れならその日は接客・追加交流ができず、翌日の在店猫の回復で復帰する。
関心・テンション・飽きなどの交流内状態は、新しいセットでリセットする。
[経営ルール](HumanToCatManagement.md)導入後は、交流の反応合計により終了時にストレスを増減する。
営業tick、来客、店の資金、疲労・療養日数は交流操作で進めない。接客用の資金ボーナスを計算する内部ルールは共有するが、店の会計には加算しない。

## セット数・休養・休業

開始時に1セット消費する。同じ猫に3セット使っても、複数の猫へ分けてもよい。
開始直後に切り上げても枠は戻らない。行動しなければ好感度は変わらない。
未使用枠の翌日への持ち越し、猫ごとの別枠はない。

営業前の準備中のみ開始できる。健康で体力のある在店猫が対象で、出勤・休養予定は問わない。
療養中・体力切れ・派遣中・その他の不在猫は対象外。
未確認の帰還イベントや未保存の接客成果がある場合は、先に解決する。

交流は一度に1セット。途中では営業開始・出勤変更・派遣・休業・翌日への進行を止める。
終了後は残った体力で接客や派遣ができる。
通常営業は閉店後に翌日へ進むと3セットに戻る。営業中・閉店後には新しく遊べない。

休業する日は休業操作の前に遊ぶ。休業操作はその日を処理して翌日の準備へ進み、そこで枠が回復する。
休業後に遊ぶ分は翌日扱い。休業専用の追加枠はない。
派遣帰還の確認や、画面の開き直しでは枠を回復しない。

## 途中保存・再開・軽量化

「閉じる（途中状態を保持）」やウィンドウの×は、セットを終わらせず画面だけ閉じる。
猫の詳細から「進行中の交流を開く」で続ける。別の猫を選んでいても、既に開始しているセットを再開する。
画面を閉じても営業は停止したまま。営業画面の保存操作で途中状態を保存できる。

営業セーブに、猫別好感度・本日と累計のセット数・進行中セットの設定と行動・直近1セットの結果を保存する。
進行中の設定を保存するため、再開で個性や反応を再抽選したりコマンドを再選択したりしない。
保存失敗時も状態を保持し、保存の再試行で行動や成果を重複適用しない。
古いセーブを読む場合は、その古い保存時点へ復帰する。

直近結果は次のセットの終了時に置き換える。全セットの詳細ログを永久に累積しない。
お客との関係ファイルにプレイヤーを追加しない。継続には営業セーブを使い、新しい営業では初期状態から始める。
この好感度は接客・派遣報酬を補正しない。

営業セーブ形式2・チェックポイント1の任意項目 player_bond 内を版2に拡張し、リプレイ4へ開始・行動・終了操作を追加する。
player_bond がない旧セーブは好感度0・未使用。旧「1回＋5」のデータは既存の値と使用回数を保持し、次のセット開始時に新形式へ移す。
旧リプレイの player_play は旧処理として読み込む。新規の画面操作から固定加算は使わない。
進行中データは行動ログの再生検証に加え、猫ID・体力・セット数・初期好感度・活動状態との整合性を検証する。

## 検証方法

通常テスト：

```bash
venv/bin/python -m unittest discover -s tests
```

このWSL環境のGUIテスト（Xvfb・xauth・x11-xkb-utilsをインストール済みの場合）：

```bash
timeout -k 3s 60s xvfb-run -a -s "-screen 0 1280x1024x24 -nolisten unix" \
  env CAT_CAFE_TEST_GUI=1 venv/bin/python -m unittest discover -s tests -p test_human_cat_gui.py
```

サンドボックス内では仮想画面に接続できない場合があるため、その場合は許可された制限外の実行環境を使う。
仮想画面はテスト単位で起動・終了し、通常のWSLgデスクトップへテストウィンドウを出さない。

検証結果：通常テスト318件中284件成功、GUI用34件スキップ。XvfbでGUIテストファイル37件すべて成功（通常テスト3件を含む）。
1席・2席、10ターンと3セット、種類切り替え・特別行動、接客とのルール一致、途中保存・再開、切り上げ・体力切れ、
進行ロック、休業・翌日の枠回復、旧データ移行、不正データ拒否を確認した。
GUIでは600×480でのログ・操作ボタン、画面の終了と再開、保存後のコマンド継続を確認した。
