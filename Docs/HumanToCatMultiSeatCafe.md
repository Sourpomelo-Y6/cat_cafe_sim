# 2席での同時交流とテスト用の猫

更新日：2026-09-13 / 営業交流ログ形式3

通常営業の既定を2席にした。プレイヤーが席・お客・担当猫を選ぶか、自動割り当てを使い、割り当て後の交流は自動で進める。

## 操作とテスト用データ

```bash
# テスト用の猫5匹を追加（登録済みの同じIDは変更しない）
python3 -m cat_cafe_sim.cafe_interaction seed-playtest
# 2席の通常営業画面
python3 -m cat_cafe_sim.cafe_interaction gui
# 従来の1席で確認する場合
python3 -m cat_cafe_sim.cafe_interaction gui --seats 1
```

この作業では既定の`saves/cafe_relationships.json`へ次の5匹を追加した。
定義は`config/cafe_playtest_cats.json`に保存し、別環境でも`seed-playtest`で追加できる。

| 猫ID | 名前 | 個性 |
|---|---|---|
| playtest-mike | ミケ | 穏やかな甘えん坊 |
| playtest-tama | タマ | 活発な探検家 |
| playtest-sora | ソラ | 距離を大切にする猫 |
| playtest-kohaku | コハク | 遊び好きで繊細な猫 |
| playtest-mugi | ムギ | 中立 |

既存の猫・個性・親しみ・適用済み交流は上書きしない。同じ追加コマンドを繰り返しても重複登録しない。
保存先を変える場合は`seed-playtest --relationships 保存先`を使い、営業画面にも同じ`--relationships`を指定する。
保存データはGit管理対象外だが、追加用の定義とコマンドは管理対象。

手動割り当てでは待機客と猫を選び、「割り当て先」で空席を選ぶ。片方が交流中でも、もう片方の空席へ別の猫・お客を割り当てられる。
同じ猫の複数席への配置、同じお客の二重着席、満席への配置は拒否する。
自動割り当てでは空席をseat-1、seat-2の順に埋め、お客は待機順、猫は交流可能で手が空いている中から体力優先・同値ならID順で選ぶ。

手動割り当て待ちで、空席・待機客・担当可能な猫が揃った場合は営業全体を一時停止する。
割り当て後に自動進行を再開する。割り当てず進める場合は「自動割り当て」を選んで再開する。

## 時間・体力・会計

営業1tickにつき、各席の交流をそれぞれ1行動進める。2席だから営業時計が2tick進むことはない。
処理順は来店→seat-1の交流→seat-2の交流→待機期限→閉店。
そのtickで空いた席への新たな自動割り当ては次回の進行処理で行う。

各席は独立した交流ID・ゲージ・親しみ増減を持ち、体力を変えるのはその担当猫だけ。
終了した席ごとに時間料金と特別行動資金を会計し、猫を解放する。
片方が終了しても他方の交流は続く。空いた席には次のお客と別の猫を配置できる。
閉店時には両席を終了・会計し、同じ席の会計を二重に行わない。体力切れと閉店が重なった席は体力切れを優先する。

関係保存は終了した交流ごとに行う。両席が同時に終了し、1件目の保存後に2件目が失敗した場合でも、保存済み交流を再加算しない。
未保存結果がある間は営業全体の時間送り・割り当てを停止し、保存再試行後に再開する。
営業の資金・時計・猫の体力は引き続き起動中のみ保持する。永続的な営業セーブは今回含まない。

## 画面とログ

画面に席ごとのお客・猫・体力・関心・テンション・親しみと特別行動資金の見込みを表示する。
空席には直近の会計を表示し、履歴ログには席IDを付ける。親しみの確定結果も席別のログで確認できる。
猫一覧ではすべての席の担当猫を「交流中」として扱い、別席へ割り当てられないようにする。

```bash
python3 -m cat_cafe_sim.cafe_interaction run
python3 -m cat_cafe_sim.cafe_interaction replay reports/cafe_interaction.json
```

自動CLIも既定で2席を使う。`--seats 1`で従来動作を選べる。
検証用の`gui --manual`は1席の手動コマンド画面を維持する。CLIの`--operations`も席数省略時は1席。
複数席を手動コマンドで同時操作するUIは提供せず、通常画面の自動交流で確認する。

営業交流ログ形式3には両席・全猫・全交流の状態と、1tickで各席に選ばれたコマンドを記録する。
旧形式1・2もそれぞれの従来coreで再生する。再生では関係保存先を読み書きしない。

## 検証

2席で1時計、猫・客・席の重複拒否、無効コマンド時に全席を変更しないこと、両席の同時閉店と会計、片方の体力切れ後の継続、席の再利用を確認した。
同時特別行動の会計テストではゲージ増加を大きくした診断設定を使い、各席220・合計440となることを確認した。これは既定値のバランス評価ではない。
一部だけ保存に成功した場合の再試行、交流中・終了後のログ再生、テスト猫の追加を繰り返しても既存データを変えないことも確認した。
GUIでは2席への手動割り当てと自動割り当て、席別会計ログ、860×600でのログ表示領域を検証した。

通常テスト214件と画面専用19件、計233件が成功。新規のテスト用5匹で自動営業を40tickの閉店まで実行し、2席の同時交流と、全猫の残り体力・会計を含むログ再生一致を確認した。
画面検証は実際のTkウィジェットの操作・配置が対象で、目視のデザイン評価は含まない。
