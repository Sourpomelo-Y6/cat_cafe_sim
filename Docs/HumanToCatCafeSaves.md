# 営業途中の保存と再開

更新日：2026-09-14 / 営業セーブ形式1

同じ営業日の途中状態を保存して再開できるようにした。
営業時計・所持金・全猫の体力・各席の交流・待機中のお客を復元し、必ず一時停止状態で開く。
翌日への進行や休養は今回の範囲に含めない。

## 画面操作

```bash
python3 -m cat_cafe_sim.cafe_interaction gui
# 起動時に営業セーブを開く場合
python3 -m cat_cafe_sim.cafe_interaction gui --resume saves/cafe_day.json
```

画面下部の「営業を保存…」で保存先を選ぶ。既定の候補は`saves/cafe_day.json`。
保存操作ではまず自動進行を止め、交流の切り上げ・会計・親しみの追加保存は行わない。
両席が交流中でも、関係保存に失敗して結果が未保存でも営業セーブを作れる。
書き込みに失敗した場合は既存の営業セーブと現在の営業状態を維持する。

「続きから開く…」で保存済みの営業を選ぶ。現在の営業がある場合は、保存して切り替える・保存せず切り替える・キャンセルを選べる。
読み込み失敗やキャンセルでは現在の営業を置き換えない。ダイアログ中と操作後は一時停止のまま。
復元後は「営業を開始・再開」で進める。未保存の交流結果があれば先に「結果保存を再試行」を使う。

通常営業画面を閉じるときも、途中状態を保存する・保存せず閉じる・キャンセルを選ぶ。
保存して閉じる場合、交流を強制終了せず、その続きから再開できる。保存ダイアログのキャンセルや失敗時は画面を閉じない。
検証用の`gui --manual`は従来の手動試遊で、営業セーブの操作は通常画面から行う。

`--resume`では保存内の猫・席・営業設定・関係保存先を使うため、`--cats`・`--seats`・`--relationships`・`--manual`とは併用しない。

## 保存するもの

- 営業時計・所持金・来店予定と待機客・退店済みの会計・営業イベント履歴。
- 参加猫ごとの体力・気力・健康状態と担当席。
- 各席の交流設定・親しみの開始値と増減・ゲージ・特別行動予約・行動履歴。
- 次の交流にも使う版4設定と自動交流方策の版。
- 自動割り当て設定。進行タイマーは復元せず、常に停止状態で開く。
- 関係保存先の絶対パスと、整合性を照合するための保存時点の関係データ。

営業状態は検証済みの操作ログから再構築する。保存時も履歴と現在の状態が一致することを確認し、履歴にない変更を黙って失わないようにする。
旧営業交流ログ形式1・2および2席の形式3を含む営業セーブを扱える。通常の再生ログ単体は営業セーブとしては開けない。

## 会計と親しみの二重反映を防ぐ

復元時は営業ログの状態を再構築するだけで、関係保存先へ書き込まない。
会計済みの資金は営業状態に含まれるため、読み込み時に改めて加算しない。
親しみの保存状態は関係データ内の適用済み交流ID・ログ内容と照合して判断する。

両席の終了時に1件目だけ保存できた場合、再開後は2件目だけを再試行する。
営業セーブ作成後に、そこに記録された未保存の終了結果だけを保存できた場合も、読み込み時に適用済みとして認識する。
終了処理・保存再試行を繰り返しても、資金や親しみを二重加算しない。

一方、営業セーブより後の交流結果が関係データへ保存されている場合や、別の営業・猫登録操作で関係データが変更されている場合は古い営業セーブを拒否する。
これは共有の親しみを巻き戻したり、同じ営業をもう一度別の交流IDで反映したりしないため。
読み込み・保存後の営業操作でも関係データの変化を照合し、外部変更を検出したら時計や交流を進めず停止する。

**営業をさらに進めて終了結果が保存された後は、営業セーブも更新してから閉じる。**
古いセーブを使った任意時点への巻き戻しや、複数プロセスで同じ営業を同時に進める運用は対象外。

## ファイルと失敗時の扱い

営業セーブ、関係保存データ、再生ログは別ファイル。
営業セーブで関係データを上書きする指定と、営業ログで現在の営業セーブを上書きする指定を拒否する。
保存は一時ファイルへ書き込み・同期後に置換し、置換前の失敗で以前の営業セーブを壊さない。

関係保存先は絶対パスで結び付ける。埋め込んだ関係データは照合用であり、読み込みで既存の関係を上書きしたり、消えた関係ファイルを自動復元したりはしない。
営業セーブだけを別PCへ移動する使い方は今回未対応。対応する関係データを削除・置換すると、整合性が合わず開けなくなる場合がある。
自動セーブは追加していない。異常終了した場合、営業セーブ以降のメモリ上の進行は失われる。
関係保存と営業セーブは別ファイルなので、2ファイルをまたぐ一括書き込みは行わず、上記の照合と再試行で扱う。

## 検証

2席の交流中・待機客・特別行動予約の保存復元、閉店済み営業と旧1席形式、関係保存の一部失敗と再試行、古い営業セーブや変更された関係データの拒否を確認した。
保存失敗で以前のファイルを維持すること、読み込みが関係データを更新しないこと、再生ログや関係ファイルとの取り違えを拒否することも確認した。
GUIでは保存・読み込み後の一時停止、読み込み先の営業へのボタン再接続、失敗・キャンセル時の維持、交流を切り上げず保存して閉じる操作を検証した。

通常テスト223件と実際のTkウィジェットを使う画面専用23件、計246件が成功。営業10tickで保存し、復元後に40tickの閉店まで進め、再保存・再読み込み・ログ再生の集計一致と関係保存再試行の非重複を確認した。
画面の目視によるデザイン評価は含まない。
