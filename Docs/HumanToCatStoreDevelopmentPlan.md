## 目的と位置づけ

ユーザーから「現在の来客数は序盤なら問題ないが、席数をさらに増やす施設発展や、満足させるのが難しい代わりにリターンが大きいお客さんが必要ではないか」という案が挙がった。
営業の成果を投資に使い、店の発展に伴って来客数・客層・配置の判断が変わる流れとして記録する。
高難度のお客さんは人気目標のクリアを条件に解放する。初回は第1段階達成時に1種類を解放し、最終クリアを待たずに継続営業へ接続する。
以下の具体例と実装順は会話中の提案であり、費用・人数・解放する種類の割り当てや満足の計算方法を確定するものではない。
全体の流れを先に作り、細かな数値調整は後回しにする方針を維持する。

## 施設発展と来店の変化

資金を使って店を段階的に拡張し、席や設備を増やす。店の人気・発展段階に応じて来客数や新しい客層を増やす案とする。
「営業で稼ぐ → 投資する → 来客と選択肢が変わる → 猫の出勤・休養・派遣を組み直す」という循環を目指す。

通常のお客さんも残し、発展しただけですべてを高難度のお客さんに置き換えない。
営業準備で当日の来店予定や公開された条件を確認し、猫や席設備を選べるようにする。
初回の上限は5席とし、6席以上の拡張段階・費用・来客数の増やし方は未決定。高難度客の解放は次節の人気目標クリアと接続する。
拡張に必要な猫の人数・休養余力と、現行の「店内席数を超える担当可能な猫を派遣する」条件との関係も確認する。

## 満足させにくい代わりに報酬が大きいお客さん

必要数値の引き上げだけでなく、猫や設備の選び方が変わる条件を持たせる。
達成時の追加料金・人気・アイテムなどを報酬候補とする。全種類の報酬を同時に導入するとは限らない。

| お客さんの例 | 条件・判断の案 |
| --- | --- |
| こだわりの強い猫好き | 毛色や特性などの好みが厳しく、条件に合う猫を担当にすると高評価 |
| 静かに過ごしたいお客さん | 落ち着いた猫や静かな席設備を重視 |
| 遊び好きのお客さん | 活発な交流を求め、猫の体力とその後の休養計画が重要 |
| 特別予約のお客さん | 事前に満足条件を提示し、達成するとまとまった報酬 |

これらは種類の候補であり、新しい特徴・特性・設備を定義済みという意味ではない。
最初は1種類から、条件の提示・配置・自動交流・結果・報酬までを通す。
通常営業でプレイヤーが選ぶのは担当猫や席であり、お客さんと猫の交流コマンドは引き続き自動とする。

実装前に、交流中の何を評価するか、判定する時点、条件未達時の料金と不利益、予約の受諾・見送りの可否を決める。
既存の特別行動ボーナスとの重複や、長く滞在させるだけで得をする設計にならないかも確認する。
ここでの満足条件は1回の接客の評価であり、ゲーム全体のクリア条件や派遣先の有力者満足度とは別に扱う。

## 人気目標クリアによる高難度客の解放

高難度のお客さんは、店の人気を上げて[人気目標](HumanToCatPopularityGoal.md)をクリアすることで解放する方針とする。
単に現在の人気が高いことや施設を購入したことだけを解放条件とせず、目標達成の成果として継続営業に新しい客層を追加する。
これにより、目標達成後に営業を続けて施設や猫の配置を工夫する目的を作る。第1段階の解放処理は初回実装済み。

現行の人気目標は3段階であり、次のような段階別解放を候補とする。

| 達成段階 | 解放内容の例（未確定） |
| --- | --- |
| 第1段階 | 高難度のお客さん1種類 |
| 第2段階 | 長毛猫と「心を開く」を条件にした翌日の特別予約（初回実装済み） |
| 最終段階 | 三毛猫、心をつかむ・心を開く、同時発動を条件にしたVIP客（初回実装済み） |

第1・第2段階は途中の目標達成であり、最終段階のゲームクリアと区別する。
第1段階の高難度客、第2段階の特別予約、最終段階のVIP客を初回実装した。VIP客は最終目標達成時のクリア判定とは分け、継続営業の追加内容として翌営業日から来店する。
一度解放した客層はその営業セーブ内では人気が下がっても維持し、通常客に混ざって来店する。
初回は達成の翌日以降、営業日の開店時に1名を追加する。休業日は来店しない。後続の頻度・人数調整は保留する。

人気以外の目標や自由営業で始めたゲームでは、現状は期限付き人気目標が開始されない。
これらのモードで人気への挑戦を後から開始できるようにするか、高難度客への別経路を設けるかは未決定であり、有力者・好感度のクリアだけで自動解放するとは定めない。
初回は旧セーブへ後付けせず、人気以外のモードにも導入しない。新規ゲームへの解放引き継ぎは行わない。他モードへの経路や旧セーブへの任意導入は後続の検討事項とする。

## 常連化との接続

会話で先に提案した常連度も、後続候補として残す。
良好な接客を積み重ねると常連度が上がり、一定値で通常の曜日に加えた追加来店が発生する案。
名簿で常連度と来店予定を確認できるようにする。

「猫からお客さんへの親しみ」「お客さんから店への常連度」「今回の接客の満足」は別の値として整理する。
来店しただけ・接客を終えただけで増えるのか、満足条件の達成を必要とするかは、接客評価の設計時に決める。
常連の追加来店と施設発展による来客増加が重なった場合の人数上限・混雑も未決定事項とする。

## 提案する実装順と確認範囲

1. （初回完了）接客の満足条件の基盤と高難度のお客さん1種類を、人気目標第1段階クリアによる解放まで含めて実装する。
2. （初回完了）4席への段階的拡張と、それに伴う通常客1人の増加を接続する。
3. （初回完了）接客成果を常連化と週1回の追加来店につなげる。

常連度を単独で先行させる提案から、施設発展と接客評価を先に整える順へ見直す案である。
初回の費用・条件・報酬は暫定値とし、詳細なバランス調整や長期比較を先行させない。

各段階では、営業前の判断から結果確認までの操作、休業時の来店抑止、既存客ID・関係の維持、費用・報酬の二重適用防止を確認する。
保存再開で予定・評価・報酬を再抽選や再付与しないこと、旧セーブへの導入方針も実装時に定める。
高難度客は解放前には来店せず、目標結果の再閲覧や保存再開で解放・報酬が重複しないことを確認する。人気低下後の解放維持も採用時の確認対象とする。
記録は必要な結果に絞り、毎ターンのログを営業セーブに大量追加しない。
