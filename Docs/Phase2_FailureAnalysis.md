# Phase 2: 失敗分析と体力区間の比較

## 結論

混合開始モデルの不満退店を分析し、体力の低い領域だけ状態区間を細かくする候補を1つ比較した。
調整用では一部改善したが、新しい評価条件で3学習seed平均の売上は737.78から717.78に低下し、
不満退店は0.78件/日のままだった。既定モデルには採用しない。
今回の結果を見てから追加の候補や学習量の変更は行っていない。

## 分析

`reports/mixed_day_validation/*_new_seed*.json`の12ログを再生し、不満退店8件を調べた。
決定的な同一条件の反復を除くと4例。すべてQ表に存在する状態で、行動前の気力は10だった。

| 学習seed / 条件 / tick | 行動前満足度 | 体力 | 選択行動ID | 直後満足度 | 1手の代替診断 |
|---|---:|---:|---:|---:|---|
| 43 / regular / 26 | 62.78 | 24 | 2 | 93.58 | 低消費行動・休憩で即時失敗を回避可能 |
| 44 / regular / 28 | 83.82 | 8 | 1 | 99.22 | 2・4・5なら即時成功 |
| 42 / spaced / 36 | 57.13 | 3 | 0 | 64.69 | 休憩のみ即時失敗を回避 |
| 44 / spaced / 36 | 57.96 | 11 | 5 | 86.56 | 0・3・4・休憩で即時失敗を回避可能 |

旧区間では体力3〜25が同じ正の区間に入るため、行動の消費量に対して体力が足りるか区別できない。
これを改善仮説とした。ただし区間の粗さが失敗の唯一の原因と確定したわけではない。
Q値が0でも、その行動を未学習だったと断定はできない。

追加した`evaluation.failures`はログとモデルのSHA-256、設定、各tick、最終集計を照合する。
失敗前の公開観測・状態・Q値を保存し、同じ直前状態から全7行動を1手だけ実行する。
内部の好みは診断用シミュレーションのみで使用し、方策には渡さない。
「即時失敗を回避」は、その後の満足退店を保証しない。

## 比較条件

`config/cat_training_stamina.json`は混合開始設定に`stamina_edges`だけを追加したもの。
正規化した体力の境界は0.05、0.08、0.10、0.15、0.18、0.25、0.50、0.75。
0と最大値の独立区間を維持し、満足度・気力・履歴・残り時間の区間は変更しない。
境界値と観測はfloat32精度で比較する。

- 状態上限: 14,256 → 26,136。新しい符号化版は`cat-state-v2-stamina`。
- 報酬・学習率・探索・開始条件・未知状態での行動規則は据え置き。
- seed 42 / 43 / 44で各3,000接客。保存状態数は2,763 / 2,715 / 2,729。
- 新モデル: `models/cat_q_stamina_seed{seed}.json`。旧モデルのSHA-256が不変であることを確認。
- 旧設定・モデルで`stamina_edges`が欠けている場合は従来の符号化を使用。

調整用は従来と同じ2シナリオ×2seed。
最終評価は実験前に`config/cafe_evaluation_stamina.json`へ別条件を固定した。
好みは(1.25, 0.70)、(0.70, 1.25)、(0.55, 0.50)、来店時刻も新しく設定し、
営業seedは60000〜60004。旧モデルと新モデル、固定方策を同じ条件で評価した。
営業seed反復は独立した客条件とは扱わない。最終評価の独立したシナリオは3種類のみ。
この条件も今後は未使用の評価条件として再利用しない。

## 再現手順と検証

```bash
venv/bin/python -m cat_cafe_sim.evaluation.failures \
  --logs reports/mixed_day_validation/*_new_seed*.json \
  --models models/cat_q_mixed_seed42.json models/cat_q_mixed_seed43.json models/cat_q_mixed_seed44.json

for seed in 42 43 44; do
  venv/bin/python -m cat_cafe_sim.training train \
    --training config/cat_training_stamina.json --seed "$seed"
done

for split in validation test; do
  venv/bin/python -m cat_cafe_sim.evaluation.days \
    --old-model models/cat_q_mixed_seed42.json models/cat_q_mixed_seed43.json models/cat_q_mixed_seed44.json \
    --new-model models/cat_q_stamina_seed42.json models/cat_q_stamina_seed43.json models/cat_q_stamina_seed44.json \
    --cases config/cafe_evaluation_stamina.json --split "$split" \
    --output "reports/stamina_day_${split}.json"
done
venv/bin/python -m unittest discover -s tests
```

旧モデル・分析元ログの生成手順は[前回の比較](Phase2_MixedStartTraining.md)を参照。
診断JSONは`reports/failure_analysis.json`、学習CSVと接客調整結果は
`reports/cat_q_stamina_seed*.training.csv`と同名の`.validation.json`。
営業比較JSONには設定・モデルの指紋と各日のログ参照を保存する。
生成モデルとレポートは従来どおりGit管理外とし、本書に比較結果を残す。

98件のテストが成功。追加6件で区間の分離、float32境界、入力検証、旧形式、
再学習再現性・同じ開始条件系列・モデル保存読込、診断の再生・改変検出を確認した。
学習CLIで3モデルとも保存前後の軌跡一致を確認し、営業比較の計133ログも全件再生一致。
