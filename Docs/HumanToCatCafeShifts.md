# 出勤・休養と長期疲労

更新日：2026-09-15

営業前に猫ごとの出勤・休養を選び、接客による疲労蓄積と休養日の回復を追加した。
翌日の体力全回復は維持する。営業中の短い休憩を設定する機能とは別の仕組み。

## 操作

通常営業画面の「出勤・休養…」で猫を選び、「選択した猫を出勤」「選択した猫を休養」で予定を変更する。
「設定を保存」で営業に反映し、キャンセルでは変更しない。画面を開くと自動進行は止まる。
設定後も一時停止を維持する。「営業を開始・再開」でその日の営業を始める。
ここでの保存は現在の営業への反映であり、ファイルへの保存は「営業を保存…」を使う。

設定できるのは、当日のtickが0で来店処理も接客も始まっていない準備中だけ。
新規営業は全猫が出勤。翌日には前日の設定を引き継ぎ、必要に応じて変更する。
休養猫は手動・自動割り当ての対象外。病気の猫は翌日から強制的に休養となり、回復するまでは出勤を選べない。出勤設定でも病気や体力切れなどの担当不可条件は有効。
現状は全猫の休養も可能で、その日は来店・待機期限・閉店だけが進み、接客売上は発生しない。
来客なしで休む場合は「今日は休業する」を選ぶ。出勤予定の猫がいる場合も休業できる。[店舗の休業日](HumanToCatCafeDayOffPlan.md)を参照。
自動割り当ての優先順（体力とID）は従来どおりで、疲労による優先順位変更はまだ行わない。

## 暫定の疲労ルール

設定値は `config/cafe_shifts.json` に分離する。

| 項目 | 既定値 |
|---|---:|
| 疲労の上限 | 100 |
| 接客1行動あたりの疲労 | 1 |
| 休養1日あたりの疲労回復 | 20 |

閉店時に1回だけ更新する。

- 出勤猫：開始時疲労＋当日の接客行動数×係数。接客しなかった猫は据え置き。
- 休養猫：開始時疲労−休養回復量。
- 結果は0から上限までに収める。

2席でも担当猫ごとに行動数を数える。交流中の「休む」も接客中の1行動なので疲労集計に含む。
設定変更や結果閲覧、保存再試行、翌日への移動だけでは疲労を再加算・再回復しない。
気力を消費して接客を延長する旧方式は通常営業に導入していないため、気力消費による疲労加算も行わない。
翌日には体力が全回復するが、疲労は閉店時の値を持ち越す。気力は変更しない。病気・療養日数は[病気と療養のルール](HumanToCatCafeHealth.md)で更新する。
疲労による能力低下は未実装。疲労が高いと発症するため、休養で発症リスクを下げる。

## 表示と保存

営業中の猫一覧に「疲労」を追加し、休養猫の状態は「休養」と表示する。
閉店結果と複数日比較に、その日の出勤・休養と疲労の開始値→終了値を表示する。
接客途中では疲労表示は開始時の確定値のまま。閉店時に更新する。

出勤設定・猫別接客行動数・疲労・計算係数を営業ログに記録し、営業セーブから復元する。
係数は営業履歴に固定するため、設定ファイルを変更しても保存済み営業の再生には影響しない。
設定変更後の係数は新規営業から適用される。

現行のログ形式4・営業セーブ形式2と、旧形式の互換性は[セーブ軽量化](HumanToCatCompactSaves.md)を参照。旧ログに新しい疲労を遡って加算しない。
旧セーブは従来の動作で再開し、次の準備中に「出勤・休養…」から設定を保存すると出勤・疲労と病気・療養のルールを開始する。
旧履歴の出勤・疲労欄は「記録なし」。新しい `set_shifts` 操作を含むログは旧アプリでは再生できない。

## 検証範囲

1席・2席での休養猫の割り当て拒否、全猫休養、猫ごとの疲労計算、上下限、営業開始後の変更拒否、
翌日への持ち越し、設定直後・接客途中・閉店後の保存再開、旧セーブ互換性、関係保存失敗からの再試行、
GUIでの変更・キャンセル・一時停止・設定ロックをテストする。

## 営業前の予測表示

「出勤・休養…」画面で、現在の疲労・体調に加えて次の情報を並べて表示する。

- 前日の接客行動数（交流件数ではなく、接客中に実行した行動数）。
- 出勤予測：前日と同じ行動数で接客した場合の、閉店時疲労と発症確率。
- 休養予測：1日休養した場合の、閉店時疲労と発症確率。

表示例：現在の疲労60、前日の接客6行動なら、既定ルールで出勤は「66 / 12.0%」、休養は「40 / 0.0%」。
疲労の上下限と発症確率は、その営業に保存されている出勤・病気ルールで計算する。
設定ファイルを読み直して係数を置き換えることはない。

出勤予測は目安で、当日の担当回数・交流時間によって変わる。出勤を選んでも接客量を固定する機能ではない。
前日に接客しなかった猫は0行動を基準とするため、今日接客すれば予測より疲労や発症確率が増える場合がある。
初日や旧履歴に接客行動数がない場合は「記録なし」とし、出勤予測は表示しない。0行動と記録なしは区別する。

療養中は出勤不可と表示し、休養による疲労回復と、1日経過後の療養日数を確認できる。
再発症判定は行わないので、発症確率を0%と表示せず「判定なし」と表示する。
旧セーブで出勤・疲労ルールが未導入なら予測は表示しない。病気ルールだけ未導入なら疲労のみ予測し、確率は「判定なし」とする。
旧セーブでルールを導入する場合は設定を保存してから画面を開き直す。

猫を選ぶと予測の根拠を表示する。横スクロールで全列を確認できる。
出勤と休養の予測は両方表示し、予定の切り替え・キャンセルでは営業状態や予測の基準値を変更しない。
表示時に発症の抽選は行わず、営業履歴・セーブ形式にも予測データを追加しない。
軽量セーブに保存された日次集計から、再開後も同じ予測を計算する。

検証：予測の計算・上下限、0行動と履歴なし、療養中・未導入ルール、保存済み係数の使用、
予測表示による状態非変更、軽量セーブ再開後の一致、GUIでの根拠表示・キャンセル・500×400での表示を確認した。
通常テスト253件・GUI専用28件が成功。
